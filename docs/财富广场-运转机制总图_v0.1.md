## 二、本体注册表长什么样（注册场景，示意）

```
对象 User（用户）——全局一份，所有场景共用
  绑定 ← cdm.dim_cu_usr_info_df.usr_id
  属性：性别←sex，注册类型←rgst_type，实名状态←实名字段

对象 Channel（渠道）——全局一份
  绑定 ← cdm.dim_ch_chl_df.chnl_id
  层级：三级←fst/sec/chnl_id；金融标识←fin_chnl_flg

事件 Registration（注册）
  绑定 ← cdm.dwd_cu_rgst_fin_di
  度量 注册用户数 = COUNT(DISTINCT usr_id)   ← 身份规则：归一到 usr_id
  口径规则（每条带出处+确认状态）：
    R1 直注段：渠道∉{麦当劳,中信书院}          ← rgst_fin_di.sql 段A [confirmed-脚本读出]
    R2 激活段：渠道∈{麦当劳,中信书院} 且 if_act=1 ← 同脚本段B   [unverified→待勾选]
    R3 激活边界：actv_tag=1 自 2024-07-01；tag=2 自 2024-07-09 ← 同脚本 [unverified]
    R4 一人多激活取最早                        ← 脚本 row_number 注释 [unverified]
  链接：Registration→Channel(rgst_chnl_id)、→User(usr_id)
```

昨天口径卡片 5 张卡的内容 = 这些结构化字段。**数仓的表和 SQL 一行不动，本体是长在上面的索引+规则层。**

## 三、一次问答的旅程（"8月麦当劳渠道注册了多少人"）

```
1 LLM 读题 → 本体目录点菜：度量=注册用户数(KPI口径) 维度=渠道(二级:麦当劳) 时间=2026-08
   （目录里没有的，如"注册用户资产规模"→ 结构化拒答）
2 编译器查注册表 → 按绑定+R1-R4 口径规则生成查询 SQL（只读）
3 校验器跑硬规则：I1 Σ分渠道=总数 / I2 身份归一 / I3 时间显式 / I5 拒答完整
4 SQL 打镜像库 → 数字
5 对账：编译 SQL vs 数仓 ads_rgst_chnl_cnt_df.sql 聚合逻辑，数字相等才算数
6 返回：数字 + 用的原语 + 生成的 SQL + 审计记录
```

LLM 全程不写 SQL。新问题（"分性别分渠道注册数"）= 已有原语重新组合，零新人工 SQL。

## 四、口径确认生命周期（机器起草 → 人勾选 → 落本体）

```
SQL 解析/机器起草 → 口径卡片（unverified）
  → 是非题给数仓同学勾（"激活边界 2024-07-09 仍生效？对/错"）
  → confirmed → 写进本体注册表的规则字段（永久带出处）
  → 此后每次问答自动套用，口径文档自动沉淀
```
人的投入=选择题；机器的投入=解析/起草/执行/对账。

## 五、对象复用（绝不重复定义）

场景是引用不是复制：User/Channel 全局一份；活跃场景来了**只加**活跃事件+活跃度量，共用对象原样；User 缺字段就在 User 上加（一处加处处用）。重复定义同一业务概念 = 口径分裂的开始 = 本体头号反模式。

## 六、维护（本体是 git 文件，不依赖 Rose 在线）

- 本体 = git 管理的代码文件：可 diff/评审/回滚/交接，你们管 ETL 脚本的方式直接适用；
- 三类变更：①新场景/新口径=确认流程走一圈 ②源表改字段=改映射层（同 ETL 适配上游）③口径演进=改规则字段+对账回归；
- 角色过渡：研究期 Rose 主维护（本体从场景长出来）→ 生产期移交数仓团队，Rose 只留方法论——这是项目目标本身；
- 诚实成本：源表变更要同步映射（任何元数据层都有），换口径不散落。

## 七、全仓扩展两速制
