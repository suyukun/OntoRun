> 依据：Jack 手绘业务流程关键表图（~25 张）+ 三份数据字典 + 理解笔记 v0.3。
> 五步规程覆盖：①表分拣（第二节）②对象四问（第三节）③链接扫描（第五、六节）；④口径挂接、⑤真问题校验待第一问拍板后做。

## 一、先报三个设计级发现（影响全局，建议最先裁决）

- **F1 两套「活动」同名不同物**：营销活动 `act_id`（DIM_OR_ACT_INFO_DF，新/老营销平台，状态机 8 态）vs 中信人活动 `acty_id`（DIM_PS_CTM_ACTY_DF，转介/主题两类）。本稿命名：**Activity（营销活动）** / **ReferralActivity（中信人活动）**。→ 待裁决 F1
- **F2 两套「任务」同名不同物**：C 端营销任务 `mission_id`（dim_or_mission_info_df，用户完成得奖励）vs 中信人资讯任务 `tsk_info_id`（DIM_OR_TSK_INFO_DF，员工推送执行，状态机 6 态）。本稿命名：**Mission（营销任务）** / **StaffTask（员工任务）**。→ 待裁决 F2
- **F3 商城订单的 ID 是 member_id 不是 usr_id**：DWD_TR_JFSC_ORDER_PRODUCT_DF 用会员 ID；积分表用 `uda_user_id`/`upd_user_id`；埋点用 usr_id/login_id/anony_id。**至少四套用户标识**，身份对齐（第五节 L1）是所有跨域问题的咽喉。→ 待裁决 F3（member_id ↔ usr_id 的映射表不在字典中，列缺口 G3）

## 三、对象设计（对象四问，逐个评审）

### O1 User 用户 ← backing: DIM_CU_USR_INFO_DF
- **身份**：`usr_id`。另持三套行为侧标识：login_id / anony_id / uid_anony_id（经 L1 对齐）。
- **生命周期**：游客（匿名，无 User 记录）→ 注册 → 实名（real_fg/real_dt/real_way）→ 注销（usr_stat_fg=0）。绑卡里程碑：Fst_Debt_Card_Fg / Fst_Bind_Crdt_Fg。
- **关键属性**：注册类型（0 子公司同步/1 登录注册）、注册渠道链（一级~四级 id/nm 拉平）、实名方式、性别/生日/证件类型、加密 PII（姓名 sm3、手机号/证件号 aes——**语义层只暴露加密态，明文不出内网**）。
- **设计要点**：①注册渠道 8 个字段在对象里收敛为「注册渠道 → Channel 链接」+ 原始渠道属性；②游客不是 User 实例（无 usr_id），是行为侧 anony_id——「游客 vs 用户」的口径由身份链接裁决，不是两个对象。→ 待裁决 O1

### O2 Channel 渠道 ← backing: DIM_CH_CHL_DF
- **身份**：`Chnl_Id`。
- **生命周期**：Chnl_Stat 0/1 + 生效日期；一/二级渠道各有独立状态字段。
- **关键属性**：名称、描述、金融渠道标识、自动授权标识、钱包支持、渠道级别（原始=3/渠道组=2/一级=1）。
- **设计要点**：**表是四级拉平存储（字段重复两组，且脏：同名字段出现两轮）**。本体应建为自引用层级：Channel { parent_channel }，四级逐层是 Channel 实例，事件的渠道链接指向最细粒度层级，roll-up 由层级链接派生。→ 待裁决 O2（含：拉平表按 Chnl_Lvl 拆层时重复组如何取舍，列 G6）

### O3 Activity 营销活动 ← backing: DIM_OR_ACT_INFO_DF
- **身份**：`act_id`（另有新活动表 id activity_id、父活动 parent_act_id——新旧双轨，见 G7）。
- **生命周期**：act_status 8 态（创建/待审批/驳回/执行中/待执行/暂停/终止/已结束）与 act_status_new 4 态（新建/开始/补签/结束）**两套并存**；is_delete 软删。→ 待裁决 O3a：以哪套状态为准（建议 act_status_new 4 态 + 存档原 8 态）。
- **关键属性**：名称/简介、起止日期时间、大类（线上销售/商机跟进/裂变营销）、细类（开户签约/产品销售）、投放类型（正式/测试）、执行类型、触发类型、审核状态。
- **设计要点**：测试活动（act_put_type=1）在语义层默认过滤，防污染指标。→ 待裁决 O3

### O4 ReferralActivity 中信人活动 ← backing: DIM_PS_CTM_ACTY_DF
- **身份**：`acty_id`。
- **生命周期**：acty_stat 4 态（新建/开始/补签/结束）+ 起止日期。
- **关键属性**：类型（1 转介/2 主题）、所属机构、来源（wealth_plaza/cmp）、父活动。
- **设计要点**：与 O3 是**两个独立对象**（F1），仅通过 E14/E15/E16 关联到 Employee。MGM 永久下线后此对象新增实例趋零，但存量在账。→ 待裁决 O4

### O5 Mission 营销任务 ← backing: dim_or_mission_info_df
- **身份**：`id`（mission_id）。
- **生命周期**：无显式状态机——start/end 日期 + hidden + is_delete 推导（进行中=日期内且未删未隐藏）。→ 待裁决 O5a：是否接受推导态。
- **关键属性**：名称/图片/文案、类型、是否推荐、奖励配置（award，JSON 态）、延迟提交标志、任务组号 group_no、归属子公司渠道 belg_chnl_id（→ Channel 链接）、排列顺序。
- **设计要点**：任务→活动经 activity_id 链接（L3）；「邀请好友」类任务（MGM 卡点 60%/49% 的元凶）可由类型识别。→ 待裁决 O5

### O6 StaffTask 员工任务 ← backing: DIM_OR_TSK_INFO_DF
- **身份**：`tsk_info_id`。
- **生命周期**：6 态（待配置/待执行/执行中/已执行/已失效/已停止）。
- **关键属性**：策略表 id（→ Strategy 参考型）、任务内容、内容类型（早午晚报/收评）、话术、执行时间。
- **设计要点**：服务于中信人资讯转发链路（E 系转介链的上游）；第一刀可不建，但命名先占住（F2）。→ 待裁决 O6

### O7 Content 资讯内容 ← backing: DIM_OR_MSG_BASE_DF
- **身份**：`ID`。
- **生命周期**：STATUS 1 未发布/2 已发布/3 已撤回；发布类型立即/定时。
- **关键属性**：标题/摘要/正文 URI/视频 URI、类型（图文/视频）、作者、标签、是否推荐。
- **设计要点**：**财富号（ACCOUNT_ID/NAME/TYPE/STATUS）拉平在本表内**——财富号有独立生命周期（禁用/启用/注销），本体应拆出 **WealthAccount（财富号）对象**，Content→WealthAccount 链接。→ 待裁决 O7（含是否拆 WealthAccount，建议拆）

### O8 Employee 中信人员工 ← backing: DIM_CU_CTM_EMP_DF
- **身份**：`emp_id`（主键 key 是技术键）。
- **生命周期**：emp_stat 员工状态（枚举值字典未给全，→ G8）。
- **关键属性**：工号、姓名、手机号（sm3）、性别、职级 tsm_rank、省市、微信号、注册时间。
- **设计要点**：Employee→Org 链接经旧机构 id（old_org_id），而 Org 表有新旧机构标识——映射经 DIM_PB_CSPM_NEW_ORG_MAP_DF（参数表，不在关键表集）。→ 待裁决 O8

### O9 Org 机构（中信人组织）← backing: DIM_PB_CTM_ORG_REL_DF
- **身份**：`ctm_org_id`。
- **生命周期**：无状态字段；有新旧机构标识（01 新/02 旧）。
- **关键属性**：三级机构 id/nm 拉平。
- **设计要点**：与 O2 同理建层级（lv1→lv2→lv3），不拉平。→ 待裁决 O9

### O10 Product 金融产品 ← backing: DIM_PS_FIN_PRDT_DF
- **身份**：`product_id`。
- **生命周期**：is_deleted；无状态机。
- **关键属性**：编码/名称、产品目录两级、资产大类三级、风险等级。
- **设计要点**：导流目标（E13 drag_prod_id → Product）；商城商品**不是**本对象（商城商品无维表，见 G3）。→ 待裁决 O10

## 五、链接设计（含命门专项）

### L1 IdentityLink 身份链接（命门，单独评审）
- **backing**：DIM_CU_LOGIN_ANONY_MAPPING_DF（login_id ↔ anony_id ↔ last_login_id + 最近时间）、DIM_CU_ANONY_LAST_LOGIN_MAPPING_DF（anony_id → 最新 login_id）。
- **模型**：IdentityLink { anony_id, login_id, usr_id?, since(最近触发时间), source(映射表) }；语义层提供 **resolve(任一 ID) → 身份主键** 的唯一入口，禁止各问题自拼 JOIN。
- **口径裁决点**：①「游客/登录/实名」三态判定以谁为准（建议：有 usr_id=实名口径？不——usr_id 只代表注册；三态= anony-only / login / real_fg，逐层收紧）；②双表不一致时以 ANONY_LAST_LOGIN（最新性）为准？→ 待裁决 L1a/L1b
- **缺口**：member_id（商城/会员体系）↔ usr_id 映射不在字典 → G3。

### L2-L8 事件归属链接
- **L2 User→Channel（注册）**：O1 收敛注册渠道 8 字段为链接（保留原始渠道属性）。
- **L3 Mission→Activity**：activity_id；任务组 group_no 内排序属性不建链。
- **L4 PrizeAward→{Activity, Mission, Prize}**：发放来源 prize_type 四类决定哪些链接非空。
- **L5 Diversion 多重归属**：导流同时挂 Activity/Mission/Product/Page/Button/Channel(导流链)+Channel(来源链)——**双渠道角色**（导流渠道 vs 用户来源渠道）是两个独立链接，不合并。→ 待裁决 L5
- **L6 CrossSaleOrder→{User, Employee, ReferralActivity}**：三方链接。
- **L7 Point{Issuance,Consumption}→Activity**：activity_id 直连。
