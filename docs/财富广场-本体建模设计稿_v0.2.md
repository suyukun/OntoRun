# 财富广场·关键表本体建模设计稿 v0.2（2026-09-08）

> **定位声明（2026-09-08 与 Jack 对齐）**：本体层 = 数仓之上的语义约束层。消费数仓结果、不重做数仓；聚合计算永远下推到 DWS/ADS 预聚合产物，明细不进语义层运行时；本文档 = 语义映射选材库，非施工清单，一切建模由真问题驱动。
> **v0.2 变更**：按 Jack 指令范围收窄——只保留**注册域 + 活跃域**的实体与属性。转化（导流/交叉销售/MGM/中信人全系）、留存（商城/积分/企微/会员）、财富节全部移出，待后续版本按需扩展。
> 基线：v0.1（3841d20）+ 手绘业务流程图 + 数据字典三份。评审方式不变：单元带编号（O/E/L/G/S），逐个裁决。

## 一、范围声明

**保留**：
- 注册域（对应手绘图「获客阶段」）：点击引流 → 注册 → 实名 → 授权，及支撑维度（渠道/注册用户/日期）；
- 活跃域（对应手绘图「活跃阶段」）：页面访问环（访问/曝光/点击/资讯浏览/资讯互动/月活）+ 活动参与链（任务完成 → 抽奖 → 奖品发放）+ 风控资格（黑名单），及支撑维度（活动/任务/资讯/财富号/渠道/日期）。

**移出**（v0.1 编号废止，扩展时重新引入）：
- 转化域：Diversion(E13)、CrossSaleOrder(E14)、Referral 系(E15/E16)、ReferralActivity(O4)、Employee(O8)、Org(O9)、Product(O10)、StaffTask(O6)；
- 留存域：Point 系(E18/E19)、MallOrder(E20)、企微系(E21-E24)；
- 全局发现 F3 中 member_id 相关内容（商城 ID 体系随之移出，身份问题收窄为三套：usr_id / login_id / anony_id）。

**横跨说明**：DWD_LM_PV_DF / DWD_LM_CT_DF 同时出现在获客（点击引流入口）与活跃（页面行为环）——同一事件对象两域共用，口径按分析域区分（见 G6），不建两套。

## 三、对象设计（对象四问）

### O1 User 用户 ← backing: DIM_CU_USR_INFO_DF
- **身份**：`usr_id`；行为侧三套标识 login_id / anony_id / uid_anony_id 经 L1 对齐。
- **生命周期**：游客（匿名，无 User 记录）→ 注册 → 实名（real_fg/real_dt/real_way）→ 注销（usr_stat_fg=0）；绑卡里程碑 Fst_Debt_Card_Fg / Fst_Bind_Crdt_Fg。
- **关键属性**：注册类型（0 子公司同步/1 登录注册）、注册渠道链（收敛为 → Channel 链接，保留原始渠道属性）、实名方式、性别/生日/证件类型、加密 PII（姓名 sm3、手机号/证件号 aes——语义层只暴露加密态，明文不出内网）。
- **设计要点**：游客不是 User 实例；「游客/登录/实名」三态由身份链接统一裁决。
- → 待裁决 O1

### O2 Channel 渠道 ← backing: DIM_CH_CHL_DF
- **身份**：`Chnl_Id`。**生命周期**：Chnl_Stat 0/1 + 生效日期（一/二级各有状态字段）。
- **关键属性**：名称、金融渠道标识、自动授权标识、钱包支持、渠道级别（原始=3/渠道组=2/一级=1）。
- **设计要点**：表为四级拉平（字段重复两轮，G2）。本体建**自引用层级** Channel { parent_channel }，事件链接指向最细层级，roll-up 由层级派生。
- → 待裁决 O2

### O3 Activity 营销活动 ← backing: DIM_OR_ACT_INFO_DF
- **身份**：`act_id`（新旧双轨 activity_id/parent_act_id，见 G3）。
- **生命周期**：act_status 8 态与 act_status_new 4 态并存（→ 裁决：建议以 act_status_new 为准、原 8 态存档）；is_delete 软删。
- **关键属性**：名称/简介、起止日期时间、大类（线上销售/商机跟进/裂变营销）、细类、投放类型（正式/测试——**测试活动语义层默认过滤**）、执行/触发类型、审核状态。
- → 待裁决 O3

### O4 Mission 营销任务 ← backing: dim_or_mission_info_df
- **身份**：`id`（mission_id）。
- **生命周期**：无显式状态机——start/end 日期 + hidden + is_delete 推导「进行中」（→ 裁决是否接受推导态）。
- **关键属性**：名称/图片/文案、类型、是否推荐、奖励配置（award JSON）、延迟提交标志、任务组 group_no、归属子公司渠道（→ Channel）、排列顺序。
- → 待裁决 O4

### O5 Content 资讯内容 ← backing: DIM_OR_MSG_BASE_DF
- **身份**：`ID`。**生命周期**：STATUS 1 未发布/2 已发布/3 已撤回。
- **关键属性**：标题/摘要/正文 URI/视频 URI、类型（图文/视频）、作者、标签（→ 参考型标签字典）、是否推荐。
- **设计要点**：财富号四字段（ACCOUNT_ID/NAME/TYPE/STATUS）从本表拆出 → O6。
- → 待裁决 O5

### O6 WealthAccount 财富号 ← backing: DIM_OR_MSG_BASE_DF（拉平字段）+ DIM_OR_MSG_WTHAT_DF
- **身份**：`ACCOUNT_ID`。**生命周期**：1 禁用/2 启用/3 注销。
- **关键属性**：名称（全局唯一）、类型 8 类（集团机构/智库专家/第三方机构/线上理财师/财经自媒体/外部资讯/出国金融/尊享专区）。
- **设计要点**：有独立生命周期，理据充分；Content → WealthAccount 链接（L5）。
- → 待裁决 O6（拆分方案本身）

## 五、链接设计

### L1 IdentityLink 身份链接（命门，单独评审）
- **backing**：两张映射维表（login↔anony↔last_login + anony→最新 login，含最近触发时间）。
- **模型**：IdentityLink { anony_id, login_id, usr_id?, since, source }；语义层提供 resolve(任一 ID) → 身份主键唯一入口，禁止各问题自拼 JOIN。
- **口径裁决点**：①三态判定链提案：anony-only（游客）→ +login_id（登录）→ +real_fg（实名），逐层收紧，全问题共用；②双表不一致以最新性（ANONY_LAST_LOGIN）为准。
- → 待裁决 L1a（三态判定链）/ L1b（冲突取最新）

### L2-L6
- **L2 User→Channel（注册链）**：注册渠道 8 字段收敛为链接（保留原始渠道属性）；授权关系由 E5 承载。
- **L3 Mission→Activity**：activity_id 直连；group_no 为组内排序属性不建链。
- **L4 PrizeAward→{Activity, Mission}**：prize_type 决定链接非空组合（1 抽奖/2 任务/3 累进/4 无活动）。
- **L5 Content→WealthAccount**：ACCOUNT_ID 直连。
- **L6 黑名单资格规则**：BlacklistEntry → {E10/E11/E12} 的**前置否决规则**，注册为规则而非链接——它不是事实关系，是业务约束。→ 待裁决 L6

## 七、缺口清单（两域相关，逐条待裁决）
- **G1** 奖品无维表：prize_id/nm 散在事实表与 DWS → 补 DIM_OR_PRIZE 或内联枚举。
- **G2** DIM_CH_CHL_DF 字段重复两轮（脏）→ 拆层取舍需数据侧确认。
- **G3** Activity 新旧双轨（activity_id / parent_act_id / 新活动表）→ 确认新活动表是否在字典外。
- **G4** 抽奖无单次行为明细（仅累计额度）→ 单次抽取分析不可行，语义层应声明此边界。
- **G5** 匿名黑名单表仅 1 个业务字段，与用户黑名单场景字段不对齐 → 合并或分开建模待定。
- **G6** PV/CT 横跨注册/活跃两域：同一事件表两域共用 → 口径按分析域区分（引流入口 vs 行为环），语义层注册两条口径规则，不建两个事件对象。
