## 故事弧（真实时间线）

1. **症状**：S3 收口——tag v0.3.0、698 测试全绿、三个行业演示、54 表 33 对象。旁观者说"很完整"，我却跟同事说：这个项目让我迷茫了。
2. **自己会诊**（自我对抗）：双演示并列没有关系、33 对象一股脑摆出来淹掉了唯一一条清晰的链、构建器不知道给谁看——每个零件都验收过，但从来没人设计过"整机"。
3. **找外行测试**：把系统给非金融人士看，"看不懂"——但比看不懂更伤的是原作者自己也讲不清它和 Excel 的区别。
4. **翻宪法**（方向与战略 v0.2，08-14 写的）：脊柱之问白纸黑字——"当消费者从人看报表变成大模型读+操作，建模范式必须变"。**产品面背叛了论点**：嘴上"为 Agent 而建"，界面是"为 BI 而建"的壳。
5. **三刀**：砍到一条核心链（33→12 进门面，一个不删）；监管口径锚定到条款号（四部法规原文逐条核对）；数据按业务逻辑重分布（原来的"均匀分布假数据"任何专家 30 秒嗅得出来）。
6. **双模型对抗复核**：豆包+DeepSeek 独立审查，两个模型**同时**咬中两个 P0（预警级别自相矛盾、双签高光业务逻辑不成立）——单模型自评根本看不见。
7. **活系统彩排**：让两个模型扮演"挑剔的处长"直接 curl 活系统、随口问剧本外问题。它们抓出了三个我方自检三轮都没发现的漏洞（阈值查不到/看板不自洽/追问来源被反问）。

## 可提炼的方法论点（白皮书弹药）

- **证据堆叠 ≠ 叙事**：没有脊柱的证据堆就是乱七八糟。一盘棋三切面（根/证据/放大器）失衡的后果清单。
- **验收标准决定产出形态**：页级验收（能看/好用/无障碍）全过，整级标准（访客 5 分钟懂价值）从未设立——于是每页都过关、整机不及格。
- **"为 Agent 而建"的悖论**：说要用 Agent 的系统，自己的界面先得经得起 Agent 时代的验收。
- **口径真相源**：业务断言必须回链到一份监管条款级锚定的文档；专家不在场时，用"法规原文锚定 + 多模型对抗 + 大白话测试"三道锁替代。
- **假数据的 30 秒嗅探**：均匀分布=机器掷骰子。五类风险各恰好 20%？任何内行一眼假。分布必须从业务逻辑来（信用风险主导、红档稀少、生命周期连贯）。
- **治理即卖点**："AI 拒绝重复提交""提议≠生效、驳回附条款"——风控人对 AI 的核心焦虑不是准不准，是谁担责。
