## 0. 一句话设计

**P1.5 在 ontology.db 上加三张治理网：① 权限策略元数据（对象级+属性级、双主体、读·写·审三分治，只标注不强制）② 审计最小骨架（append-only WORM：触发器禁改删 + SHA-256 哈希链防旁路篡改 + 字段级镜像 + TTL 分级，读侧查询审计明确排除）③ 映射置信度打标骨架（候选 → 高/中/低分档置信度 + 审核状态机 + 审核痕迹，高自动过/低进队列）——三骨架是 P2（读权限）/P3（映射审核）/P4（动作权限+审计完善）的公共地基，先立 schema 与机验口径，避免补丁式返工。**

三骨架全部落 ontology.db（治理真相库），复用 store.py 的 schema 管理模式；语义层只做「操作权限 + 策略分发 + 元数据标注」，数据权限下沉（DuckDB 视图/RLS）留 P4——对齐 C3。

## 0.5 三骨架模型总览

| 骨架 | 核心模型（规格） | 门禁 | 机验口径（一句话） |
|---|---|---|---|
| ① 权限元数据 | PermissionPolicy（对象/属性级 × 读·写·审 × allow/deny × agent/human）+ PermissionRegistry + 纯函数 decide() | **权限元数据可写** | 策略可增删改查；未知对象/未知属性/非法操作/非法主体在写入时即拒绝；deny-wins 决策语义可机验 |
| ② 审计最小骨架 | AuditLog 扩展（prev_hash/record_hash 链 + retention_class + source）+ audit_field_mirror + WORM 触发器 | **审计骨架可查** | 审计可追加可查询；UPDATE/DELETE 被触发器拒绝；哈希链整体可重算校验，旁路篡改必被 verify_integrity() 检出 |
| ③ 映射打标骨架 | MappingCandidate（score + level + review_status + evidence）+ classify() + 审核状态机 + mapping_review_history | **映射打标骨架可跑** | 对 builder 映射输出可自动打标（score→档→初始状态）；档位与分数自洽、高置信度自动过、低置信度进队列、状态流转合法、审核痕迹 append-only |

## 1. 权限元数据 schema

### 1.1 设计决策与边界（对齐议题3 §3.9 + C3）

| # | 决策 | 口径 | 依据 |
|---|---|---|---|
| D1 | **双主体** | subject = {kind: agent \| human, id}，粒度到主体；角色（role）仅作便捷分组 | §3.9-1 |
| D2 | **读·写·审三分治** | operation ∈ read / write / approve；读=只读查询、写=动作写回、审=映射审核等人工批准 | §3.9-2 |
| D3 | **审=人专属** | operation=approve 的 subject.kind 强制为 human（agent 不可审）——机验规则 V9 | §3.9-2 |
| D4 | **对象级 + 属性级，属性级只读** | 对象类型级策略控制整对象读/写；属性（列）级策略只控制「哪些列可读」；字段级写权限 S2 不做（下沉数据源） | §3.9-3 + C3 |
| D5 | **权限做在语义层** | 策略挂本体元数据（对象类型/属性），不依赖数据库层权限；语义层只做「操作权限 + 策略分发 + 对象/属性级标注」 | §3.9-3 + C3 |
| D6 | **数据权限下沉** | 源数据行/列级强制（DuckDB 视图/RLS、PostgreSQL RLS）留 P4；P1.5 只落语义层元数据标注并声明边界 | C3 |
| D7 | **角色便捷分组** | permission_roles 表：role = 一组 subject；策略可引用 role_id 代替逐主体列举 | §3.9-3 |
| D8 | **不造轮子** | 复用 S1 的 Pydantic + 注册表 + ALLOWED_ACTORS 白名单模式；FastAPI 鉴权复用在 P4 接线时落地 | §3.9-5 |

**语义层权限边界（防越界）**：语义层权限 = 操作级门禁（这个主体能不能读这个对象/执行这个动作/批准这个映射）+ 属性级读标注（返回哪些列）。它**不**做行级过滤、不做源库写权限强制——那些是数据源层（P4 RLS/视图）的职责。P1.5 阶段策略只作为**元数据与决策逻辑**存在（可写、可查、可机验），**不接线到动作/查询执行**（接线 = P4/P2，接入点见 §4.4）。

### 1.2 权限策略模型（Pydantic 规格）

```python
# src/runtime/permissions.py（规格，实现由编码角色落地）
from typing import Literal
from pydantic import BaseModel, Field

PermissionOperation = Literal["read", "write", "approve"]   # D2 三分治
PermissionEffect    = Literal["allow", "deny"]
SubjectKind         = Literal["agent", "human"]             # D1 双主体
PolicyScope         = Literal["object", "attribute"]        # D4 粒度


class PermissionSubject(BaseModel):
    """双主体：agent（LLM/Agent 操作）或 human（人/工作台）。"""
    kind: SubjectKind
    id: str  # agent:"procurement_agent" / human:"jack"（无用户体系期用稳定标识，P4 定身份来源）


class PermissionPolicy(BaseModel):
    """一条权限策略：谁（subject/role）对哪个对象/属性做什么操作、allow 还是 deny。"""
    policy_id: str
    object_type: str                          # 必须已注册对象（V1）
    operation: PermissionOperation
    effect: PermissionEffect = "allow"
    subject: PermissionSubject | None = None  # 直接主体；与 role_id 二选一（V7）
    role_id: str | None = None                # 便捷分组引用
    scope: PolicyScope = "object"
    attributes: list[str] = Field(default_factory=list)  # 仅 operation=read 允许非空（V6）
    version: int = 1
    created_at: str = ""
    updated_at: str = ""
```

**角色便捷分组**：PermissionRole = {role_id, name, members: list[PermissionSubject]}，存 permission_roles 表。decide() 展开 role 时把 role 的成员并入 subject 集合。角色只做「便捷分组」——策略主体的权威表达仍是逐主体，角色不存在时策略失效（V7）。

### 1.3 决策语义 decide()（纯函数，P1.5 即机验）

```python
def decide(subject, object_type, operation, attribute=None) -> PermissionDecision:
    """权限判定（纯函数，无副作用，P4 接线时直接复用）。

    规则：
    R1  fail-closed（默认拒绝）：无匹配策略 → denied；
    R2  deny-wins：同一 (object_type, operation, subject) 上显式 deny 覆盖 allow；
    R3  属性级读可见集：对象级 read allow 给出可读属性全集（默认 = 对象全部字段），
        再按属性级 deny 剔除；对象级 deny 全局优先（属性级 allow 无法翻案）。
    R4  operation=approve 仅 human（V9 写时机验 + 此处兜底）。
    """
```

- PermissionDecision = {allowed: bool, visible_attributes: list[str] | None, matched_policy_ids: list[str]}（matched 供审计溯源）。
- 属性级读判定：decide(subject, "Order", "read", attribute="total_cents") → allowed 当且仅当该属性在 visible_attributes 内。
- P1.5 机验点：fail-closed（无策略→denied）、deny-wins（deny 覆盖 allow）、属性级剔除、approve-human 兜底——四条均可单测，不依赖执行器接线。

### 1.4 写时机验规则（V1–V9，P1.5「可写」的核心机验口径）

策略写入（create/update）与 validate() 全量校验共用同一规则集（单一实现，防双轨漂移）：

| 规则 | 检查 | 拒绝口径 |
|---|---|---|
| V1 | object_type ∈ Registry.object_types() | 未知对象拒绝（门禁点名项） |
| V2 | 属性级策略的每个 attribute ∈ 该对象 model 字段 | 未知属性拒绝 |
| V3 | operation ∈ {read, write, approve} | 非法操作 |
| V4 | effect ∈ {allow, deny} | 非法效果 |
| V5 | subject.kind ∈ {agent, human} | 非法主体类型 |
| V6 | attributes 非空 ⇒ operation == "read" | 属性级仅读（D4/C3） |
| V7 | role_id 非空 ⇒ 该 role 已存在；且 subject 与 role_id 二选一 | 未知角色 / 双填 |
| V8 | policy_id 唯一（重复注册拒绝，防静默覆盖，对齐 Registry 先例） | 重复策略 |
| V9 | operation == "approve" ⇒ subject.kind == "human" | 审=人专属（D3） |

V1–V9 由 GovernanceValidator 单一实现；Registry 通过 add_self_check 挂载（与 des_objects 先例一致，registry 保持通用），启动自检时对全部策略做一致性校验（策略引用对象/属性存在、规则全过）。

### 1.5 存储与注册

- 表：permission_roles + permission_policies（DDL 见 §4.1），落 ontology.db。
- 注册表：PermissionRegistry（内存态 = 权限元数据镜像，启动从表加载；写走服务层 CRUD → 落表 + 更新内存）。对齐 S1「schema 元数据单一来源」——策略的权威在表，内存注册表供运行期 O(1) 判定。
- 服务层：PermissionService 提供 create/update/delete/get/list（CRUD + V1–V9 校验），P1.5 门禁「可写」以服务层为准；**FastAPI 路由与 actor 鉴权接线留 P4**（骨架阶段不造 UI/路由）。
- 策略变更的审计落痕（谁改的策略）留 P4（届时经 API + 审计 source='permission'），P1.5 不接。

### 1.6 P2/P3/P4 消费接入点（预留，§4.4 汇总）

- **P4 动作执行**：ActionEngine.execute() 在 ① 参数校验 与 ④ 前置规则 之间插权限门位；deny → rejected + 新增错误码 PERMISSION_DENIED（加错误码 = 改本体 schema 边界，P4 开工前与架构确认）+ 审计落 rejected（含 matched_policy_ids）。
- **P2 契约执行**：读侧在契约执行前 decide(subject, object_type, "read")；属性级 visible_attributes 决定返回列集（过滤 SELECT 列）。
- **P3 映射审核**：批准候选 = decide(subject, <对象>, "approve")（human）；审核痕迹落 review_history + 审计（source='review'）。

## 2. 审计最小骨架

### 2.1 范围决策（明确「记什么」）

| 审计对象 | P1.5 | 理由 |
|---|---|---|
| 动作执行（action execution）动作级 | ✅ 骨架扩展（哈希链 + 分类字段） | C5「动作级」；S1 已有 audit_log |
| 字段级镜像 | ✅ 新增 audit_field_mirror | C5「字段级镜像」；「谁改过某字段」可查，不靠解析 effects_json |
| 读侧查询审计 | ❌ **明确排除** | 读侧审计「记什么」（query_id/耗时/结果规模，不记查询内容防隐私）依赖 P2 ChatBI 契约形态才可定义；预留 source='query' 分类字段，P2 落 |
| 会话存储 | ❌ 独立 | C5「审计独立于会话存储」：审计不依赖 sessions，session 只经 audit_id 引用（P4 建 sessions） |

### 2.2 WORM（append-only 双层防篡改）

| 层 | 机制 | 防什么 | 机验 |
|---|---|---|---|
| L1 应用/API 层 | AuditLog 只提供 append/get/query，无 update/delete 方法 | 正常调用路径不可能改删 | 接口面检查（无 update/delete 公开方法） |
| L2 SQLite 触发器 | audit_log / audit_field_mirror / mapping_review_history 建 BEFORE UPDATE / BEFORE DELETE → RAISE(ABORT) | 绕过 API 直连库的 UPDATE/DELETE | UPDATE/DELETE 抛错测试 |
| L3 哈希链 | 每条记录存 prev_hash + record_hash，可整体重算校验 | 文件级/旁路篡改（直接改库文件、恢复攻击） | 拷贝库+删触发器改数据 → verify_integrity() 检出 |

> 审计修正策略（重要）：审计只追加、不修改。发现记录有误 → 追加一条「修正记录」（correction model），绝不 UPDATE 原记录（否则违背 WORM）。此策略需 Jack 确认（见 §6 R3）。

### 2.3 哈希链规格（零依赖）

- 算法：SHA-256（stdlib hashlib，**不引哈希链库**）。链序 = ORDER BY audit_id（ULID 时间有序——S1 选 ULID 的副产物，天然给链定序）。
- 每条记录：record_hash = SHA256(prev_hash + "|" + canonical_json(record 内容))；首条 prev_hash = ""（genesis）。
- canonical 序列化：json.dumps(fields, sort_keys=True, separators=(",",":"), ensure_ascii=False)（确定性强、跨版本稳定）。
- verify_integrity() -> IntegrityReport：按链序重算全部 record_hash 与 prev 衔接，返回 {ok: bool, checked: int, broken: [audit_id, ...], first_broken_index}。正常链全绿；任一记录被改/删除/插入 → 报告 broken（篡改检测）。
- 字段级镜像行不单独入链（跟随母记录）；镜像完整性 = 每条 applied 审计的 effects 与镜像行一一对应 + 镜像表 append-only 触发器保护。

### 2.4 字段级镜像 + TTL 分级 + 独立于会话

- **字段级镜像** audit_field_mirror：{mirror_id, audit_id, object_type, pk, prop, old_value, new_value, ts}。由 AuditLog.append(record, effects) 在**同一事务**内落（记录+镜像原子）。动作管道已有 Effect(object_type, pk, prop, old, new) 数据源（effects_json 的规范形态），直接同步派生镜像行，不重复解析。
- **TTL 按数据分级**：retention_class ∈ {standard, sensitive, transient}（枚举单一来源 + CHECK）。默认：动作审计+字段镜像 = sensitive（合规长保留）；映射审核痕迹 = standard；查询元数据（P2 预留）= transient。**实际保留时长与清理任务 = P4**（届时按计划评估 S3 Object Lock/immudb 生产化，Jack 拍板）；P1.5 只落分类字段 + 机验枚举合法。
- **独立于会话存储**：审计表不引用/不依赖 sessions（P4 才建）；反向，session 若需追溯动作，只存 audit_id 引用。审计模块构造不依赖任何 session 状态（结构性约束，可机验：AuditLog 初始化仅依赖 Store）。

### 2.5 接口扩展 + 机验点

```python
class AuditLog:  # src/runtime/audit.py 扩展（规格）
    def append(self, record: AuditRecord, effects: list[Effect] | None = None) -> str:
        """原语义 + 计算 prev_hash/record_hash（链） + 同步落字段级镜像（同一事务）。"""
    def get(self, audit_id) -> dict | None: ...   # 不变
    def query(self, action=None, outcome=None, page=1, page_size=20): ...  # 不变
    def verify_integrity(self) -> dict:  # 新增：重算哈希链 → IntegrityReport
```

机验点：① WORM（UPDATE/DELETE 抛错）；② 哈希链正确性（record_hash = 按规格重算值）；③ 篡改检测（正常链 ok；拷贝库改数据后 broken）；④ 字段镜像一致性（applied 审计的 effects 数 = 镜像行数且一一对应）；⑤ retention_class/source 枚举合法；⑥ 审计独立于会话（AuditLog 不依赖 session 状态）。

## 3. 映射置信度打标骨架

### 3.1 候选模型（对齐议题2 §3.7）

映射候选 = 一条「源表字段 → 本体目标」的建议，携带置信度与审核状态。三类候选：

| kind | 候选内容 | 来源（S1 builder 输出） |
|---|---|---|
| object | 源表 → 本体对象类型 | DES 语义已知 / naming 派生 entity_class |
| attribute | 源列 → 本体属性 | naming.derive_property_schema / DES |
| link | 源字段 ↔ 目标字段 → 本体链接 | fk_detection.detect_links / alias_matcher.match_aliases |

```python
# src/builder/mapping/annotate.py（规格）
ConfidenceLevel = Literal["high", "medium", "low"]
ReviewStatus     = Literal["draft", "reviewing", "approved", "rejected"]
MappingKind      = Literal["object", "attribute", "link"]

class MappingCandidate(BaseModel):
    candidate_id: str
    kind: MappingKind
    source_table: str
    source_field: str | None        # object 级候选可为空
    target: str                     # 目标对象类型名 / 属性名 / 链接名（注册表校验 C4）
    confidence_score: float = Field(ge=0, le=1)   # 0-1，来自适配器
    confidence_level: ConfidenceLevel             # classify(score) 派生（纯函数）
    review_status: ReviewStatus = "draft"
    auto_approved: bool = False
    evidence_json: dict = {}        # 证据：method + 原始分量（direct_ratio 等）
    created_at: str = ""
    updated_at: str = ""
```

### 3.2 置信度：score + 档位（阈值可配，C2）

```python
def classify(score: float, high: float = 0.9, medium: float = 0.6) -> ConfidenceLevel:
    """纯函数：score ≥ high → high；≥ medium → medium；否则 low。
    阈值只是临时默认，P3 用 ground truth 校准（C2），骨架不把阈值写死为神圣数字。
    """
```

- **高置信度自动过 / 低置信度进审核队列**（议题2 §3.7-2）：routing(candidate) = high → auto_approved=True, status=approved（并写一条 reviewer="auto" 的审核历史）；medium/low → status=draft（进审核队列，队列内按 score 降序排优先级）。
- 机验口径：auto_approved ⟺ (score ≥ high_threshold ∧ status=approved ∧ 历史含 auto 记录)；档位与分数自洽（high ⇒ score≥0.9 等）。

### 3.3 审核状态机（复用 status_machine 模式）

复用 src/builder/status_machine.py 的「合法流转表 + assert_transition」模式（不造轮子），映射审核的合法流转：

| from | to | 说明 |
|---|---|---|
| draft | reviewing / approved | 人工接手 / 工作台一键接受 |
| reviewing | approved / rejected | 人工裁决 |
| rejected | draft | 重新打标/重审（允许回环） |
| approved | — | **终态**（不可回退不可改，入注册表的依据） |
| (auto) draft→approved | reviewer="auto" | 高置信度自动过 |

非法流转抛 IllegalTransitionError（复用现有异常语义）。机验：状态机表完整 + 非法流转抛错 + 终态锁定。

### 3.4 审核痕迹（append-only + 对接审计）

- mapping_review_history：{history_id, candidate_id, from_status, to_status, reviewer, reviewed_at, note}，append-only（触发器禁改删）。
- **痕迹单一来源** = review_history；P3 审核工作台上线时，把「人审动作」**同步**落 audit（source='review'），形成完整证据链（审计=底层证据面，见 §0.5 关系）。
- 机验：每次状态流转必有一条 history；history 与 candidate 最终状态一致；history append-only。

### 3.5 接 S1 builder 映射输出（适配器规格，精确到公式）

| 来源模块 | 输入形态（现状） | 适配为候选 | score 公式 |
|---|---|---|---|
| fk_detection.detect_links | DetectedLink.match_summary = {direct_match_rows, format_normalized_match_rows, unmatched_rows, total_rows} | link 候选（每 DetectedLink 一条） | (direct + format_normalized) / total_rows（total=0 → 0.0 low）；evidence 记三分量 + detection_method |
| alias_matcher.match_aliases | AliasMatch.confidence ∈ {1.0, 0.95, 0.92, 0.85, 0.75, 0.0} + match_type | link/attribute 候选（**仅 matches，no_match 不进候选池**——S1 已归「待补录」） | = confidence；evidence 记 match_type + disambiguation_note |
| naming.derive_property_schema | 派生 property_schema（无置信度） | attribute 候选（每非 is_technical 列一条） | 0.9（规则确定性高，仍过审） |
| DES（语义已知，议题2 §3.7-1） | DES 自带对象语义 | object/attribute 候选 | 1.0（高置信度自动过） |

适配器输出统一为 list[MappingCandidate]；打标入口 annotate_mapping_candidates(source, registry) -> list[MappingCandidate]（classify → routing → 落表）。**approved 候选如何写入 mappings/注册表 = P3 接线点**（议题2 §3.7-3「改完即入注册表」），P1.5 只落标注状态。

### 3.6 机验点

① classify 档位与分数自洽；② 高置信度自动过（auto_approved 三条件）；③ 低/中进审核队列（初始 draft）；④ 状态流转合法（非法抛错、approved 终态）；⑤ 未知 target（对象/属性不在注册表）拒绝（机验规则 C4，对齐权限 V1/V2 的注册表校验风格）；⑥ 每次流转有 history 且 append-only；⑦ score ∈ [0,1]。

## 4. 三骨架的关系与存储

### 4.1 表结构总览（GOVERNANCE_SCHEMA 规格，复用 store.py 模式）

新增 GOVERNANCE_SCHEMA 段（store.py，仿 BUILDER_SCHEMA：CREATE TABLE IF NOT EXISTS + 单一来源枚举派生 CHECK + 从 DDL 自动解析 GOVERNANCE_TABLES——沿用 red-team I3 模式防双轨漂移）：

```sql
-- ================= 治理骨架（P1.5）=================
-- ① 权限元数据
CREATE TABLE IF NOT EXISTS permission_roles (
  role_id      TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  members_json TEXT NOT NULL DEFAULT '[]',     -- [{"kind": "agent"|"human", "id": "..."}]
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS permission_policies (
  policy_id      TEXT PRIMARY KEY,
  object_type    TEXT NOT NULL,                -- V1 注册表校验（应用层）
  operation      TEXT NOT NULL CHECK (operation IN ('read','write','approve')),
  effect         TEXT NOT NULL CHECK (effect IN ('allow','deny')),
  subject_kind   TEXT NOT NULL CHECK (subject_kind IN ('agent','human')),
  subject_id     TEXT NOT NULL DEFAULT '',
  role_id        TEXT NOT NULL DEFAULT '',     -- 与 subject 二选一（V7 应用层）
  scope          TEXT NOT NULL DEFAULT 'object' CHECK (scope IN ('object','attribute')),
  attributes_json TEXT NOT NULL DEFAULT '[]',  -- V6：仅 operation=read 允许非空
  version        INTEGER NOT NULL DEFAULT 1,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_policy_obj  ON permission_policies(object_type, operation);

-- ② 审计：字段级镜像（audit_log 加列走幂等补丁，见 §4.3）+ WORM 触发器
CREATE TABLE IF NOT EXISTS audit_field_mirror (
  mirror_id    TEXT PRIMARY KEY,
  audit_id     TEXT NOT NULL,                  -- 应用层对账（TD-10 先例，不加 SQLite FK）
  object_type  TEXT NOT NULL,
  pk           TEXT NOT NULL,
  prop         TEXT NOT NULL,
  old_value    TEXT,
  new_value    TEXT,
  ts           TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_mirror_audit  ON audit_field_mirror(audit_id);
CREATE INDEX IF NOT EXISTS idx_mirror_target ON audit_field_mirror(object_type, pk, prop);
-- WORM 触发器（audit_log / audit_field_mirror / mapping_review_history）
CREATE TRIGGER IF NOT EXISTS trg_audit_log_wo_upd  BEFORE UPDATE ON audit_log
  BEGIN SELECT RAISE(ABORT, 'audit_log 只读（WORM）'); END;
CREATE TRIGGER IF NOT EXISTS trg_audit_log_wo_del  BEFORE DELETE ON audit_log
  BEGIN SELECT RAISE(ABORT, 'audit_log 只读（WORM）'); END;
-- （audit_field_mirror / mapping_review_history 同型触发器，略）

-- ③ 映射置信度打标
CREATE TABLE IF NOT EXISTS mapping_candidates (
  candidate_id     TEXT PRIMARY KEY,
  kind             TEXT NOT NULL CHECK (kind IN ('object','attribute','link')),
  source_table     TEXT NOT NULL,
  source_field     TEXT,
  target           TEXT NOT NULL,              -- C4 注册表校验（应用层）
  confidence_score REAL NOT NULL CHECK (confidence_score >= 0 AND confidence_score <= 1),
  confidence_level TEXT NOT NULL CHECK (confidence_level IN ('high','medium','low')),
  review_status    TEXT NOT NULL CHECK (review_status IN ('draft','reviewing','approved','rejected')),
  auto_approved    INTEGER NOT NULL DEFAULT 0,
  evidence_json    TEXT NOT NULL DEFAULT '{}',
  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_cand_status ON mapping_candidates(review_status, confidence_level);
CREATE TABLE IF NOT EXISTS mapping_review_history (
  history_id   TEXT PRIMARY KEY,
  candidate_id TEXT NOT NULL,
  from_status  TEXT NOT NULL,
  to_status    TEXT NOT NULL,
  reviewer     TEXT NOT NULL,                   -- human id 或 'auto'
  reviewed_at  TEXT NOT NULL,
  note         TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_review_cand ON mapping_review_history(candidate_id);
```

### 4.3 schema 演进与复用纪律

- Store.migrate() 扩展：执行 GOVERNANCE_SCHEMA（新表 CREATE IF NOT EXISTS）→ 执行 _apply_governance_patches()（audit_log 加列幂等 ALTER，已加则跳过）→ schema_version note 追加「治理段（P1.5）」标识。
- **不 bump schema_version**：沿用 v2/v3/v4「幂等补丁只追加 note 不升号」先例，保住 get_schema_version()==1 既有契约（tests/test_b2_action_engine.py:736 锁定）。
- **单一来源枚举**：operation/effect/subject_kind/confidence_level/review_status/retention_class/source 全部模块级常量 + 派生 CHECK（TD-9 同源模式），机验「CHECK 值 = 常量」。
- **机验结构断言**：migrate 后 GOVERNANCE_TABLES ⊂ sqlite_master；audit_log 新列存在；schema_version note 含治理段。
