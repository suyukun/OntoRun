## 一、根因（第七轮已实证）

- **F20**：生成器两表独立随机——ap_subsidiary_credit_detail 余额 = rng.uniform(100, 200000) 万，ap_concentration_limit 分子 = net_capital × ratio，**两表从不互引**。天晟/瑞华主链靠补丁手工对齐，背景集团天生不勾稽（18 抽 3 中，000098 明细 36.53 亿 vs 归集 3.3 亿方向反了）。
- **F21**：_concentration_ratio 分布堆在低位 + 补丁只造了 rank1/2 → 9.4% → 1.025% 九倍断崖。
- **F23**：明细逾期天数 rng.randint(0, 400) 超 364 天业务时钟上限。
- **F19**：F14 洗文案时把全部信号 push 列统一替换成「集团集中度指标异动」，非集中度维度信号被误标。
- **F18**：/risk/audit 直读审计全表，开发冒烟行（smoke-c1/c2、PURPLE、comment=x）占 35/55。

## 二、修复设计（按依赖序）

### 第 1 批 · 数据层补丁（patch_risk_live_data.py 新增函数，幂等）

**P-F20 背景集团勾稽重锚（台账为锚，明细回填）**
1. 对前十大 + 质疑道具（001516/000098）共 12 组：读台账归集分子 S（SUM(concentration_limit)）；
2. 组内 detail 行 business_balance 等比例缩放，使 Σbusiness_balance = S ÷ (1−内部占比)，内部占比取 0.25–0.35（组内随机但种子固定，保证幂等）；

**P-F21 前十大分布补腰**
