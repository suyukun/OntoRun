# 安平金控 · 业务流程建模（DES 企业模拟 STEP 3 初稿 · BPMN 2.0 + 状态机）

> 方法：BPMN 2.0 分级（Level 1 描述性 → Level 2 分析性 → Level 3 端到端）。初稿，供 M2 本体动作/状态机参考。
> 依据：企业画像 + 业务域建模 + 表结构字典（DEAL_TYPE/BUSINESS_TYPE/ORDER_STATUS 等已还原真实流程）。

## 核心流程 1：预警信号处置全流程（端到端，Level 3）

### 流程描述
预警信号产生 → 人工确认 → 等级定级 → 处置方案 → 处置审批 → 推送执行 → 销号

### BPMN 泳道
| 泳道 | 角色 | 动作 |
|---|---|---|
| 系统 | 预警监测 | 产生预警信号（系统识别） |
| 风险监测中心 | 预警岗 | 信号确认（确认/误报）、定级建议 |
| 风险管理中心 | 风险经理 | 等级定级、处置方案制定 |
| 风险审批中心 | 审批岗 | 处置审批（多级岗位链） |
| 子公司风管岗 | 执行岗 | 推送、执行处置、反馈 |
| 风险审批中心 | 审批岗 | 销号确认 |

### 状态机（WarningSignal + Disposal）
**预警信号状态（ap_warning_signal.sgn_stat）**：
- GENERATED（已生成）→ CONFIRMED（已确认）→ GRADED（已定级）→ IN_DISPOSAL（处置中）→ CLOSED（已销号）
- 分支：CONFIRMED → REJECTED_AS_FALSE（误报，关闭）

**处置状态（ap_disposal）**：
- DRAFT（草拟）→ SUBMITTED（已提交）→ APPROVING（审批中）→ APPROVED（已通过）/ REJECTED（已驳回）→ EXECUTING（执行中）→ DONE（已完成）

### 状态迁移触发条件
| 迁移 | 触发 |
|---|---|
| GENERATED→CONFIRMED | 人工确认（低风险，双签否） |
| CONFIRMED→GRADED | 风险经理定级（等级变更=高风险双签✅） |
| GRADED→IN_DISPOSAL | 处置方案提交（高风险双签✅） |
| IN_DISPOSAL→CLOSED | 处置完成 + 销号确认（高风险双签✅） |
| CONFIRMED→REJECTED_AS_FALSE | 误报确认（低风险） |

## 核心流程 2：审批链（多级岗位，Level 2）
- 审批单（ap_approve_order）：PROCESS（审批中）→ APPROVED（已通过）/ REJECTED（已驳回）
- 审批节点（ap_approve_node）：NODE_SEQ 1-初审 → 2-复审 → 3-推送；APPROVE_RULE ANY_ONE/ALL
- 岗位链：风险预警管理岗 → 风控部门负责人 → 集团风控领导

## 核心流程 3：集中度限额调整（Level 2）
- 限额调整（ap_concentration_limit_adj）：申请 → 审批 → 生效；保留旧值审计（CONCENT_LIMIT_OLD）
- 集中度预警（ap_warn_signal_concentration）：预警 → 定级 → 处置

## 核心流程 4：风险项目（Level 1）
- 风险项目登记（ap_risk_project）：登记（五级分类/担保方式/减值/业务余额）→ 进展更新 → 处置

| 动作 | 归属域 | 双签 | 状态机 |
