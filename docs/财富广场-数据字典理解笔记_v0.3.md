## 二、业务图景（从数据反推）

财富广场 = 中信金控客户端 App。数据围绕一条用户旅程：

**引流（活动/外投/渠道）→ 注册 → 激活 → 实名 → 活跃（PV/曝光/点击）→ 参与活动任务（抽奖/奖品/积分）→ 导流到金融产品（转化）**

周边两条支线：① 内容线（资讯/财富号/AI 打标）；② 企微客服线（客服任务/朋友圈/单聊）+ 中信人（员工）转介线。

## 三、数据域（10 个）与实际分布

用户 CU / 运营 OR / 经营 BS / 风控 RC / 产品 PS / 交易 TR / 账务 AC / 公共 PB / 日志 LM / 渠道 CH。
实际事实表集中在 LM(7)、OR(15+)、TR(4)、CU(3)、BS(1)、CH(1)；**RC/PS/AC 三个域目前基本无事实表**（风控仅黑名单）。

## 六、身份识别（handoff 命门）的现状

- 四种 ID：`usr_id` 用户ID、`login_id` 登录ID、`anony_id` 匿名ID、`uid_anony_id` 用户游客id（MAU 表注明「统计 UV 使用」）。
- 归一靠两张 DIM：`DIM_CU_LOGIN_ANONY_MAPPING_DF`（login_id ↔ anony_id ↔ last_login_id 最近一次时间）、`DIM_CU_ANONY_LAST_LOGIN_MAPPING_DF`（anony_id → 最新 login_id）。
- 埋点侧 `IS_VISIT` 标记是否游客（0/1）。
- **本体化第一刀**：User 对象 + 身份链接（IdentityMapping）显式建模，问答时「游客/登录/实名」三态口径由语义层统一裁决，不许 LLM 现场拼 ID。

## 九、业务理解深化（吸收数据分析项目背景，2026-09-08）

来源：Jack 转数据分析项目背景注入 + 该项目 `AGENTS.md` / `knowledge/{metrics.md, 契约v0, problem-tracker.md, 北极星之问, 业务背景速查}`。

- **平台本质**：财富广场 = 依附集团金融 APP 的运营入口（负一屏/微广场/导航栏/服务号），无独立刚需场景；日活靠活动脉冲，自然基线弱——**「北极星之问：人为什么会来财富广场」**（领导亲出，利益驱动 vs 需求驱动，候选答案 A 集团资产视图 + B 金融需求路由）。
- **入口结构 ↔ 字典身份命门互证**：负一屏匿名占比 89%、微广场 >75% 匿名、广场活跃中一次性不登录 43.9%（P6 数据）——数仓四种 ID + 两张映射表正是为此而生；本体第一刀做身份链接得到业务侧强验证。
- **五大 KPI 现状（8 月，0903-FL 终稿）**：日活 7.0 万（-30.4%，缺口 8.0 万）/ 注册 76.7 万连跌 / 导流 148.7 万人次（+85.1% 但质未验）/ 交叉 9.5 万单（高价值仅 22%，人工分类）/ 盈利（商城转亏非主线）。
- **在账八大问题**（problem-tracker I1-I8，月月跟踪）：日活缺口、注册连跌、导流涨质未验（I4）、高价值占比低（I5）、战客专区日活 6 人、行情中心受阻、功能延期集群、商城转亏（不披露）。
- **口径教训实证（I4）**：894 vs 759 的「单任务效能假衰减」= 口径错配（总量口径 vs 活动口径），同指标不同口径比出假结论——**这就是 OntoRun「口径固化在语义层、LLM 不许发明公式」要治的病，兄弟项目已用真实翻车案例背书**。
- **两项目衔接点**：① `metrics.md` = 口径唯一事实源（文档态、人读）→ OntoRun 语义层可让它变成机器可执行态；② 契约 v0 62 指标 = 数字事实源（LLM 判断稿输入）；③ 数据分析项目当前「数据入口待定」（月报管线第一环）——**本体化的语义接口正是该空位的候选答案**；④ 该项目机检哲学「可机检的规则一律回填断言，纯文字规则视为未生效」与 OntoRun 铁律②同构。
- **协作纪律（引用其数字时）**：逐字对齐契约 v0，不自造不推算改写；人次≠人数严格区分；拿不准问 Jack。

## 十、业务流程关键表图理解（Jack 手绘，2026-09-08）

### 四阶段旅程（Jack 划分，取代此前的数据反推版）
1. **获客**：点击引流（CT→PV）→ 注册（RGST→渠道关联授权 RLTV；非金融渠道激活 ACTV）→ 实名（RGST 表内标记 is_real/real_dt/real_way/real_type，非独立表）→ 授权（RLTV）。支撑维度：渠道 CHL、注册用户 USR_INFO、日期 DATE。
2. **活跃**：页面访问环（PV→曝光 EV／点击 CT；点击→资讯浏览 PV_CONT／资讯互动 CONT_INTER；月活明细 MAU_DI）＋ 活动参与链（任务完成 mission_completed → 抽奖 lucky_draw → 奖品发放 prize_detail；**黑名单 USR_BLACKLIST → 抽奖 = 风控拦截**）。支撑维度：财富号 MSG_WTHAT、资讯 MSG_BASE、活动 ACT_INFO、任务 TSK_INFO、活动任务 mission_info、渠道、日期、策略 STRGY。
3. **转化**：导流 DRAG → 交叉销售订单 **DWD_BS_SHARE_DF**；MGM 线（转介分享 CSPM_MGM_USR_SHARE ＋ 奖励发放 CSPM_MGM_AWARD；MGM 已永久下线，表在账）。支撑维度：渠道、注册用户、中信人员工 CTM_EMP、中信人活动 CTM_ACTY、中信人机构关系 CTM_ORG_REL、日期。
4. **留存**：会员服务（体系=空框建设中；基础指标 DWS_MEM_SYS_INDX）、权益兑换（积分发放 UCOIN_DETAIL／积分商城订单 JFSC_ORDER → 积分消耗 UCOIN_PROCESS）、企微（单聊任务 SNGL_TSK_EXEC → 智能客服聊天 AI_CUST_SEV_CA；朋友圈客服确认 CRCE_FRD_CFM → 朋友圈互动 CRCE_FRD_INTRT）、客户服务（空框——数据未建）。支撑维度：渠道、注册用户、日期、中信人机构/员工。

### 箭头 = 业务流转关系（本体「链接」的原料，非外键）
- 获客漏斗：点击 → 访问 → 注册 → 实名 → 授权（旅程推进）
- 活跃环：访问 → 曝光/点击（行为层级）；任务完成 → 抽奖 → 奖品发放（活动事件链）
- 风控拦截：黑名单 → 抽奖（风控作用于活动资格）
- 转化漏斗：导流 → 交叉销售订单
- 权益链：积分发放/商城订单 → 积分消耗
- 企微链：单聊任务 → 客服聊天；朋友圈确认 → 朋友圈互动

### 对本体建模的三条直接指引
1. 切片对象候选池 = 图中关键表（用户、渠道、活动、任务、奖品、导流目标、资讯、中信人、积分权益）——3-5 对象第一刀从中选；
2. 链接以业务流转箭头为原型：旅程推进（转化率语义基础）、事件链归属（任务→活动）、风控资格（黑名单→活动参与）；
3. 两个空框（客户服务、会员体系）= 数据未建（对应 I8 功能延期集群），切片避开或留接口位。
