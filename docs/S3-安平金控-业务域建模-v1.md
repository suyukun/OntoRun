# 安平金控 · 业务域建模（DES 企业模拟 STEP 2 初稿 · DDD 限界上下文）

> 方法：DDD（Bounded Context / Ubiquitous Language）。初稿，供 M2 本体参考（不具约束力）。
> 依据：企业画像 + 54 表选表清单 + 金控风控通用业务认知。

## 业务域清单（限界上下文）

### 1. 客户域（Customer Context）
- 边界：单一客户 / 集团客户 / 客户关系 / 重要客户名单
- 核心实体：Customer（单一客户）、GroupCustomer（集团客户）、CustomerRelation（客户关系）、ImportantCustomerList（重要客户名单）
- 通用语言：单一客户、集团客户、集团、关联方、重要客户、TOP500
- 对应表：ap_customer, ap_group_customer, ap_customer_relation, ap_customer_relation_tree, ap_important_customer_list, ap_top500_customer_risk

### 2. 风险监测域（Risk Monitoring Context）
- 边界：预警信号识别、指标监测、维度指标、排名
- 核心实体：WarningSignal（预警信号）、Metric（维度指标）、DimRank（维度排名）、WarningSource（预警来源）
- 通用语言：预警信号、预警等级（红/黄/蓝）、信号类型、信号主题、指标、维度、排名
- 对应表：ap_warning_signal, ap_dim_metric, ap_metric_std, ap_dim_rank, ap_metric_std

### 3. 预警处置域（Warning Disposal Context）
- 边界：预警确认、等级定级、处置方案、处置执行、销号
- 核心实体：Disposal（处置）、DisposalDetail（处置详情）、WarningLevelChange（等级变更）
- 通用语言：预警确认、定级、处置方案、处置措施、销号、处置进展
- 对应表：ap_warning_disposal, ap_disposal, ap_disposal_detail

### 4. 集中度管理域（Concentration Context）
- 边界：集中度限额、集中度预警、限额调整审批
- 核心实体：ConcentrationLimit（集中度限额）、ConcentrationWarn（集中度预警）、LimitAdjustment（限额调整）
- 通用语言：集中度、限额、大额客户、调整、预警
- 对应表：ap_concentration_limit, ap_concentration_limit_adj, ap_concentration_warn_adj, ap_warn_signal_concentration

### 5. 押品管理域（Collateral Context）
- 边界：押品登记、估值、押品预警、抵质押物
- 核心实体：Collateral（押品）、PledgeDetail（押品明细）、Mortgage（抵质押物）
- 通用语言：押品、质押、抵押、估值、担保
- 对应表：ap_collateral, ap_subsidiary_mortgage, ap_bank_pledge_detail, ap_securities_pledge_detail

### 6. 共债管理域（Co-Debt Context）
- 边界：共债客户识别、风险评分
- 核心实体：CoDebtCustomer（共债客户）、CoDebtScore（共债评分）
- 通用语言：共债、多债、风险评分、多头授信
- 对应表：ap_codebt_customer, ap_codebt_warn_score

### 7. 风险项目管理域（Risk Project Context）
- 边界：风险项目登记、五级分类、减值、处置进展
- 核心实体：RiskProject（风险项目）
- 通用语言：风险项目、五级分类、减值、担保方式、风险暴露、业务余额
- 对应表：ap_risk_project

### 8. 审批域（Approval Context）
- 边界：审批单、多级岗位审批、推送、待办
- 核心实体：ApproveOrder（审批单）、ApproveNode（审批节点）、ApproveTask（审批任务）、ApproveTodo（待办）
- 通用语言：审批单、审批节点、初审/复审、审批中/通过/驳回、待办、推送
- 对应表：ap_approve_order, ap_approve_node, ap_approve_task, ap_approve_todo, ap_approve_oper_log, ap_approve_warn_rel

### 9. 机构与用户域（Org & User Context）
- 边界：机构、用户、岗位、字典
- 核心实体：Organization（机构）、User（用户）、BizDict（业务字典）
- 通用语言：机构、子公司、岗位、用户、字典项
- 对应表：ap_org, ap_user, ap_biz_dict, ap_data_dict, ap_sys_param

### 10. 合规审计域（Compliance & Audit Context）
- 边界：监管处罚、合规台账、审计记录
- 核心实体：RegulatoryPenalty（监管处罚）、ComplianceLedger（合规台账）、AuditDetail（审计记录）
- 通用语言：监管处罚、合规、审计、整改
- 对应表：ap_regulatory_penalty, ap_compliance_risk_ledger, ap_audit_detail

### 11. 资产与投融资域（Asset & Investment Context）
- 边界：客户资产、投资分布、子公司授信
- 核心实体：CustomerAssets（客户资产）、InvestDist（投资分布）、SubsidiaryCredit（子公司授信）
- 通用语言：资产结构、投资分布、授信明细
- 对应表：ap_customer_assets, ap_customer_invest_dist, ap_subsidiary_credit_detail

## 域间关系（核心链路）
客户域 → 风险监测域（客户产生预警信号）
风险监测域 → 预警处置域（预警被处置）
预警处置域 → 审批域（处置需审批）
风险监测域 → 集中度管理域（集中度预警）
客户域 → 押品域（客户有押品）
客户域 → 共债域（客户可能共债）
风险监测域 → 风险项目域（预警可能升级为风险项目）
审批域 → 机构与用户域（审批人来自机构/用户）

## 锚定
这 11 个域将映射为 M2 本体的对象/链接/动作，支撑"LLM 经语义接口问风险问题、执行真实动作"。
