## 2. 自足确认卡设计

### 2.1 设计问题
Jack：「我的同学不知道你说的是什么意思，不敢瞎确认。」现状 RuleCard = 规则人话描述 + 出处路径全文 + 影响表 Tag + 两个按钮——**缺三样**：这个数是啥（业务语言）、怎么算的实物证据（试算数字）、确认后影响谁（下游）。王工面对的是一句抽象规则，不是一张能对账的卡。

### 2.2 三问信息层级（普通卡）

每张卡固定四层，顺序不可换；三问区每问有固定图标锚位，形成肌肉记忆：

- **L1 标题行**：状态徽章 + 人话标题（**是非题句式**，如「只有已授权的记录才算授权用户，对吗？」）+ 右侧元信息（规则号 · 排队时长）。
- **L2 三问区**（默认全部展开，这是「敢确认」的最低配置）：
  - ① **这是什么数**：受影响度量的业务名+一句话，禁止表名/字段名打头（QC-4）；
  - ② **怎么算的 + 实物证据**：算式人话版一句 + **试算实例**（「按此口径跑 2026 年 8 月 = 552 人」）——数字是王工唯一能拿去对账的东西，有对账数字才算「自足」；
  - ③ **确认后影响谁**：受影响 ChatBI 数字清单（度量名）+ 涉及表（表名只在此处出现，定位用）。
- **L3 折叠区**（默认折叠，QC-3）：出处脚本「文件+行段」摘要，展开见片段（原则⑥）；历史确认记录。
- **L4 行动区**：确认人 + 两个按钮（措辞=规则本身的是非题变体，非抽象「通过/驳回」）；驳回走二次确认弹层（现状保持）。

## 3. 数字目录（对象页转向）

### 3.1 设计问题
Jack：「说实话有点专业，我看不懂也不会用。」现状 ObjectsPage = 工程 Table（ID/表达式/源表/维表 JOIN），是给写代码的人看的 schema 浏览器。王工要的不是「对象列表」，是**数字目录**——像查字典一样查「授权用户数是什么、怎么算的、可不可信」。

### 3.2 数字卡设计

页面=「口径字典」：主体是数字卡网格（度量为主体，5 张：3 原子+2 比率），维度降为下方折叠速查表。**每张卡直接回答北极星三问**：

- **卡面 L1**：人话名称（如「注册用户数」，不用 reg_user_cnt 打头，QC-4）+ 可信度徽章；
- **卡面 L2**：一句话含义（业务语言）+ 算式人话版（技术表达式收进折叠/详情）；
- **卡面 L3**：版本行——最近确认 commit 短码+确认人+日期（「谁确认的/哪个版本」直接可见）；
- **卡面 L4**：动作行——试算入口 + 看血缘 + 进详情。

**可信度状态编码**（度量自身无状态，聚合其关联口径规则，双编码 QC-7）：

| 状态 | 编码 | 判定 |
|---|---|---|
| 已钉死 | 绿徽章「✅ 口径已钉死」 | 关联规则全部 confirmed |
| 待钉死 | 橙徽章「⚠ N 条口径待确认」 | 关联规则含 unverified（N=条数，点击直达该卡确认动线） |

## 4. 局部血缘视图交互规格

### 4.1 定位与入口

- **全图降级**：首页画布改为**聚簇概览**——节点=层域（ODS/CDM/DIM/ADS，共 4 个大节点）+ 层内表数与未确认数角标。表数涨到一万，聚簇节点还是 4 个（回答 Jack「上万张表怎么展示」的第一层）。
- **详情血缘=按需局部视图**，三个入口：① 表/对象详情「看血缘」；② 规则卡/数字卡「看血缘」（这个数从哪来）；③ 首页聚簇节点点击 → 该层域表清单 → 选表进入。

### 4.2 交互规格

| 项 | 规格 |
|---|---|
| 范围 | 中心节点 + **默认 1 跳**邻居；「再看上游/下游」逐跳展开，最多 2 跳。**节点硬上限 30**（QC-6）：达上限停止展开并提示「已到 30 节点上限，N 个未显示——用筛选缩小范围」 |
| 布局 | **分层左→右**：ODS｜CDM+DIM｜ADS 三列，边一律向右流（业务读法：数据从哪来→怎么加工→出了什么数）。列内按节点名排序，坐标稳定不抖动。实现：自写分层坐标（按 layer 分列+列内均分），不引 dagre（新增依赖=先问档，收益不成比例） |
| 节点去重 | 同对节点多边合并为一条边+倍数角标「×2」；同层汇聚不画交叉，仅邻接边直连；节点固定尺寸（160×44），杜绝大小不一 |
| 高亮 | 中心节点描边加粗；关联未确认规则的边=红虚线+动画（现状保持）；hover 邻接边高亮、其余降透明度 |
| 图例 | 固定画布左下角一行：层色块+线型说明（实线=已确认链路 / 红虚线=含未确认口径），不随内容滚动 |
| 点击 | 点节点=右侧 Drawer 摘要（人话名/层域/关联规则状态/上下游计数）——Drawer 内「进入详情」「以此为中心重看」两个动作 |
| 空态 | 无邻居：Empty「『××表』还没有登记上下游」+ 出路按钮「返回详情」（QC-8）；加载失败：错误卡+重试 |
| 返回 | 面包屑「数字目录 / 表名 / 血缘」+ Esc 关闭；从规则卡进入时预高亮该规则相关边 |

**首页版式配套**（混合首页内部清爽化，IA 不推翻）：首屏=待确认横条（现状保留，顶格）+ 聚簇概览画布（区块数≤3，QC-1）；MiniMap 在聚簇视图下无意义，直接移除；图例压成画布内一行。

### 5.2 布局与留白规范（QC-9 配套）

- **间距四档**：8（元素内/图标与文字）/ 16（卡内区块间、卡间距）/ 24（页面容器 padding、区块间）/ 32（仅页首与正文之间）。禁止 4/6/10 级随手值。
- **字号四档**：页题 20、卡题/区题 16、正文 14、辅助/元信息 12（secondary 色）。
- **页面统一骨架**：`padding:24 → 页首（intro 一句 + 唯一主行动）→ 主体（间距 24）→ 页脚辅助`；每页首屏区块 ≤3（QC-1）。
- **层级纪律**：primary 按钮每视图 1 个（QC-2）；卡片边框色只用于状态语义（橙=待确认/绿=已确认），不再作装饰。
- **色彩 token**：沿用 AntD 默认 token + 两处语义色（橙 #fa8c16 系待确认、绿 #52c41a 系已确认）；红色只留给「未确认口径」风险提示，不作普通强调。

## 6. 开放问题（UX-1..UX-5，请老板逐条裁决）

> 恰好 5 条，进入 NC 答题卡。已裁决策（NC-Q1/Q2、ADR-0011/0012）不在其列。

**UX-1 首页是否立即执行 ADR-0012 降级判据**
背景：ADR-0012 定「上线满一个月图谱交互趋零→换工作台首页」，而 Jack 2026-09-11 反馈「一大堆内容挤在一起、卡片不能拖动」= 图谱日用价值趋零的最强证据，一个月观察期实质已可提前判定。
选项：a) 立即触发降级——首页=待确认工作台，聚簇概览图降为页内折叠区块，路由随时换回；b) 图谱仍作主体，只按 §4.2 做聚簇化清爽化；c) 严格等满一个月再定。
默认建议：**a**——用户（老板本人）的体感就是判据要抓的东西，不必为流程牺牲体验；保留路由换序半天成本可控。

**UX-2 试算数字从哪来**
背景：三问卡与数字卡的「试算 8 月=552」是「敢确认」的关键证据，但语义层当前只有查询引擎、无面向管理台的试算端点，数字不真=自足卡失效。
选项：a) 后端新增只读试算端点（点击触发+当日缓存，走既有语义查询链路）；b) 人工登记静态快照数字进注册表；c) 先快照后实算，分两步。
默认建议：**a**——图表明细同源纪律（AGENTS 铁律）不允许手填假数字；b 只能作端点未就绪时的过渡并须标「快照日期」。

**UX-3 ChatBI 侧默认口径标注**
背景：NC-Q2 已裁「R8 双口径并存、ChatBI 默认账户口径」，但该默认只在管理台可见；业务用户在 ChatBI 问「授权用户数」时看不到「按哪个口径」的说明，三问在最后一公里断头。
选项：a) 本轮只在管理台标注口径与裁决结论，ChatBI 标注记 BACKLOG；b) 本轮同步改 chatbi 前台（答案卡片加口径角标）——动 chatbi 超 A5 非目标边界；c) 发布期随「口径包 v0.4」一起做。
默认建议：**a**——遵守本轮非目标边界；用 UX-3 把 chatbi 标注显式排进发布期，避免静默丢失。

**UX-4 「影响谁」的装配深度**
背景：三问之③「确认后影响谁」——MVP 能从现成 lineage/ratio 装配到「受影响度量+表」粒度，但「影响哪几类 ChatBI 问法」需要问题-口径映射登记，属新数据资产。
选项：a) MVP 装配到度量+表粒度（现成数据零新增）；b) 同时建「ChatBI 问法→口径」映射表（+1~2 天，且映射需人工维护）；c) 度量粒度+问题级只对 R8 一个试点。
默认建议：**a**，问题级映射记 BACKLOG——度量粒度已够王工判断「这影响哪个数」，问题级映射的价值密度等真实使用反馈再投。

**UX-5 清爽化判据的执行强度**
背景：QC-1..10 中 5 条需 vitest 才能机器验收，而 vitest+eslint 引入 = 门槛稿 NC-Q4 仍 OPEN（默认批准未落章）；不补脚手架则 QC 条款退化为纯人工巡检，清爽化验收回到「看感觉」。
选项：a) 批准 NC-Q4，QC-1/2/3/4/6 进 vitest 硬断言、其余人工巡检；b) 不引测试，QC 全部人工巡检（省 0.5 天脚手架）；c) 加码引入 Playwright 做视觉回归（+1 天，收益存疑）。
默认建议：**a**——判据的价值就在机器可验，不批脚手架等于本轮清爽化没有验收线；Playwright 留发布期。
