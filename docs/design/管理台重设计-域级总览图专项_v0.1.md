## 0. 执行摘要

1. **封装主轴=业务域**（业务问题视角），存储层（ODS/CDM/DIM/ADS）降为域内图的分列副轴，本体域 MVP 与业务域同键不单设——三概念取舍见 §1.1。
2. **表→域=登记制元数据**：DOMAINS + TABLE_DOMAINS 声明块进语义层注册表（git 治理、禁止从表名猜），payload 由后端装配（§1.2）。基于现有 30 张表给出 **7 个初始域**的具体分域提案（§1.3）。
3. **域图布局裁决：自写「确定性力导向+碰撞约束」**——复用现有 forceLayout.ts 加固定种子+碰撞分离，不引新库（§2.1）；域间 N 条表级边聚合为 1 条边+权重角标，边样式三级编码（已确认/含待确认/含未裁分歧）（§2.2）。
4. **三层下钻**：域图（≈7 节点）→ 域内图（表级、按层分列、≤30）→ 表详情/邻域血缘（1-2 跳）；每层硬上限，万表压力被域封装逐层吸收（§3、§4）。
5. **首屏 QC-1 兼容**：横条（有待办才出现）+ 画布 + 图例/健康度行 = ≤3 区块；健康度并入图例行不再占卡片（§4.3）。
6. 万表演进三档触发器（域数 >12 → 二级域分组；>30 → 主题页签+搜索聚焦）见 §6；开放问题 DX-1..3 见 §7。

## 1. 域封装模型

### 1.1 三个概念的定义与取舍

| 概念 | 定义 | 视角回答的问题 | 本篇取舍 |
|---|---|---|---|
| **存储层** | 数据加工阶段：ODS 贴源 / CDM 明细与维表 / ADS 应用汇总 / DIM 外部维表——表级天然属性，lineage.py 已实现 classify | 「这张表在加工链路的哪一段」 | **副轴**：只用于域内图分列，不上域图 |
| **业务域** | 业务问题视角的表分组（注册/实名/授权/渠道…），一表唯一主域 | 「我的生意分几块、块之间怎么供数」 | **MVP 主封装轴**：域图节点 |
| **本体域** | 语义层对象（度量/维度/规则）的域归属容器 | 「这些数字属于哪块业务」 | **MVP 与业务域同键，不单独建实体**：度量卡/规则卡按 TABLE_DOMAINS 反查所属域即可；发布期若出现真跨域对象再拆 |

**为什么业务域做主轴**：①域图的用户是老板/数仓同学，头脑里的地图是「业务分几块」不是「加工分几段」——存储层已有现成分类且横平竖直，做主轴等于把工程结构又晒了一遍（正是 Jack 看不懂的那种「专业」）；②万表场景下存储层只有 4 个值，封装度不够（一层 ODS 就可能几千张），业务域才是可伸缩的分治单元；③本体域与业务域同键对齐后，数字目录卡（v0.1 §3）自动获得域归属，两套界面共享一张业务地图，不养第二套口径。

**正交关系**：域 × 层是矩阵不是二选一——一个域横跨 ODS/CDM/ADS（如注册域既有贴源又有汇总）；域内图按层分列展示这张矩阵的切片。

### 1.2 表→域元数据：登记制，进 git

- **落哪**：语义层包内新增声明（`DOMAINS`：域 key→人话名+一句话简介；`TABLE_DOMAINS`：表 id→域 key），与 MEASURES/RULES 同库同风格（Pydantic + 显式注册表）。放语义层而非前端硬编码：装配进 /api/lineage 与 /api/ontology payload，域图、数字目录、规则卡共用一份真相。
- **怎么进 git**：改声明=普通 commit（ADR-0011 红线天然覆盖——变更历史页自动留痕「谁在哪个版本把某表划入某域」）。**MVP 不给域映射设 unverified/confirmed 生命周期**：它是对现状的描述不是待验证的口径判断，套确认流程属过度治理（DX-1 可改）。
- **不许从表名猜**：前端/装配层一律读 TABLE_DOMAINS；未登记表在域图上落入「未分域」暂存区并计数提示，不许静默用前缀兜底。
- **改动面提示**：registry.py 增声明块 = 改本体 schema（⚠ 先问档，与门槛稿 §5-Q3 同模式），列 DX-1 请老板批准。

## 2. 域图布局与边聚合

### 2.1 布局算法选型（节点 ≈5-10 域）

**裁决：自写「确定性力导向 + 碰撞约束」，复用 ontology-admin/src/forceLayout.ts，只加三件事**：
1. **固定随机种子**：以「域 key 集合+边集合」的哈希为种子 → 同一图结构必得同一布局，数据刷新/确认状态变化不引起坐标跳动（待办徽章变了图不重排）；
2. **碰撞分离 pass**：迭代推开节点至包围盒间距 ≥8px（QC-5 从「期望」变「构造保证」，布局函数纯函数可单测，v0.1 QC-5 验收挂这里）；
3. **结果缓存**：图结构不变不重算；结构变化（新域/新边）才重排并整屏过渡动画。

为什么不是另外三个：
- **手工固定坐标**：≤10 域时最稳，但域是登记出来的不是画出来的——每加一个域要手调一次坐标，登记制的好处（加域零布局成本）就没了；留作 §6 二级域分组组件的内部实现。
- **分层布局**：域与存储层正交，域图强行分层等于把两根轴拧成一根，误导读者；分层属于域内图（副轴的主场）。
- **引入 dagre/elk 等布局库**：新依赖=先问档，且 ≤10 节点的力导自写已在仓内验证过（GraphHome 现用），引库收益不成比例，ADR-0012 不引新图库不破。

### 2.2 域间边聚合规则

- **聚合**：按（源域, 目标域）分组表级血缘边，N 条 → 1 条聚合边 + 权重角标「×N」（N=表级链路数）；同域内部的表级边**不上域图**，折进节点的表数里（自环会让域图秒变毛线团）。
- **边样式三级编码**（把 v0.1 的红虚线一分为二，红留给最严重档）：

| 档 | 样式 | 判定 |
|---|---|---|
| 已钉死 | 灰实线，宽随权重 1→3px 渐增 | 链路上全部口径规则 confirmed |
| 含待确认 | 橙虚线+动画 | 链路上存在 unverified 规则 |
| 含未裁分歧 | 红虚线+动画（最粗） | 链路上存在未裁决分歧规则（R8 类） |

- **节点编码**：大节点=域卡（人话名+表数）；**红徽章=域内待确认口径数**（待办长在地图上，点徽章直达该域待办预筛队列——默认建议，DX-3 可改）；**⚡角标=域内含未裁分歧**；hover 节点=高亮其全部聚合边、其余降透明度。
- 装配提醒：权重、待确认数、分歧标记全部由后端从 TABLE_DOMAINS+lineage+rules 现算进 payload，前端不写死。

## 3. 域内图（第二层）

沿用 v0.1 §4.2 局部血缘规格的分层左→右、点击抽屉、图例固定、空态出路，**只列差异**：

| 项 | 与 v0.1 §4.2 的差异 |
|---|---|
| 入口 | 从域图节点下钻（非直接从表/规则进）；面包屑「全域图 / 注册域」 |
| 分列 | ODS｜CDM+DIM｜ADS 三列不变；列头带该层表数，配层筛选 chips（勾掉一层即整列收起，重新计数） |
| 跨域链路 | 域内图只画域内表级边；跨域边在底部一行摘要「⌁ 来自其他域：渠道域→2 条 · 公共维表域→1 条」+「查看跨域链路」收起折叠，默认不画（防跨域边把画布又挤成一坨） |
| 节点上限 | ≤30 张（QC-6 同源，域级单列独立计数）；域内表多时的截断/筛选策略见下 |
| 节点内容 | 表节点显示人话名+层色条；⚠/⚡ 状态角标沿用 |

**域内表数 >30 的截断/筛选策略**（硬上限不破）：
1. 先弹层筛选（Search 输表名关键词 + 层 chips）——筛选后 ≤30 才渲染；
2. 不筛选则按（层序，表名字典序）取前 30，画布角落常驻提示「已截断：显示 30/42 张，用搜索或层筛选缩小范围」；
3. 提示附出路「按二级域查看」（§6 第三档触发后可用）；
4. 截断是 UI 行为不是数据行为：payload 不截，前端视图截（后端契约不动）。

## 4. 下钻与返回交互

### 4.1 三层下钻路径

~~~
全域图(域节点≈7)      --单击抽屉[进入域内图]/双击直下钻-->   域内图(表≤30,按层分列)
   ↑面包屑「全域图」                                       --点表--> 表详情 / 邻域血缘(1-2跳,≤30)
                                                              ↑面包屑「全域图 / 注册域 / 表名」
返回：面包屑逐级回退 / Esc 关抽屉 / 抽屉内「以此为中心重看」换中心不换层
~~~

- **单击域节点**=右侧 Drawer 预览（不打断总览）：域人话名+简介、层分布条、待办前 3 条（各带直达确认页锚点）、主按钮「进入域内图 →」。
- **hover**：节点/边高亮自身链路、其余降透明度——先看清关系再决定点谁。
- **顶栏搜索**：AutoComplete 搜域/表 → 直接跳到对应层并聚焦该节点（万表时代的主路径，§6）。
- **空态**：域无登记表 → Empty「该域暂无登记表（域=登记出来的）」+提示去 registry 登记；搜索无结果 → Empty+「清空筛选」；未分域表>0 → 域图角落计数徽章「未分域 N 张」点开列表（防登记欠账静默堆积）。

### 4.2 与待办横条、健康度的版式关系（QC-1 兼容）

首屏三区块，恰好压线：

~~~
区块①  Alert 横条：N 条口径待确认 · 其中 R8 含未裁分歧      [去确认 →]   ← pending=0 时整条隐藏
区块②  画布（域图主体）：右上浮层 [🔍 搜域/表] [整理布局]；左下图例并入区块③
区块③  图例+健康度一行：▢=业务域(表数) · 边×N=表级链路 · ⚠=待确认 · ⚡=未裁分歧 · 红虚线=分歧链路
        ｜健康度：27/30 表口径已钉死 · 3 条待确认 · 1 处分歧未裁
~~~

健康度从「统计卡阵」降级为图例行内数字（辅助定位，不与地图抢注意力）；横条保留待办入口职能（ADR-0012 横条对冲设计意图不变）。v0.1 判据联动：QC-1=3 区块 ✅、QC-6=每层上限 ✅、QC-5=碰撞约束 ✅。

## 6. 万表演进路径（域数 10 → 30+）

| 档 | 触发器（登记成判据，非感觉） | 动作 |
|---|---|---|
| 一：聚焦搜索 | 默认启用 | 顶栏搜索域/表直达+聚焦模式（选中域居中全亮、邻接半亮、其余透明度 0.15）——图不变小，注意力变小 |
| 二：二级域分组 | 域数 >12 或画布节点 >15 | 相近域聚成「域组超节点」（如 用户生命周期组=注册+实名+授权），组内展开/收起；组布局复用 §2.1 同一套确定性力导 |
| 三：主题页签 | 域数 >30 或单域表数 >30 | 域图按业务主题分页签（获客/交易/服务…）；单域超 30 表强制拆二级域登记；搜索聚焦成为第一入口，全图变「地图册」而非「一张图」 |

- **性能底座**：域图节点=域数（几十封顶），SVG 渲染无压力（v0.1 §3 选型结论不变）；表级视图三层硬上限吸收万表压力——**表可以无限加，图的复杂度只随域数走**，这正是「封装后逐个打开」的机制化表达。
- **不做的事**：不做万表平铺（回到一坨）、不做服务端图计算/图数据库（当前边数装配 JSON 足够，规模到「域间边>500」再议，属发布期）。

## 7. 开放问题（DX-1..DX-3，请老板裁决）

**DX-1 域映射元数据的落点与治理强度**
背景：TABLE_DOMAINS 放语义层 registry = 改本体 schema（⚠ 先问档，同门槛稿 Q3 模式），且要不要给它配确认生命周期未定。
选项：a) registry.py 增 DOMAINS/TABLE_DOMAINS 声明块，git commit 留痕、**不设**确认生命周期（本篇默认）；b) 独立 domains.json 放数据目录（语义层 schema 不动，但真相源分家）；c) 映射也走 unverified/confirmed 生命周期（治理最重）。
默认建议：**a**——单一事实来源优先，映射是对现状的登记不是待验口径，生命周期属过度治理；需要 Jack 批准动 schema。

**DX-2 跨域表的主域归属**
背景：转化链主表 ads_chnl_rgst_to_real_auth_dau_df 一张表回答注册→实名→授权三域的漏斗问题，域图要求一表一主域，归属不同域图长相不同。
选项：a) 一表唯一主域，跨域性由聚合边自然表达（本篇默认，转化链主域=注册域）；b) 允许一表多域（节点在多个域内重复出现，图变重、计数会重复）；c) 单设「转化漏斗域」（1 张表一个域，域粒度碎片化）。
默认建议：**a**——唯一主域保持图论简单，漏斗的跨域故事由 D1→D2→D3 聚合边讲，反而更清楚。

**DX-3 域图节点拖拽与坐标持久化**
背景：Jack 原话批评过「卡片不能拖动」——域图要不要允许拖拽与他这句直接相关，但拖拽与「确定性布局、无重叠」判据有张力。
选项：a) 禁拖拽，只保留「整理布局」一键重排；b) 允许拖拽微调，坐标存浏览器 localStorage（视图偏好不进 git、不进元数据），配「整理布局」一键重置；c) 拖拽坐标落盘进 git（与 DX-1 登记制冲突，视图偏好污染真相源）。
默认建议：**b**——直接回应 Jack 的拖拽诉求且成本极低（React Flow 原生）；拖歪了有重置兜底，QC-5 由重置保障。
