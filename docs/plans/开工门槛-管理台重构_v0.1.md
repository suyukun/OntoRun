### A3 验收标准（EARS，每条挂在用户故事下，附测试名构想）
- [US1] WHEN 数仓同学打开确认页 THEN 界面 SHALL 按"未确认在前"列出全部规则并显示待确认总数（test: rules_page_sort_and_count）。
- [US1] WHEN 确认人未填名 THEN 系统 SHALL 禁用确认按钮并提示"身份是确认的一部分"（前端已有，补 vitest 断言；test: confirm_requires_name）。
- [US1] WHEN 确认成功 THEN 系统 SHALL 返回含 confirmer/时间/commit 短码的记录且队列计数减一（test: confirm_flow_commit_trail）。
- [US2] WHEN 打开 R8 规则卡 THEN 界面 SHALL 展示双口径对照（595/552/55 与适用场景）而非二值是非题（test: r8_divergence_card）。
- [US2] WHEN 数仓同学对 R8 做出裁决 THEN 系统 SHALL 把裁决写进规则记录并产生带身份的 git commit，且 lineage 高亮消解（test: r8_verdict_commit_and_highlight）。
- [US3] WHEN 点击出处锚点 THEN 系统 SHALL 展开脚本片段，默认折叠只显示"文件+行段"摘要（test: source_snippet_expand）。
- [US3] WHEN 打开对象详情"变更历史"Tab THEN 界面 SHALL 只显示与该对象相关规则的确认/驳回记录（test: object_scoped_history）。
完成标志：每条能想出对应测试名（如上）。

### A4 边界条件（每条有明确答案，不是"再说"）
1. **确认人为空**：前端禁用+后端 min_length=1 双拦（均已实现，保持）。
2. **git 不可用**：降级 json 模式（已实现）——但"确认冻结版本"承诺（原则⑦）随之失效，UI 必须明示"未产生 commit（降级记录）"且该状态在历史页可见，不许静默。现有 message 已分支，补历史页降级标记。
3. **并发/重复确认同一规则**：status 后写覆盖，confirmations.json append-only 双记录均在、最新覆盖 last_record——数据不丢，UI 显示最新记录即可（接受，写进 spec）。
4. **registry.py 规则块被手改导致文本替换失配**：confirm_store 抛 ValueError → 返回结构化 422，不产生半提交（替换成功才写文件，现有顺序正确）；前端展示错误卡不白屏。
5. **对象详情接口 404**：现有 Alert+返回列表按钮，保持。
6. **R8 类"双合法"规则进入队列**：是非题模型失效——系统 SHALL 以分歧卡承接（US2），不允许把它当普通是非题硬确认。

### A5 非目标（本轮不做，出现即退回）
- 不改语义层 src/fortune_semantic/ 的 compiler/query（编译与查询链路不动）。

- 不做登录/权限矩阵/双负责人（保持 MVP 全员+手输名字，接口预留不变）。
- 不做本体 schema 编辑器（管理台只读注册表+状态/裁决翻转，不提供 Pydantic 编辑）。
- 不做批量导入、通知中心、多级权限页（UX 概念设计已裁剪项）。

### B2 关键决策（≤5 条，每条含"为什么不是另一个"）
1. **增量改而非推翻重做** [假设，待 §5-Q1 拍板]：现壳即 UX 概念设计的实现（七成覆盖），推翻损失 ~2600 行已验证代码且后端装配层与 IA 无关；备选"推翻信息架构重做"在 Jack 澄清不满的具体对象前不评估。
2. **R8 用分歧卡（对照+裁决）而非塞进是非题**：二值模型装不下双合法裁决，硬塞=表面工程复发；备选"仍用对/错两键+描述里写清"被否——数仓同学无法从一段文字里可靠地区分"确认事实"与"选择口径"。
3. **裁决数据模型走 CaliberRule 增补可选字段（decision/alternatives）**：状态机仍是 unverified/confirmed 两态，裁决是确认的附带结论而非新状态，改动最小；备选"新增 adjudicated 第三状态"被否——生命周期翻倍、图谱高亮与汇总逻辑全部联动，违反最小实现。
4. **确认人身份维持手输名字输入**：MVP 全员可确认已拍板（ADR-0012），登录/账号属非目标；备选"接 git config 身份"被否——数仓同学机器上未必配 git 身份，且界面身份应显式可见。
5. **测试脚手架前置**：ontology-admin 从零补 vitest（最小配置），后端只补确认写路径与装配增量测试；备选"不补测试靠手点"被否——确认写路径直接改源码文件+commit，无测试的回归风险不可接受（两档测试制度下属核心不变量邻接）。

### B3 接口/数据契约（契约先定，实现后动）
- 现有 5 端点形状全部向后兼容：新增字段一律 optional。
- 规则 payload 增补（草案，Pydantic 落形后才开工）：`divergence?: { options: [{key, label, value_evidence, applies_to}], recommendation?: string }`（仅 R8 类规则携带）；`decision?: { option_key, decided_by, time, commit }`。

- 前端类型继续手写镜像（api.ts），openapi-typescript 生成留发布期（阶段二 shared 包）。

### B4 宪法门禁检查（对照 AGENTS.md 三铁律+边界）
