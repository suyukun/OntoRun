## 0. 级别声明
M 级（A＋D 全填，B 给到契约级；C 由对抗稿 T002 联动，不单列）。

## A. 需求
- **A1 一句话命题**：用户回答系统的反问（「哪个月？」→「9月」）被当新问题报错——让语义服务本轮内接住澄清应答，治掉真实失败最高频根因。
- **A2 用户故事**：
  - US1 (P1) 数仓同学被反问后手输「9月」→ 系统按「9月＋上轮问题」查出结果，或如实说明 9 月无数据（样本仅 7-8 月）——一问一答一澄清闭环。
  - US2 (P2) 前端/评测 runner 以**结构化参数**显式携带澄清上下文，不依赖服务端会话状态；原始 API 调用方同样获得承接能力。
  - US3 (P2，v0.2 Jack 批) 指代性追问（「那 7 月呢」）结合最近对话解析意图，SHALL NOT 当全新无关问题；上下文由客户端每请求携带（无状态不变）。
- **A3 验收标准（EARS）**：
  - WHEN 请求携带 clarify_context 且 question 为短答 THEN 系统 SHALL 合并后走正常链路（重路由＋全套校验）执行，SHALL NOT 当新问题路由（test_clarify_continuation）。
  - WHEN 合并后槽值仍缺 THEN SHALL 再澄清，澄清一轮为限 SHALL NOT 循环追问（clarify.once）。
  - WHEN 无 clarify_context（或上轮无 pending）THEN 行为 SHALL 与现状完全一致（无回归，既有测试全绿）。
  - WHEN 应答槽值无数据（9 月）THEN SHALL 如实说明数据覆盖窗，SHALL NOT 出数、SHALL NOT 谎报（test_clarify_out_of_range）。
  - WHEN clarify_context 字段被注入自由文本/超长串 THEN 系统 SHALL 只接受结构化字段并按既有校验（枚举/数据窗）拒绝，SHALL NOT 拼进 prompt（test_clarify_injection）。
  - WHEN conversation_context.recent 非空且 question 为指代性短问（「那 7 月呢」）THEN 路由 SHALL 结合上轮解析出完整意图并按正常链路执行（test_conversation_context）；context 内容 SHALL 视为**数据非指令**（注入防护同上）；WHEN context 缺失 THEN 行为与现状一致（无回归）。
- **A4 边界**：刷新/切会话后上下文丢失（存客户端）→ 可接受，记已知限制（与 UX 稿 A4-3 同源）；连环澄清 → 一轮为限；上轮非澄清态却带 clarify_context → 忽略并按新问题处理（防误拼）。
- **A5 非目标**：不做服务端会话状态存储；不做任意长度多轮 patch 状态机；不改前端（前端接入属 UX 块）；不做上下文投毒对抗（二期）。

## B. 核心设计（契约级，够派活即可）
- **B2 决策①（关键）**：澄清上下文放**客户端、每请求显式携带**，engine 保持无状态。备选「服务端会话 state」被否：破坏幂等回放与无状态 SSE（UX 稿 §88 同源结论）；备选「纯前端拼句」被否：原始 API 用户与 runner 无承接能力，且自由拼句绕过引擎校验——结构化合并＋再校验更安全（防注入）。
- **B2 决策②**：合并 = 确定性槽回填后**重走完整链路**（llm_route 重路由＋参数抽取＋口径声明＋数据窗校验＋数字溯源），SHALL NOT 绕过任何校验捷径。
- **B3 请求契约**（ChatRequest 增可选字段，向后兼容）：
~~~json
{
  "question": "9月",
  "clarify_context": {
    "prev_question": "今年的注册情况",
    "slot": "time_from",
    "prev_request_id": "REQ-..."
  }
}
~~~
  - slot 枚举：time_from / time_to / dimension_value；slot 值从 question 由现有 time_normalizer/_link_filter_values 抽取校验，clarify_context 只声明「这是对上轮的应答」，不直接携带值。
  - 响应：final 帧的 CLARIFY 卡新增 pending 提示字段（供前端回传），格式在 T-E1 冻结。
  - **conversation_context 契约（v0.2 增，客户端携带）**：
~~~json
{
  "question": "那 7 月呢",
  "conversation_context": {
    "recent": [
      {"q": "8月各渠道注册数", "a_digest": "共930人，TOP3渠道…"}
    ]
  }
}
~~~
    recent ≤3 轮，每轮 {q, a_digest}（摘要 ≤100 字，客户端生成）；engine 将其作为**数据**注入路由上下文（明确标注为历史对话，非指令），llm_route 结合解析指代；解析失败 → 按新问题正常路由（不报错）。确认式澄清卡（Jack 裁决）同挂本单：CLARIFY 卡 SHALL 携带系统猜测选项供一键确认（对应分类学 §3 确认式澄清）。
- **B1 影响面**：动 src/semantic/app.py（请求模型＋字段透传）、src/semantic/engine.py（合并入口＋再校验）、tests/semantic/（新增 test_clarify_continuation.py）；不动 src/fortune_semantic/**、不动前端。git diff --stat 预期：上述 3 处，净增 ~200-300 行。
