# S4 演示设计平衡评估（评审模型：doubao-seed-2.1-turbo，火山 Coding Plan）

> 评审日期 2026-08-27 ｜ 输入包 docs/s4-review/input-pack.md ｜ web_search 次数：0（监管事实已条款级锚定）

## 三条最强支持
1. "单看没事、合起来出事"揭示帧精准踩中金控风管部核心价值主张（穿透/并表/归集是金控层存在的理由），处长第一秒能共情"这就是我们每天在干的活"。
2. 监管口径条款级锚定+双层口径分离，专业密度扛得住内行审视——内行第一个本能是挑口径错，挑不出来就会默认你懂行。专业信任是价值感知的地基。
3. "人拦 AI"双签高光回应风控人对 AI 的核心焦虑（谁担责），是治理 show 而非技术 show——"这个东西是给我用的，不是来替代我的"。

## 三条最强反对
- **反对 1（P0）**：R1a 规则"≥10% 橙色"与剧本第 1 步"10.8% = 黄色预警"直接矛盾，数字对不上专业可信度瞬间崩塌；且三级预警主规则只有两级触发，黄色悬空。改法 A（推荐）：R1a 三档化"≥9% 黄 / ≥10% 橙 / >12% 红"，第 1 步橙色、第 2 步红色，递进感更强。
- **反对 2（P1）**：第 2-5 步本质是"规则引擎+工作流"，把"AI 提议"换成"系统自动触发"业务结果一样——看不出智能体不可替代性。改法：第 2 步明示恒昌贸易这条关联线**不在传统关联/股权表里**，是 AI 从弱信号（共同联系人/交叉担保/资金往来异常/公开信息共同实控人）交叉验证推理出来的。
- **反对 3（P1）**："押品评估价上调 30%"太假——上调押品价有明显合规程序、且处长反应会是"AI 连基本合规常识都没有"，本想展示治理、结果暴露低能。改法：换成"看起来合理但有争议"的提议（如表内贷款调整为符合净额结算条件的衍生品交易以降低风险暴露），驳回理由="净额结算认定条件不满足"。

## 不确定/需更多信息
1. 前端 UI 质感——处长判断"像不像真系统"70% 看 UI 细节（表格密度/字段命名/按钮位置/配色），AI 生成廉价感界面专业度归零。
2. Agent 是预设脚本还是实时对话？剧本外问题（"天晟在前十大客户排第几？"）答不上来智能体人设崩，需兜底策略。
3. 证据链展开颗粒度：只有表名+规则名是壳，要能看到原始数据行+计算过程，业务专家会钻到底。
4. 隐性关联识别是规则驱动（表里已有）还是 AI 推理？决定第 2 步含金量。

## 跨项检查（数字验算与矛盾表）
- 数字全部验算通过（86.4/800=10.8%；+16=102.4/800=12.8%；48/600=8.0%）。
- 矛盾：①R1a vs 剧本第 1 步级别矛盾（P0）②黄色悬空无阈值（P1）③"安平银行内部限额 10%"未在 R1b 定义（P2）④第 3 步金控督办与处置权属边界演示中未区分（P2）。
- 逻辑流：黄→红跳级缺橙色过渡，系 P0 连锁。

## 过度设计/遗漏/玩具风险
- 过度：21 个退链对象对 5 分钟演示价值为零；R3-R6 六条规则列出不增加价值，不如声明"今天只演集中度主线，其余已注册"。
- 遗漏：①监管报送视角（1104/大额风险暴露报送/关联交易报送）是处长最头疼的事，建议第 5 步加"自动生成合规监管报告初稿"钩子 ②组合管理视角（前十大集中度/行业分布/迁徙趋势）结尾 10 秒仪表盘闪回 ③跨部门协同阻力未体现。
- 玩具风险：数据规模偏小（不主动提数字即可）；"AI 起草上调建议"表述太弱，关键在调级因果链讲具体。
