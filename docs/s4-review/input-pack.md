# 复核输入包：OntoRun S4「金控风险预警演示」设计（事实陈述，非金科玉律）

## A 栏（客观机制事实）

1. 项目：OntoRun，研究"大模型如何嵌入真实业务系统"，聚焦语义接口层（Palantir Ontology 为国际标杆）。已完成并冻结 tag v0.3.0：S1 零售供应链语义闭环（LLM 经本体执行动作真实写回源库+全程审计，三问测试通过）、S2 生产化（ChatBI head-to-head：受限结构化查询 60% 首超 NL2SQL）、S3 金控风险演示版（33 对象/37 链接/9 动作走状态机发布进图谱，698 测试通过）。
2. 技术底座（全部已可跑）：自研本体运行时（对象/链接/动作注册、规则校验引擎、审计写回，SQLite 源库）+ FastAPI + React。LLM provider 热插拔（火山 DeepSeek）。
3. 终极验收（用户原话级标准）：给中信金控风险管理部处长（懂风险业务、不懂 AI）演示。通过 = 他 5 分钟内感受到价值、觉得专业、看得出智能体优势。反面 = 像玩具 / 看不出比 Excel 强在哪 / 术语让他皱眉。
4. 演示业务口径（已按四部法规原文条款级锚定：2003 集团客户授信指引、2018 大额风险暴露办法、2020 金控办法、2023 金控关联交易办法）：
   - 场景：金控集团风险管理部穿透监测集团客户授信集中度。双层口径：银行层各附属机构自算监管红线 15%（2003 指引第十二条 2010 修订）；集团层 = 并表归集余额/集团并表资本，内部限额 12%、预警线 10%（金控办法第三十二/三十三条要求自设，监管不规定数值）。
   - 分级：黄/橙/红三级中文枚举（内部口径，参照苏州银行红/橙/黄一手披露）；生命周期：生成→确认→处置→解除/撤销/排除（武汉金控募集说明书披露口径）；处置动作五类（额度管控/排查核查/担保缓释/结构调整/退出）。
   - 预警规则：R1a 集团层归集集中度（主）、R1b 银行层对照、R2 隐性关联纳入重算、R3 单一客户对照、R4 关联交易合规预警（独立维度）、R5 担保集中度、R6 行为类（欠息/逃废债等，锚指引第二十五条）。
   - 演示剧本 6 步：①揭示帧：天晟集团在安平银行(8.0%)/证券/资管各融一笔，单看都安全 → 联合授信台账归集 10.8% ≥ 预警线 10% → 黄灯，观众亲眼看"单看没事、合起来出事" ②联合授信识别隐性一致行动人恒昌贸易 → 归集 12.8% > 内部限额 12% → AI 起草上调红色、人工确认生效 ③处置：冻结额度+追加押品，金控督办 ④双签高光：AI 提议"押品评估价上调 30% 以达标"，审批人当场驳回（人拦 AI） ⑤监管动作：红色触发立即报告监管+银团分散计划（2018 办法第三十七条） ⑥黄色小案例走完整解除关闭 + 全程 audit 回放、每个答案可点开证据链（哪张表/哪条规则/哪个分母）。
   - 数字设定（可验算）：集团并表资本 800 亿、安平银行资本净额 600 亿/一级资本净额 480 亿；天晟归集 86.4 亿→10.8%，加隐性关联 16 亿→102.4 亿→12.8%。
5. S4 计划：M0 方向重锚文档 → M1 数据按口径再生（中文枚举、数字可验算、剧本数据即道具）→ M2 规则注册进校验引擎 → M3 Agent 对话唯一入口+证据链交互+双签驳回 UI → M4 多模型扮演内行领导彩排 → M5 真演示。
6. 既定边界：研究对象是语义接口层方法论（非做商业产品）；传输/操作层用现成方案不造轮子；33 对象不删、12 进门面；受众双重（GitHub 同行架构师 learn-in-public + 处长演示）；真实业务背景：用户所在集团确有风险管理部及其风险系统（表结构源自真实系统 211 表字典脱敏，数据为模拟）。
