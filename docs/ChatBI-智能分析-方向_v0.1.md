# ChatBI / 智能分析：方向规划（待系统讨论，不现在做）

> 来源：Jack 试用反馈（2026-08-20）。**当前不实现**，仅记账，等 S1 收口后系统规划。

## 问题（Jack 原话要点）
- 本体建立之后，如何**系统地实现 ChatBI 或智能分析**，是核心价值方向。
- 真实企业数据量级 = 几百 TB ~ PB 级，**不可能靠"LLM 轮询 50 条数据"来支撑 BI 分析**（当前 search_objects 工具 page_size≤50、无排序/聚合/翻页，LLM 靠轮询补齐数据在真实规模下不可行）。
- "名字最长客户"这类聚合问题暴露的能力边界，本质不是"加个查询参数"，而是**智能分析的能力形态**问题。

## 已确认的边界（Jack 拍板）
1. 本项目当前查询工具是"等值过滤+分页"（search_objects），LLM 解题上限 = 工具能力上限；
2. 真实生产级智能分析不能靠 LLM 全量拉数/轮询——**数据不出本地、按需取数**的架构原则不因分析需求改变；
3. 智能分析如何落地（预计算聚合/物化视图/语义层查询/LLM 出 SQL 或 MDX 等）**待系统规划**，不在这轮 MVP 改动里碰。

## 待系统规划时讨论的候选方向（仅记录，不立项）
- 分析型语义层：本体对象 → 可聚合指标/维度模型（星型/语义层）；
- LLM 生成结构化分析查询（而非逐条拉取），本地引擎执行；
- 预聚合/物化：PB 级下响应与成本的正确形态；
- 与"三问测试/写回回路"的关系：分析只读，动作写回，统一在语义接口层治理。
