## 5. 关键设计决策（修反模式 + 借鉴参考项目）

1. **Object Type / Link Type 为一等公民**：独立 schema 定义（Pydantic + 注册表，沿用现有风格），不散落成字符串（修反模式#2）
2. **单一数据模型**：不做 v1/v2 双表双身份，实体/实例/概念用字段区分而非两套表（修反模式#3）
3. **领域驱动建模**：先理解业务建模，再映射数据；禁止源列 1:1 Kitchen Sink（修反模式#1）；实体三分类（业务/过程/结果，参考 B站笔记 EP07）
4. **动作引擎直接复用 OntoRun runtime**：提交条件 + 规则前置校验 + before/after 快照审计 + 写回源系统（我们的差异化核心，三问测试延续）
5. **LLM 输出七道校验**：结构/必填/引用完整性/去重/类型白名单/语法/语义引用（借鉴 PostHarnessValidator 思路，原创实现）
6. **优雅降级**：SQLite-first，Neo4j/Chroma/MinIO/Redis 全可选、缺失回退——本地零依赖可跑
7. **草稿→审核→发布状态机**：对象类型/动作/逻辑上线前走审（借鉴参考项目 + Palantir 治理层）
8. **审计升级**：现有审计（SQL+影响行数）补 before/after 快照，对齐 Palantir function_runs 形态
