# S3 v0.2 独立复核报告 — kimi-k2.7（第2轮）
> 视角：金融科技/风管领域架构师，独立 red-team。

## 三条最强支持
1. 延续"本体优先+受限结构化查询"是 S2 自然延伸，对风管部领导"精准答对+域外拒答"比"大而全但胡编"有价值。
2. 读/写引擎分离是金融风控正确架构——把 LLM 从"数据修改者"降级为"提议者"，唯一能满足审计/回滚/双签要求。
3. DES"企业模拟"四资产是战略性升级——解决"模拟数据像玩具"根因，沉淀可复用能力。

## 三条最强反对
- 【P0 反对1】55 表/35 对象/11 动作与"5 分钟看懂价值"严重不匹配：演示认知带宽有限，30 个对象概念超载。改：划定"演示脊柱"8-12 核心对象 + 3-4 核心动作（信号确认→升红→处置提交→审批→销号），先跑通华夏新能源故事，其余作可选项/深度层。
- 【P0/P1 反对2】DES 四资产与 M2 本体边界模糊，"表驱动本体"复发风险：DES 资产是虚构企业背景设定，本体是查询/执行契约，混用让本体过拟合生成数据。改：写 ADR 明确边界——DES 四资产是 M2 输入/参考和测试素材，不具约束力；本体独立定义再反向映射表；DES 规则只用于生成测试数据。
- 【P1 反对3】20-30 万行撑不起 55 表/35 对象，重现"像玩具"：S2 100 万行 18 表仍一半空，现 20-30 万÷55 表≈3600-5400 行/表。改三选一：表砍 25 张内 / 数据提 80-100 万 / 显式行分布（核心事实表 ≥5 万行，rows-per-object 作 Demo 健康指标）。

## 不确定
- 拒答机制实现方式（可表达集判定：白名单？NLU？查询规划失败即拒答？）；火山对中文金融字段契约生成成功率（M2 早期做 ≤5 对象 pilot）；"不像玩具"判定标准（谁评审 UI）；P95≤500ms 口径（明确是 exec 非端到端）；双签 UX 形态（弹窗/独立审批页/岗位链）。

## 跨项
- M1-M5 无硬循环；M1b DES 四资产未与 M2 定边界会软耦合。
- 30-35 对象 vs 20-30 万行不匹配，先 8-12 对象跑通或增数据。
- 11 动作全深与读/写分离不矛盾，但对 5 分钟 Demo 过度工程，分层：3-4 核心做深其余模板级浅实现。

## 过度设计/遗漏/违反原则
- 过度：55 表全量生成；11 动作全深；DES 四资产作强交付物（不绑定可执行测试会变"先写方法论"）。
- 遗漏：拒答判定机制；前端反玩具设计策略（有口号无设计系统/评审机制）；LLM 失败兜底 UX；行分布策略；演示失败恢复/预热脚本。
- 违反：第一版先跑通（首个可运行切片应"5 对象+2 动作+5 题"）；落地先行（DES 四资产若脱离可执行验证）；内容密度>文件数量（55 YAML+35 对象+11 动作模板有 scaffold 爆炸风险）。

## 结论
方向对（本体优先/读写分离/DES 企业模拟），但范围大到可能淹没 5 分钟 Demo 目标。立即三件事：写 ADR 定 DES 四资产与本体边界；Demo 脊柱砍到 8-12 对象/3-4 动作/25 表内，其余标"扩展层"；rows-per-object 和 LLM 契约生成成功率作阶段门禁。
