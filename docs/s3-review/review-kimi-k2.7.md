# OntoRun S3 设计独立复核报告 — kimi-k2.7
> 角色：金融科技/风险管理系统领域架构师，独立 red-team 视角

## 一、3 条最强支持
1. **S2 已验证核心机制，S3 是"换场景"而非"从零发明"**。语义接口+受限结构化查询+写回审计这条 spine 已立住。金融风控实体关系天然比零售更适合展示本体价值。
2. **金融风控与 Jack 背景高度咬合**（人保财险 9 年数仓负责人），避免"外行讲外行话"。风险预警业务痛点外行 5 分钟能听懂，内行 5 分钟能判断你真懂。
3. **"5 分钟看懂价值"的叙事聚焦，是对 S2 痛点的直接回应**。5 步剧本（Landing→数据→图谱→问答→动作→审计）是产品化的必要一步。

## 二、3 条最强反对
### 反对 1（P0）：S3 是"同时做三件大事"——范围爆炸
M1 升级 DES 标准化 + M2 建金融本体 + M3/M4 重做 Agent 与前端 = 领域切换+产品重构+UI 重写三合一。S2 胜利来自"窄而深"（8 对象/1 条流程/659 测试）。
**改**：① 把 S3 重新定义为"金融风控 demo 跑通"，DES 产品化降级为 S4 目标；② M1 只做"为安平金控生成 20~30 万行"的配置化脚本；③ 冻结 M2 对象集为 8~10 个核心对象。
### 反对 2（P0）：M1"表结构驱动 DES"与 M2"本体先行"方向矛盾
项目核心论点是先有语义层再有源系统表承载。若 DES 先按 SQL DDL 生成表，M2 会被已有字段绑架，本体退化为"表的注释层"。S2 成功恰因 DES 按业务对象生成数据再物化到表。
**改**：① 先定义安平金控语义层（对象/链接/动作/指标），再由本体派生所需源表；② 数据字典 211 表只作为输入参考和脱敏来源；③ 记录 ADR「S3 本体优先，表结构仅用于字段语义对齐与脱敏映射」。
### 反对 3（P1）："真实业务动作"在模拟数据 demo 里是 credibility trap
金融真实审批涉及合规/法务/董事会授权/监管报备，demo 不可能也没有权利"真的完成"。
**改**：动作严格分层——只读查询（80% 演示）/低风险分析动作（调整预警等级、添加审核批注、生成处置建议书，可真写回）/高风险动作（改称"发起审批流/创建审批工单"，只写回"待审批状态"+审计，不声称完成审批）。UI 标注"模拟环境/非真实业务决策"。

## 三、不确定
1. 数据字典 211 表未在 git 中，无法复核"55 张核心表"怎么筛出来的。单一事实来源缺口。
2. 演示受众未明确（互联网架构师 workshop/金控风管部领导/潜在甲方客户？）决定 UI 深度与 demo 台词。
3. "真实业务动作"的法律/合规边界是否需免责声明。
4. DES 标准化验收标准是"能配出安平金控"还是"能配任意行业"（差 5-10 倍工作量）。
5. 火山 Coding Plan token 配额是否够 S3 规模（比 S2 大一个数量级）。
6. 旧 AI 助手页是否直接删除（regression 基准丢失？）。

## 四、跨项检查
- M1-M5 依赖方向正确，但需"严格串行"改"迭代并行"：M2 不依赖 M1 全部，M3 不依赖 M2 全部，M4 可独立 mock 开发。
- 增加 M2 冻结门禁：schema 变更必须经 Jack 双签，M3 启动后只接受 bug 修复。
- M1 表驱动 vs M2 本体建模：矛盾，必须二选一，建议"本体优先"。
- M3 精准路线 vs 真实动作：不冲突但有张力。金融真实动作太模糊无法写成可形式化 precondition，S3 只选"可形式化动作"作为写回目标。

## 五、过度设计/遗漏/违反原则
- 过度：DES 标准化产品放 S3 过早（应先让金融 demo 跑通）；55 张表对 5 分钟 demo 太多（核心 10-15 张足够）；M5 备份清空旧数据放最后有风险（建议保留 data/retail/ 可切换）。
- 遗漏：缺 S3 级 ADR（从零售切金融是重大方向变更）；缺用户/受众验证步骤；缺数据字典入 git 方案；缺 LLM 调用预算与 fallback。
- 违反单一事实来源/阶段声明：git 显示 S2 已收口但 AGENTS.md 仍写"S1（MVP 跑通）"，派活前必须修正。
- 违反"待定项未定不派活"：动作范围仍是待定，应先由 Jack/业务顾问拍板再派编码。
- 违反"研究对象锚定"：M4 每页必须能回答"这体现语义接口什么价值"。

## 复核结论
方向正确、技术底座扎实，但**排期策略（严格串行）和范围控制（55 张表、DES 一步到位）有明显问题**。最大结构性风险是"业务动作设计空白"和"选表无标准"。调整后再开工。
