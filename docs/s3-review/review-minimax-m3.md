# S3 设计独立复核报告 — minimax-m3

## A. 三条最强支持
1. **S2 核心机制可复用，最小增量做新场景**。S3 把"零售对象"换成"金融对象"，本体运行时/查询引擎/动作执行器几乎不动。最大杠杆=把 30 万行金融数据塞进已跑通回路，验证语义接口可迁移性。
2. **DES 升级为"表结构驱动"是正确抽象层**。表结构是 SQL 层标准抽象（列/类型/外键/枚举），Pydantic 驱动可复用到任何行业——从研究原型走向演示资产的合理路径。
3. **"受限结构化查询"与金控风管天然契合**。合规与可解释性要求本就排斥 LLM 自由生成 SQL/动作。"可表达集内保证答对+域外明确拒答"在金融是需求而非约束——这正是 5 分钟 demo 最强卖点。

## B. 三条最强反对
### B-1（P0）："表结构驱动"被滥用为"自动本体建模"
表结构是物理层，本体是语义层，不可自动互推。如"客户-集团客户"是聚合还是组合？"预警-处置"是触发还是依赖？这些不会从 JOIN 长出来。
**改**：M1 严格只做"表结构→模拟数据+物化指标"，禁止做本体建模。M2 在 M1 输出的 schema metadata 之上手写本体。M1 是输入提示，不替代 M2 决策。
### B-2（P0）：211 表→55 核心表的选择标准完全缺失
决策引擎与流程引擎本质是规则/流程定义而非业务数据，它们的表是规则模板的物化（极少实例化），当业务表处理会让 demo 偏离真实场景。
**改**：先列 5-8 个 demo 剧本（今日新增橙色预警？某客户集中度？某押品估值变动？某集团风险敞口？），从剧本反推必选表。决策引擎只看 metadata（规则分类/命中数），流程引擎只看审批节点定义。
### B-3（P0）：写动作与读查询混用同一引擎
读的不变量是"答案与表一致"；写的不变量是"状态机合法+并发安全+可回滚+审计完整+双签通过"。S2 的 7 道校验针对读，搬到写上会失效。LLM 自由生成写语句必然溢出。
**改**：M3 拆两引擎——读引擎（沿用受限结构化查询）+ 写引擎（动作模板：每动作固定参数 schema+预检规则+双签门槛，LLM 只做"问询理解+动作选择+参数填槽"，不生成任何写语句）。这是 S3 新增研究价值——读易写难。

## C. 不确定
- 可表达集迁移性：金融指标维度组合远多于制造业，未实测前不能假设 85%+。
- 火山 Coding Plan 对金融语义时延：金融 schema 复杂度 12 倍，契约解析可能显著拉长，M3 启动前需 30 题实测确认 ≤2s。
- "金控风管部"视角边界：集团统一风管（看子公司合并）还是某子公司风管？影响"客户"对象范围。
- "真实业务动作"颗粒度：单步还是多步工作流？demo 用单步即可。
- 演示对象差异：领导看新范式/客户看痛点/workshop 看机制，单一 Landing 能否三合一未验证。
- "安平金控"真实感：落到金融监管口径（1104/EAST）还是脱敏版内部口径？
- S2 架构对 211 表本体的扩展性未压测。

## D. 跨项检查
- D-1：修正 B-1 后 M1-M5 严格 DAG 无环，M3/M4 后半程并行合理。
- D-2：M1 表结构驱动 vs M2 本体建模——潜在矛盾，修正：M1 不做本体，M2 手写，接口=M1 输出的 schema metadata。
- D-3：M3 精准路线 vs 真实动作——真实冲突。禁止 LLM 自由生成写语句，禁止用读查询 7 道校验覆盖写动作。两者是不同研究问题。

## E. 过度设计/遗漏/违反原则
- 过度：M1 产品化文档（README 级足够）；M2 领域字典语义化（留 S4）；M5 白皮书更新（副产物）；M3 风险注入 5+ 子项（先做集中度+集团风险，其他留接口）。
- 遗漏：双签 UX 设计（demo 高光时刻，需 LLM 提议→人工看 diff→确认/驳回）；演示冷启动/预热（1.6s 延迟需首批问题预热+物化缓存）；LLM 失败兜底（超时/解析失败/拒答 fallback 话术）；字段值脱敏（表名脱敏了字段值也要）；demo 剧本与 30 题评测集（验收标准）；演示环境隔离（data/s3_demo/+切换开关）；AGENTS.md 与 ADR 更新（docs/adr/0007-s3-金控风险预警.md）。
- 违反"研究对象锚定"：S3 demo 必须反向回答"这跟语义接口/本体论落地有什么关系"，Landing 页脚写一行研究价值锚定。
- 违反"落地先行"：先跑通 1 个 demo 问题端到端（7 道校验通过+写动作双签通过），再扩展。
- 违反"待定项未定不派活"：动作清单是 M2 派活前置依赖，Jack 必须先拍板。
- 违反"第一版先跑通"：M1 上来就 55 张表是反的，先跑 1 个 demo 问题所需表（≈10 张）验证 schema-driven DES 后再扩。

## 优先级建议
- P0：B-1（DES 不做本体）、B-2（55 表选择标准+demo 剧本反推）、B-3（读/写引擎分离）、动作清单 Jack 拍板。
- P1：D-2/D-3 跨项修正、双签 UX、LLM 失败兜底、字段值脱敏、AGENTS.md/ADR 更新。
- P2：领域字典语义化、白皮书更新、过度设计裁剪。
