## 〇、评审汇聚摘要与裁决

### 共识采纳（两份评审一致）
1. D3 重定义：L1 摘要行常驻 ↔ L2 步骤列表（默认收起）↔ L3 详情抽屉，严格包含（§3.3）；
2. 状态模型重划：拒答为大类下分子类，补加载中/部分成功告警/空结果/未注册口径/降级成功标记（§4.2）；
3. D6 落地：后端数值硬校验（LLM 输出数值必须可溯源，否则整条拦截）（§5-D9）；
4. 新增「SSE 事件协议」节（附录 A）；
5. 会话持久化 = 服务端（审计属性决定，非开放问题）（§6）；
6. **删除 = 对用户隐藏，物理数据保留审计链**（§附录 D）；
7. 图表类型 = 语义层规则声明 viz 字段（§5-D7 修订）；
8. profile schema 规范化（附录 C）；
9. 证据编号 = hover 说明 + 一键复制，格式含日期可解析（§3.2）。

### 分歧裁决（3 项）
| 分歧 | 模型一 | 模型二 | 裁决 |
|---|---|---|---|
| D3 修复 | 摘要条置顶+顺序重排 | L1 常驻+严格包含 | 融合：摘要条单行常驻于消息卡顶部，生成期间动态显示「校验中 · 第 n/N 步」（直播在 L1 体现，不展开 L2），完成后转为路径摘要 |

## 三、信息架构与界面结构

### 3.1 布局
同 v0.1 三栏（会话栏 | 对话区 | 上下文栏可选）。修订：**查询历史从会话栏移至对话区顶部 tab**（模型二：与会话列表功能重叠），会话栏专注会话管理。

### 3.2 AI 消息卡（v0.2 重排，区块自上而下）
1. **L1 摘要条**（单行常驻，第一元素）：
   - 生成期间（动态）：`⏳ 校验中 · 第 3/7 步`——直播在 L1 体现，不展开 L2；
   - 完成后（静态）：`❄ 冷路径·明细下推 · 8 项校验全过 · REQ-20260909-A3F19B ⧉`（证据编号 hover：「本次查询唯一编号，可审计追溯」+ 点击复制；耗时不在 L1 显示——性能数字进 L3，对演示者是靶子（模型一 P1-1），分析者可在 L3 查看（角色显隐））。
2. **回答区**：结论文字（P0 = 模板句式，语义层填充数字；P1 = 三色标记增强，见 §5-D9）；
3. **数据区**：表格/图表直接内嵌（有 rows 必显示；空结果显示空态文案，见 §4.2）；
4. **决策过程区（L2，默认收起）**：点击 L1 展开步骤列表（按路径重新编号 1..N，无跳号）；
5. **详情（L3 抽屉）**：Tab 决策过程全记录（含 LLM 原始输出——**脱敏后展示**，防系统提示词泄露）/ 结论依据 / 返回数据全量。
消息卡与详情面板为**同一数据的摘要/完整视图**，映射关系：消息卡各区块 = 面板对应 Tab 的截断视图（模型二 P0-4 的映射表要求）。

### 3.3 决策过程三级（v0.2 重定义，采纳模型二严格包含式）
L1（1 行，常驻）⊂ L2（步骤列表，点击 L1 展开/收起）⊂ L3（完整详情抽屉，点「详情」）。每级信息量差一个数量级；直播只在 L1 动态体现；总决策 >2.5s 时 L1 追加「处理中」呼吸态（不自动展开 L2）。

### 3.4 证据面板统一（v0.1 结论不变）
三分区（决策过程/结论依据/返回数据）由 profile 决定构成；金控 profile 的结论依据五区并入「结论依据」分区。映射表见 §3.2。

### 3.5 会话栏（v0.2 修订）
会话列表：**重命名 / 置顶 / 收藏 / 删除（二次确认）**；删除语义 = 对用户隐藏，审计数据保留（附录 D）。查询历史移至对话区顶部 tab（§3.1）。

### 3.6 输入区
新增：**中文输入法组合键保护**（compositionstart/end 期间 Enter 不触发发送，模型一 P2）；**停止按钮**（生成中可取消，SSE AbortController，模型二 P1-2）；连发处理：BUSY 时输入可写、发送置灰（不做排队）。

## 四、交互流程与状态

### 4.0 状态机（新增，模型二 ④-2）
```
idle → 输入中 → 加载中（骨架+L1 直播）
  加载中 → 成功 / 成功含告警 / 参数追问 / 拒答（口径缺失|范围超限|未注册口径） / 校验失败 / 服务异常
  参数追问 → （用户补参数）→ 加载中
  任意态 → （用户取消）→ idle（半成品消息卡标记「已取消」）
  任意失败态 → （重试）→ 加载中
```

### 4.1 生命周期
SSE 事件驱动，协议见附录 A；超时/断连/取消按附录 A。

### 4.2 状态定义表（v0.2 重划：八状态 + path 映射，融合两份评审）

| # | 状态 | 后端 path | 触发场景 | 回答区 | 数据区 | 附加 |
|---|---|---|---|---|---|---|
| 1 | 加载中 | — | 请求发出至 final | 骨架+L1 直播 | 骨架 | 可取消 |
| 2 | 成功 | hot / cold_pushdown / cold_adhoc | 正常返回 | 结论文字 | 表格/图 | L1 摘要+详情 |
| 2b | 成功·含告警 | 上述 + 降级标记 | **LLM 路由降级为关键词匹配**（答案正确但链路弱一档）或部分校验告警 | 同上 + 黄标「本次由简化路由回答」 | 同上 | 告警进详情 |
| 2c | 成功·空结果 | 上述 | 查询合法、0 行 | 「该范围无数据」空态文案（禁崩句） | 空态 | 建议调整范围 |
| 3 | 参数追问 | blocked_param（缺失子类） | 时间/维度缺失 | 追问句 + 快捷参数 chips | 无 | 选中即续查 |
| 4 | 拒答·口径缺失 | unregistered | 问题无对应规则 | 「无对应口径」+ 提交规则候选引导 | 无 | 与范围超限区分（模型二 P0-2） |
| 5 | 拒答·范围超限 | blocked_param（超边界子类） | 时间超数据边界 | 如实说明数据边界 | 无 | 边界来源=语义层元数据（非硬编码） |
| 6 | 拒答·范围外 | rejected | 问题属未注册业务域 | 「当前范围仅…」+ 域说明 | 无 | — |
| 7 | 校验失败 | validation_failed | 校验不一致 | 「校验未通过，拒绝返回」+ 数值对照 | 无 | 强调宁可不答不出假数 |
| 8 | 服务异常 | error 帧 / 网络失败 | 基础设施失败 | 脱敏错误文案 + 重试 | 无 | 错误码见附录 B |

> path→状态为一对一显式映射（模型一 P0-2 要求）；blocked_param 拆为 3/5 两态，由结构化字段（非 answer 文案猜）区分：final.result 附 `block_reason: "missing_param" | "out_of_range"`。

### 4.3 多轮追问（P1，收敛范围）
P1 仅支持**同规则换参数**（「那 7 月呢」= 复用规则+替换时间参数）；维度筛选/跨规则组合需语义层组合能力，不在本版（模型一 P1-4）。追问链消息卡标注「承接上一问」。

## 六、非功能（v0.2 补强）
- **性能三段指标**（模型二 P1-4）：首字延迟（点击→回答区首字）热路径 P95 ≤2.5s / 冷路径 P95 ≤6s；数据到达延迟（→表格首屏）+1s 内；完整完成延迟（→final）≤10s；测法：语义层埋点 + trace 耗时字段，采样真实查询统计 P95；
- **持久化**：会话/消息/trace 全部服务端（SQLite + JSONL→审计库）；**删除 = 用户侧隐藏，物理保留**（审计一致，附录 D）；
- **安全（可执行化，模型一 P1-7 + 模型二 P1-5）**：PII 按 profile 字段级配置，默认打码+权限查看；LLM 原始输出展示前**脱敏**（系统提示词/密钥样式串过滤）；前端渲染统一 sanitize（禁裸 innerHTML 拼接用户/LLM 内容）；错误文案经错误码映射表转人话，不透内部堆栈；LLM 数值硬校验（§5-D6）；
- **可观测性**（模型二 ④-7）：前端埋点（查询数/状态分布/步骤点击率/三段延迟/错误率）+ 后端监控（SSE 成功率/步骤耗时分布/拒答原因分布）——研究项目需要知道用户怎么用；
- **幂等**：查询带 client 请求 ID，重试不产生重复 trace（模型一 P1-8）；
- **鉴权与隔离**（模型一 P1-8）：P0 声明最小边界 = 单用户（Jack），会话归属字段预留；多用户与权限为 P2（附录 C 预留角色字段）。

## 七、验收标准（v0.2 重写）
1. 八状态各配 ≥1 真实问题验证（用例清单：热/冷下推/冷即席/空结果/参数追问/超范围/范围外/校验失败[注入假数据触发]/服务异常[停服务触发]）；
2. 消息内顺序：L1 摘要条 → 回答 → 数据表格（有 rows 时）→ L2 收起；L1 生成期间动态更新；
3. L2 步骤编号从 1 连续递增（按 path 编号，无跳号）；
4. 详情面板可看：LLM 原始输出（脱敏后）、完整 SQL、逐项校验、耗时（分析者视角）；
5. 证据编号回放 = **快照回放**，回放内容与当时一致（数据变更后回放不变）；
6. D6 一致性用例：随机抽 10 次回答，提取全部数字逐一与 rows/语义层返回比对，一致率 100%；
7. 会话四操作（重命名/置顶/收藏/删除）可用；删除后列表与历史均不可见（审计库保留）；
8. 刷新/重开浏览器会话恢复；
9. 断网/停服务 → 消息卡显示脱敏错误 + 重试；生成中点停止 → 消息标记「已取消」；
10. 性能：三段指标 P95 达标（采样 ≥20 次真实查询）；
11. 新增业务域仅需：注册规则 + profile + 面板组件，壳零改动（代码评审验证）；
12. IME 输入法组合期间 Enter 不误发。

## 附录 A：SSE 事件协议
| 事件 | payload | 顺序保证 |
|---|---|---|
| step | {n, title, status(ok/fail/blocked), detail, sql?, ms?} | n 按 path 从 1 连续递增；step 均在 final 前 |
| token | {text} | 仅成功路径；在步骤[7]后、final 前 |
| final | {完整 result：request_id/started_at/question/rule/path/answer/sql/rows/tables/steps/block_reason?} | 终帧，每查询恰好一帧 |
| error | {code, message(脱敏)} | 服务异常终帧；后发出即终止 |
- 心跳：每 15s comment 帧（防代理断连）；超时：客户端 30s 无任何帧 → 超时态；
- 取消：客户端 AbortController 断开 SSE；服务端收到断开终止生成，trace 记 canceled；
- 重连：不自动重连（问答场景重新发送即可）；重试带相同 client_request_id 保证 trace 幂等；
- 断流半成品消息卡：标记「已中断」+ 重试按钮，不保留半截回答正文。

## 附录 B：错误处理矩阵（节选，完整版随开发计划）
| 场景 | 错误码 | 用户文案 | 操作 |
|---|---|---|---|
| 服务不可达 | E_NET | 查询失败：服务未响应 | 重试 |
| LLM 路由超时/失败 | E_ROUTE_FALLBACK | （无感，降级关键词路由+黄标） | — |
| LLM 输出非法 | E_ROUTE_INVALID | （无感，降级同上） | — |
| SQL 执行错误 | E_SQL | 查询执行出错，已记录（编号） | 重试/反馈 |
| 数值校验拦截 | E_VALIDATION | 校验未通过，拒绝返回（附数值对照） | 反馈 |
| 参数缺失 | E_PARAM_MISSING | 追问句 + 参数 chips | 补参数 |
| 超数据边界 | E_PARAM_RANGE | 数据边界说明 | 调整范围 |
| 范围外 | E_SCOPE | 域说明 + 候选引导 | 换问法 |
