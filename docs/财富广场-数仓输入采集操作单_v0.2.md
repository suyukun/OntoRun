## C. 数据导出（三类表分开处理）

### C1. DWS 汇总表 → 两个月全量

- 时间窗 **2026-07-01 ~ 2026-08-31**，整段全要
- 这类表本身就是算好的日/周期汇总，行数小（天数 × 维度组合），放心全导
- CSV 或查询结果导出都行

### C2. DWD 注册明细表 → 抽 6 天 + 只挑需要的列

明细表两个月过亿行，全导不现实也用不上，按下面来：

- **抽 6 天**（每旬取一天，避开月初月末跑批边界）：
  `2026-07-05、2026-07-15、2026-07-25、2026-08-05、2026-08-15、2026-08-25`
  按注册日期字段过滤（`rgst_dt`，实际字段名不同就按实际的来）；
  单文件超过 500MB 就减成 3 天（07-15 / 08-05 / 08-25）
- **只挑这些类别的列**（具体字段名以 A 的表结构为准，表里没有的跳过）：
  用户标识、注册日期、渠道编码、性别、年龄或出生年月、地域（省/市，如有）、实名相关字段（如有）

### C3. 维表 → 渠道全量、用户按需

- **渠道维表 `dim_ch_chl_df`**：整张全要（本来就小）
- **用户维表 `dim_cu_usr_info_df`**：两种做法任选其一
  - 简单：只挑不敏感的列（用户标识、性别、年龄、地域、实名状态/时间、注册相关信息）
  - 彻底：用 C2 抽样明细里的用户标识反查（`WHERE usr_id IN (...)`），人少列全
- **匿名映射表 `DIM_CU_LOGIN_ANONY_MAPPING_DF`**：不大（百万行内）就整张；太大就同样按 C2 的用户标识抽

### 敏感数据三原则

1. **用不到的不导**：手机号、证件号、姓名、详细地址——注册分析用不到，直接不出现在导出列里，比打码更安全
2. 实在要带的敏感字段，在导出 SQL 里打码后再导，例如：`substr(phone,1,3)||'****'||substr(phone,-2)`
3. 导出文件走内网共享盘/企业微信，不走公网网盘
