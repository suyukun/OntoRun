## C. 数据导出（三类表分开处理）

### C1. ADS 汇总表（8 张）→ 两个月全量

- 时间窗 **2026-07-01 ~ 2026-08-31**，整段全要
- 这类表本身就是算好的日度汇总，行数小（天数 × 渠道组合），放心全导
- CSV 或查询结果导出都行

### C2. DWD 明细表 → 抽 6 天 + 只挑需要的列

明细表数据量大，全导不现实也用不上，按下面来：

- **必给：`dwd_cu_rgst_fin_di`**（注册 KPI 口径主表）
  **建议同给：`dwd_cu_real_df`（实名）、`dwd_cu_actv_df`（激活）**——实名/激活转化分析要用
  视文件大小选给：dwd_cu_rgst_nonfin_di、dwd_ch_usr_rltv_df
- **抽 6 天**（每旬取一天，避开月初月末跑批边界）：
  `2026-07-05、2026-07-15、2026-07-25、2026-08-05、2026-08-15、2026-08-25`
  注意 `_di` 结尾是增量表，按表内业务日期字段过滤（字段名以 A 的表结构为准）；
  单文件超过 500MB 就减成 3 天（07-15 / 08-05 / 08-25）
- **只挑这些类别的列**（具体字段名以 A 的表结构为准，表里没有的跳过）：
  用户标识、注册/业务日期、渠道编码、性别、年龄或出生年月、地域（省/市，如有）、实名/授权状态相关（real/rltv 表）

### C3. 维表 → 整体原则：渠道等小表全量、用户等大表抽样

- **渠道维表 `dim_ch_chl_df`**：整张全要（本来就小）
- **用户维表 `dim_cu_usr_info_df`**（广场全部注册用户，量大）：两种做法任选其一
  - 简单：只挑不敏感的列（用户标识、性别、年龄、地域、实名状态/时间、注册类型等）
  - 彻底：用 C2 抽样明细里的用户标识反查（`WHERE usr_id IN (...)`），人少列全

### 敏感数据三原则

1. **用不到的不导**：手机号、证件号、姓名、详细地址——注册分析用不到，直接不出现在导出列里，比打码更安全（实名相关表如含证件要素，只挑状态/时间类字段，证件号本身不导）
2. 实在要带的敏感字段，在导出 SQL 里打码后再导，例如：`substr(phone,1,3)||'****'||substr(phone,-2)`
3. 导出文件走内网共享盘/企业微信，不走公网网盘

## D. 报表 SQL（观远平台）

注册、实名、授权、关联渠道相关报表的取数 SQL，一张报表一条：

- 从**观远平台**把上述指标的报表/取数定义拷出来（ADS 表是观远指标的唯一数据源，报表侧的指标定义对口径确认很关键）
- 有几张给几张，散的更好——每张都是一份确认过的口径
- SQL 实在拿不到的，给报表名或指标名也行
