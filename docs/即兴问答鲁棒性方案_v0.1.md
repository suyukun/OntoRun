# 即兴问答鲁棒性方案 v0.1（2026-09-10，融合两路调研，待 Jack 批准后实施）

> 依据：docs/research/ChatBI问答鲁棒性调研_v0.1.md + docs/research/LLM结构化路由最佳实践_v0.1.md + tests/fixtures/问法压力测试集_v0.1.json（30 条）
> 架构总判断（业界三方同构背书）：原语固定、LLM 只选；分水岭在编译器前的问法理解工程——全部用确定性代码兜住，LLM 只做它擅长的抽取与选择。

## 链路总图

```
中文问题 → LLM 结构化抽取（JSON mode，只输出：measure 候选/dimension 候选/时间表达槽/实体 mention/缺槽声明）
  → 【代码】时间规范化：表达槽→真实区间（LLM 禁直出日期）
  → 【代码】实体链接：mention→维表成员值（绝不静默选近似）
  → 【代码】澄清判定：缺必填槽/0 候选/多候选 → 结构化 clarify（一轮为限）
  → 原语组合 → 编译器（现有）→ 数字 + data_profile
  → 任一步失败：置信度不足 → 模板化拒答 + 注册表生成推荐问法（宁拒不错）
```

## 六模块（M1-M3 为新增确定性模块，M4-M6 改造 llm_route）

| # | 模块 | 做什么 | 业界依据 |
|---|---|---|---|
| M1 | **别名层** | 注册表加 aliases 资产：度量/维度/渠道值的口语变体（"来了多少人"→注册用户数；"优享+"/"优享plus"→同一渠道值）。编译前按相关性注入候选 | 衡石指标检索增强；条目描述质量>喂法 |
| M2 | **时间解析器** | LLM 只输出标准化时间槽 {模式:上月/近N天/季度/显式区间, 粒度}；time_normalizer 代码算真实区间。"自然月vs滚动30天"进口径包 | 阿里 XiYan 两步法 >95%；LLM 直出日期有系统性偏差（DateLogicQA） |
| M3 | **实体链接器** | LLM 只抽表面串（"麦当劳"），linker 查维表：精确/别名→模糊匹配→embedding；0 候选拒答/1 候选用/多候选澄清。编译器只认 value_code | text-to-SQL value linking 路线；防幻觉参数核心；兼注入防御 |
| M4 | **澄清循环** | 判定权在代码（注册表元数据：无默认值=必填；候选数量触发）；结构化 {"clarify":{question,options}} 通道，选项由注册表生成不让 LLM 编 | CLAMBER：LLM 认得歧义但压倒性直答，CoT 反加重过自信 |
| M5 | **few-shot+重试** | prompt 补 3-5 个静态精选（直问/带时间/缺时间/域外 reject 反例），从注册表模板生成防漂移；JSON mode+finish_reason/空 content 检查+1 次错误回喂重试→降级关键词 | DeepSeek JSON Output 官方模式；Instructor 模式 |
| M6 | **拒答与引导** | 映射置信度低于阈值→模板拒答+推荐问法（"我能答：注册数的渠道/性别/趋势任一切片"） | 腾讯提问建议/衡石视觉锚点；演示红线宁拒不错 |

## 多轮（二期，演示先单轮）

结构化原语组合天然是对话状态：多轮=每轮 LLM 输出 patch（add/replace/clear），编译器拿完整组合无感。"那分渠道呢？"=上轮组合+channel 维度。演示话术兜底："先单轮问"。

## 评测（压力测试集升级）

30 条扩成六难点分层问法集（口语化/相对时间/模糊/多轮/超纲/实体匹配各 5-8 条）+ 坏例回归制（每次修路由必跑，防 regression）；澄清轮次进指标（追问次数越少越好）。

## 实施排期（AI 产能估算，非人天）

- **演示版（先行）**：M1 别名层 + M2 时间解析器 + M5 few-shot/重试 + M6 拒答引导 ≈ 2-3 小时（两个子代理并行：确定性模块一路、llm_route 改造一路）
- **完整版（演示后）**：M3 实体链接器 + M4 澄清循环 + 多轮 patch ≈ 后续迭代
- 验收：升级版压力测试集全绿 + 真实 LLM 跑通率目标：演示高频问法 100%、全集 ≥90%

## 演示红线

宁拒不错：任何不确定→拒答+引导；数字永远带 data_profile 徽标。
