## 二、按顺序试用（5 步看懂最小语义接口闭环）
1. **本体驱动 UI**（前端左侧「数据浏览」）：点对象类型（订单/客户/商品/库存…）→ 列表列是 schema 自动生成的 → 进详情看属性 + 链接计数 → 点链接跳到关联对象。改 schema 界面跟着变，前端零硬编码。
2. **动作表单**（前端「动作」）：找到 cancel_order → 填订单号 + 原因 → 提交。注意提交后源库真的变（见第 3 步）+ 高危动作有二次确认。
3. **写回是真的（三问之 2）**：终端执行 `sqlite3 data/sources/retail_source.db "SELECT order_id,status FROM orders WHERE order_id='ORD-1001'"` —— 取消后是 `cancelled`，库存 reserved 释放。不是改前端状态。
4. **规则拦截（三问之 3）**：对已发货订单 ORD-2007 提交取消 → 被 `SHIPPED_ORDER_CANNOT_BE_CANCELLED` 拦下，源库零变更，审计仍留痕。
5. **审计留痕**：浏览器开 http://127.0.0.1:8000/audit → 每条动作含 actor/params/effects 差异/writeback SQL/影响行数；before/after 快照在 action_runs（E6）。
