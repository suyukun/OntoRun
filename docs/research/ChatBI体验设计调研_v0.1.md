# ChatBI 体验设计调研 v0.1（财富ThoughtSpot）

> 命题：把「问答计算器」升级成「数据分析师」——思考呈现、多轮记忆、拒答话术、溯源 aha、系统级 aha 五+一主线调研。
> 调研人：Rose（产品体验调研子代理）· 日期 2026-09-11 · 来源分级沿用项目惯例（T1 官方规范 / T2 研究机构 / T3 官方文档·大厂 / T4 编辑媒体 / T5 社区线索）。凡未核验处显式标注。
> 主线⑥（系统级 aha）为老板定位级反馈新增，整体建议以其为纲。

## 0. TL;DR

1. 「最短思考时长」无公开规范，但有 30 年感知延迟定律背书（NN/g 0.1s/1s/10s + 「系统可以太快」原话），节奏设计有据可依。
2. 多轮记忆感的业界共识不是喂聊天记录，是**结构化对话状态 + 差量更新**（衡石/FreeWheel/Power BI Copilot 三源一致）；长上下文裸喂有明确劣化证据。
3. 拒答/澄清话术 LLM 改写的费用**完全不成立**：flash 级模型月成本 0~3.3 元；真实代价是时延与稳定性，用「并行改写+模板兜底」化解。
4. 侧边栏 aha 的业界答案是**四级穿透**：数字→SQL/查询词→来源明细行→口径规则（ThoughtSpot、Power BI 均有官方能力）。
5. progress theater 有真实翻车案例（Devin 85% 任务失败、o1 藏思维链被封号争议），铁律=表演必须绑定真实管道事件。
6. 系统级 aha 的样板是 Tableau Pulse：**不问就说**（主动洞察自动挂载+渐进式引导问答），其检测层是统计规则而非 LLM——我们九步管道的中间产物现成可复用。

## 1. 主线① 思考呈现与节奏

**发现**
- 感知延迟三限值（Nielsen, *Usability Engineering*, 1993；2026-09-11 抓取原文核验）：0.1s 内=即时感；1s 内=思维流不断（>0.1s 已失去「直接操作数据」感）；10s=注意力上限，**超过必须给进度反馈与完成预期**。两条被忽视的原话：①「响应时间高度可变时，延迟中的反馈尤其重要」——LLM 管道恰好是高可变延迟；②「计算机也可能快到用户跟不上……动画应按真实时钟计时」——这是**最短展示时长的 30 年依据**：太快与太慢同样破坏体验。
- 「最短思考时长」作为产品参数**未找到公开规范**（诚实标注：检索多轮无果）。最接近的业界事实是两类：流式派（DeepSeek R1 等推理模型直接流式输出真实推理 token，思考即内容）与摘要派（OpenAI o1 只展示原始思维链的摘要）。
- Tableau Pulse 的「渐进揭示」：洞察不是一次全给，而是点建议问题→逐层展开图+叙述（官方帮助文档，2026-09-11 核验）。
- 国内 ChatBI（腾讯云等）把「流式输出」列为降低多轮等待感的标准手段（本地《ChatBI问答鲁棒性调研》已核验 T3）。
- Kent Beck《The Precious Eyeblink》（Substack，题录 T5 未深读）：主张保护「眼眨时刻」级即时响应——与最短时长 tension 的思想素材。

**来源**
- NN/g Response Times: The 3 Important Limits https://www.nngroup.com/articles/response-times-3-important-limits/ （T2，1993-01，2026-09-11 核验）
- Tableau Pulse insight types https://help.tableau.com/current/online/en-us/pulse_insights_platform_insight_types.htm （T3，2026-09-11 核验）
- shinychat thinking/reasoning display UI（社区实现旁证 T5）https://github.com/posit-dev/shinychat

**对财富ThoughtSpot 的可借鉴做法**
- 最短思考时长定 2~3s 有依据，但**节拍器只能由真实管道事件驱动**：每个 SSE 步骤事件到达即上屏，真实耗时<2.5s 时按 NN/g「真实时钟」原则用补间拉满表演节奏（演示模式可配）；真实>节奏时直接显示真实事件，不做假延展。
- 思考文案去模板化：文案按**步骤类型+结果参数**生成变体（「锁定口径：存量资金规模（2026-08 版）」而非「第 3 步：匹配口径」），参数从结构化管道产物取，不需要 LLM。

## 2. 主线② 多轮上下文记忆感

**发现**
- 业界共识（本地《ChatBI问答鲁棒性调研》已核验）：维护**结构化对话状态**（当前查询计划+已确认口径+消歧结果+会话摘要），每轮做差量更新，判「新增条件/修改条件/纯追问」三类合并；衡石拆三种跨轮依赖：指代消解、增量修改、上下文继承。FreeWheel 持久化前序关键实体（时间区间、指标别名）。
- Power BI Copilot 实证（MS Learn 官方文档，2026-09-11 核验）：Copilot pane 内追问「about a summary you received」，答案带**报告内视觉对象引用**且 RLS/OLS 全程生效——大厂同样做「会话内携带模型上下文」，但携带的是语义模型与视觉对象，不是裸聊天记录。
- 无状态/裸历史的坑（本地《AI工程管理开工前方法调研》§1 引用链）：Anthropic 官方「上下文塞满→忘早期指令→出错」；NearForm 实践者证据「context collapse：约 20 个 prompt 后模型自相矛盾」；lost in the middle（Liu et al. 2023, arXiv:2307.03172，经典文献，本轮未重验原文）——中段信息召回率显著下降。
- 衡石 A/B（T3 厂商单方实验，引用需注明口径）：嵌入式上下文+引导问法后问题描述准确率 23%→68%、首次回答满意度 41%→89%。

**对财富ThoughtSpot 的可借鉴做法**
- 多轮 = LLM 输出对上一查询组合的**结构化 patch**（add/replace/clear，作用槽位），编译器每轮拿完整组合编译——架构红利，勿喂聊天记录。
- 记忆感要**外显**：答案卡顶部放「当前范围」chips（指标·时间窗·维度筛选·口径版本），追问命中继承时 chips 高亮新增项——用户「看见」系统记得，比模型真的记得更重要。

**价格核验**（2026-09-11 抓取官方/官方镜像页）

|---|---|---|---|
| qwen-flash（≤128K，百炼） | 0.15 | 1.5 | help.aliyun.com/zh/model-studio/model-pricing（T3 核验） |
| qwen3.8-flash（现默认模型） | 0.8 | 2.7 | 同上（T3 核验） |

| GLM-4-Flash/GLM-4.7-Flash | 免费 | 免费 | T4 报道（zaowu.world 2026-06、stockstar 2026-01），官方定价页 JS 渲染未能直接核验，标注待验 |

**算账**（假设：日 200 问 × 30% 拒答澄清 = 60 次/日 × 30 = 1800 次/月；每次 500 in + 100 out，月量 90 万 in + 18 万 out）
| 模型 | 单次成本 | 月成本 |
|---|---|---|
| GLM flash（免费档） | 0 元 | 0 元 |
| qwen-flash | 0.000225 元 | **0.41 元** |
| qwen3.8-flash | 0.00067 元 | 1.2 元 |
| deepseek-flash（峰时价） | 0.0018 元 | 3.24 元（谷时减半） |

**结论**：费用担忧不成立，全档月成本 < 一杯奶茶。真实代价是**交互链路加一跳 LLM 的 0.5~2s 时延**与稳定性。做法：拒答分支与话术改写**并行**发出，SSE 先出模板兜底文案、改写结果 1.5s 内到达则平滑替换；改写超时/失败静默回退模板——用户永远看到文案，费用照旧忽略不计。

## 4. 主线④ 查询详情侧边栏的溯源 aha

**发现**
- ThoughtSpot「Show underlying data」（官方文档，2026-09-11 核验）：任何答案可下钻到**非聚合明细行**，官方定位原话「lets you understand what an Answer consists of」——把「这个数是怎么构成的」做成一等交互。
- Power BI Copilot：答案内嵌**视觉对象引用**，点击跳到正确过滤态的图表；隐藏视觉、切片器状态都被引用且权限全程生效（T3 核验）。
- ChatGPT 数据分析：aha 来自**过程可见**——用户看着它写并执行 python、报错自修、出图，过程即信任（T4 题录 coursera.com，未深读）。
- 口径卡：本地《本体管理台UX调研》已定「口径规则是一等公民、是非题永远带出处（哪个脚本哪段/影响哪个度量/确认人与时间）」——侧边栏可直接复用该资产。

**对财富ThoughtSpot 的可借鉴做法**
- 侧边栏做**四级穿透**：数字 → 生成的 SQL（duckdb 方言，只读高亮）→ LIMIT 20 来源样例行（点击列头可全量）→ 口径规则卡（复用管理台口径卡）。全部确定性产物，零幻觉风险，开发量集中在展示层。
- 每个数字（含表格单元格）都可点开穿透——「图表与明细同源计算，不手写假数字」的项目纪律直接变成产品卖点。

## 5. 主线⑤ 风险清单：表演式进度翻车案例

| 案例 | 事实 | 教训 |
|---|---|---|
| OpenAI o1 藏思维链（2024-09） | 界面只展示原始推理 token 的**摘要**；用户问「show your chain of thought」收到警告邮件、有人被封一周；批评：「让我们盲目相信 AI 的答案」（T4 极客公园/智源社区 2024-09-17，2026-09-11 核验原文） | 思考展示与真实推理脱节会被识破并反噬信任；**展示什么、藏什么要诚实标注** |
| Devin「首个 AI 软件工程师」（2024） | 演示惊艳，第三方实测 benchmark 任务失败率 85~86%（T4 tweaktown/dev.to 题录，未深读） | 演示进度≠真实能力；一旦被对照实测，progress theater 变成信誉负债 |
| Manus 演示真实性争议（2026） | 社媒质疑演示镜头下 agent 行为的真实性（T5 aitoolsrecap 题录，未深读） | 同上，演示文化圈的反噬案例 |
| NN/g 反馈原则 | 承诺了进度就必须兑现预期；高可变延迟必须给「还要多久」信号（T2 核验） | 假步骤事件零容忍：思考流每一行都必须对应真实管道事件 |

**红线**：宁可显示 3 个真实步骤跑完 1.2s，不要 8 个匀速假步骤跑 3s——被懂行的人看一眼日志即穿帮。演示模式的节奏拉长只作用于**真实事件间**的补间。

## 6. 主线⑥ 系统级 aha：从「计算器」到「分析师」

### 6.1 主动洞察（不问不说）
- Tableau Pulse（T3 官方文档核验）：创建指标即自动检测 drivers/trends/contributors/outliers，**主动**用自然语言+可视化解释，top insight 直接挂在指标旁；再以建议问题做渐进式问答。洞察类型按 descriptive→diagnostic→predictive→prescriptive 分层。**关键考据：其检测层是统计规则（环比/贡献分解/离群），不是 LLM**——主动洞察的成本大头在统计模板，不在大模型。
- 对我们：九步管道本来就产出对比/贡献等中间结果，目前只用来画图。把中间产物再加工成 1~3 条「值得注意」置顶句（规则模板+维度成员名），增量成本≈零。
- 首页「今天你应该看」= 对注册表核心指标跑同一套规则检测，聚合 top-N 推送——分析师的开场白。

### 6.2 信任带来的 aha（把审计链变成卖点）
- ThoughtSpot Spotter Semantics 发布（2026-03，T3 题录 tmcnet.com，正文被 Cloudflare 拦截未深读）：把 deterministic AI + semantics 作为企业 AI 分析的信任叙事——与我们「确定性管道+语义注册表」架构同构，证明这条路是头部厂商正在讲的故事。
- 可感知信任三件套（均有官方实证）：数字可穿透到来源行（ThoughtSpot）、结论可回跳到带过滤态的证据（Power BI Copilot）、口径有版本与出处（我们的注册表+口径卡）。审计链不是合规后台，是**演示时最敢点的地方**。

### 6.3 惊讶时刻案例（业界演示的 wow 瞬间）
- ThoughtSpot Sage：自然语言→平台自动生成可视化+洞察，零报表搭建（T4 Luzmo 2024-06/2026-06 更新，FAQ 原文核验）。
- Tableau Pulse：点一个建议问题→图+「为什么」逐层展开（T3 核验）。
- Power BI Copilot：答案引用可点回报告里正确的图（T3 核验）。
- ChatGPT 数据分析：实时代码执行、报错自修（T4 题录）。
- 共性：wow 时刻全部是「**用户问了一句话，看到一个可点、可查、可追问的世界**」，没有一个是 spinner 转得好看。

### 6.4 我们能低成本实现的前三条 aha（性价比排序）
1. **四级穿透溯源**（数字→SQL→样例行→口径卡）：管道已产 SQL、duckdb 现成、口径卡已有设计稿；纯展示层开发；确定性零幻觉；演示 wow 最强。
2. **置顶「值得注意」**：复用管道中间产物的规则模板句；不新增 LLM 调用；把每次回答从「一个数」变「一个判断」。
3. **追问建议 chips（确定性生成）**：从当前查询计划差量生成（相邻时间窗/维度成员/上轮修改回滚），零 LLM 成本，同时缓解首问模糊（衡石 87% 首问模糊的教训）。
4. （顺带）拒答/澄清 flash 改写：费用已证伪，随拒答分支一起上。

## 7. 给 OntoRun 的整体建议草案（以系统级 aha 为纲）

**纲**：先让产品「自己开口、句句可查」，再打磨节奏与措辞。呈现节奏/话术是小事，放 P1/P2。

| 优先级 | 建议 | 成本 | 效果 | 风险 |
|---|---|---|---|---|
| P0 | 四级穿透溯源侧边栏（数字→SQL→样例行→口径卡） | 展示层为主，约一周量级；零新增 LLM | 直接回应「没有 aha」；信任即卖点；演示最敢点 | 需与 RLS/权限口径对齐，样例行必须走同一查询管道防口径漂移 |
| P0 | 置顶「值得注意」规则洞察 + 首页「今天你应该看」 | 复用管道中间产物+模板；低 | 从计算器变分析师的第一步；不问不说 | 规则句式易模板化，需变体池；数字必须与图表同源 |
| P0 | 追问建议 chips + 「当前范围」chips 外显多轮状态 | 确定性生成；低 | 记忆感可见化；降低首问模糊与澄清轮次 | chips 生成规则要随注册表更新，防推荐过期口径 |
| P1 | 思考流与真实 SSE 事件对齐 + 最短 2.5s 真实时钟补间（演示模式可配） | 前端节拍器；低 | 解决「千篇一律像规则引擎」；节奏有 NN/g 依据 | **假步骤零容忍**；日志可查，穿帮即信誉负债（Devin/o1 前车之鉴） |
| P1 | 多轮=结构化 patch（本地调研既有结论），拒绝裸喂聊天记录 | 已在语义层架构内；低 | 指代/增量/继承三类追问可用；上下文注入量可控 | patch 失败需回落澄清分支；防 prompt 注入（维度值只取注册表成员集） |
| P2 | 拒答/澄清话术 flash 模型并行改写+模板兜底 | 月 0~3.3 元；并行架构防加时 | 拒答从生硬变体面；费率已证伪非障碍 | 改写不得改事实与推荐问法（只改措辞）；失败静默回退模板 |
| P2 | 思考文案参数化变体（步骤类型+结果参数生成） | 规则模板；低 | 去「规则引擎感」的 80% 收益，零 LLM 成本 | 文案变体池需维护；不得编造未发生步骤 |

**一句话纲举**：把「确定性管道」从工程事实变成产品叙事——每个数字可穿透、每个洞察不请自来、每轮追问被记得，这三件事做完后，思考流怎么演、话术怎么润色都只是化妆。
