## 〇、一句话定位

> **OntoRun = 让大模型从"聊天"变成"干活"**：AI 能看懂业务问题、自动发起流程，但每一步都要人批准、改的是真数据、每个答案都能点开证据链（哪张表、哪条规则）。金控风险预警是它的证明用例。
>
> **差异化对照（对外统一口径）**："ChatBI 只会答，OntoRun 会做；Palantir 要数据团队建模，OntoRun 让 AI 直接看懂业务 + 人把关 + 全留痕。"

### 证明用例：安平金控集团客户风险预警处置

> 监管要求一家银行对单一集团客户的授信不得超过资本净额的 15%。但金控集团下面有银行、证券、保险——集团客户把钱分散在各家附属机构借，**单看每家都安全，加起来可能早就超了**。监管最怕的正是这种"各看没事、合起来出事"（超线=监管处罚与客户爆雷的坏账）。风险管理部的活，就是穿透看全口径：归集算总账、接近限额亮灯、确认处置、全程留痕。
>
> 术语底栏：**授信**=银行答应借给你的额度；**集中度**=一个客户占你全部家当的比例；**资本净额**=银行自己的本钱；**风险暴露**=如果对方还不上钱，你会损失多少；**穿透/并表**=透过每家小公司看到背后同一个大股东、把全家的账合起来看。

## 一、背景设定口径（模拟企业）

- **安平金控**：模拟金融控股集团，按《金控试行办法》第二条设定——控股两类以上金融机构（安平银行、安平证券、安平资管等），自身仅做股权投资管理。演示用资本口径：**集团并表资本 800 亿**；安平银行资本净额 600 亿、一级资本净额 480 亿（数字为可验算设定值，演示页随数字给出分母）。
- **视角主体**：安平金控**风险管理部**（集团视角）。
- **双层集中度口径（v0.2 关键修正）**：
  - **银行层（法定合规指标）**：各附属机构按自身监管规则各自计算——商业银行层：单一集团客户授信余额/本行资本净额 ≤15%（2003 指引第十二条 2010 修订口径）；大额风险暴露：单一客户贷款余额/资本净额 ≤10%、风险暴露/一级资本净额 ≤15%、一组关联客户 ≤20%（2018 办法第七/八条）。**注意这是两条不同的 15%，义务主体都是商业银行。**
  - **集团层（金控风管部监测口径）**：集团客户在安平系各机构融资的**并表归集余额 / 集团并表资本**，不套用银行 15% 红线；内部限额与预警线由安平自设（挂靠金控办法第三十二条"并表管理+大额风险暴露预警报告制度"、第三十三条"联合授信与融资风险预警线"）。分子=对同一集团及其关联方的全部融资归集（含表外承诺，扣除符合规定的净额项——2010 修订第十二条允许扣除项在演示明细中注明）。
- **处置权属声明**：处置动作的执行主责在附属机构（如授信管控在安平银行信贷/风险部门）；金控风管部做归集监测、预警督办、风险报告。演示中金控侧动作均为"督办/审批/推送"性质。
- **边界声明**：集团整体恢复与处置计划（金控办法第四十九条）属集团层面处置机制，与本包的客户级预警处置不同域，不在演示范围；预警处置质量纳入监管评估（2018 办法第三十四条）可在叙事提一句。

## 四、预警分级与生命周期口径

- **分级（安平内部口径，三级：红/橙/黄）**：🟡 黄色=关注（不紧急，纳入监测）→ 🟠 橙色=紧急（预计形成实质风险）→ 🔴 红色=危急（风险基本确定）。**v0.2 起由蓝/黄/红改为红/橙/黄**，与行业一手披露对齐（苏州银行 2021 半年报红/橙/黄三级；武汉金控=一/二/三级），并显式区别于我国突发事件预警"蓝黄橙红"四色（气象/应急语境）。分级无国家强制标准，叙事中不得称"监管分级"。
- **生命周期状态机**（行业主流，武汉金控披露）：**生成 → 确认（核实+定级）→ 处置（行动方案+跟进，不解除按月汇报）→ 终态**。状态全集：待确认 / 确认中 / 已确认 / 处置中 / 已关闭（解除）/ 已撤销 / 已排除。终态三种：核实信息不准确→撤销；不构成风险→排除；情况好转→解除（填解除报告经审批）。映射动作：confirm_warning / adjust_warning_level / submit_disposal / approve_disposal / push_warning / close_warning。
- **处置动作五类**（武汉金控口径）：①额度管控（冻结未用额度/暂停新增授信/提前收回——提前收回的法律依据=2003 指引第十八条）②排查核查（实地核查/账户只入不出/加密检查频次）③担保缓释（处置押品/更换或追加保证人/追索代偿→落 collateral）④结构调整（变更授信条件/下调分类/资产保全/诉讼）⑤退出。红色预警另含：**立即报告监管 + 压降/分散计划（银团贷款、联合贷款、贷款转让）**（2018 办法第三十七条、2003 指引第十二条）。

## 七、演示剧本（口径版 v2，6 步）

> 演示数字设定：天晟集团在安平系融资——安平银行 48 亿（8.0%，低于该行内部限额 10%）、安平证券 22 亿、安平资管 16.4 亿，各自口径单看都安全。集团归集 86.4 亿 ÷ 并表资本 800 亿 = **10.8%**。

1. **揭示（money shot）**："天晟集团风险有多大？"→ Agent 不直接给总数，先展开联合授信台账：银行 8.0% / 证券 / 资管逐家亮出（单看都安全）→ 归集合计 **10.8% ≥ 预警线 10%** → 已生成黄色预警。观众亲眼看"单看没事、合起来出事"。（挂 R1a + 金控办法第三十三条联合授信机制）
2. **升级识别**：联合授信机制识别出隐性一致行动人"恒昌贸易"→ 纳入归集 102.4 亿 ÷ 800 亿 = **12.8% > 内部限额 12%**。Agent **起草**上调红色建议（附依据），风险管理部**人工确认后生效**——confirm_warning + adjust_warning_level。
3. **后果链**：红色=风险基本确定 → 处置方案：冻结未用额度 + 追加押品（submit_disposal，押品对象联动）；金控向附属机构督办（warning_push）、启动风险项目跟进（risk_project）。
4. **双签高光（人拦 AI）**：AI 为"达标"提议**将押品评估价上调 30%**——看起来合理、实际是为绕开限额。审批人按限额规则当场驳回该额度项，AI 建议退回重新起草。演出"LLM 提议 ≠ 直接生效"。
5. **监管动作**：演示面板显示红色预警配套动作——立即报告监管 + 压降/分散计划（银团/联合贷款）（2018 办法第三十七条、2003 指引第十二条）。红色案例结束于"处置中/已督办"（真实处置周期数月，不演快关）。
6. **闭环与证据**：另设小额黄色案例走完整"解除关闭"（close_warning + 解除报告）；全程 audit 可回放，每个回答可点开证据链（哪张表、哪条规则、哪个分母）。
