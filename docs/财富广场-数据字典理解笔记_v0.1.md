## 二、业务图景（从数据反推）

财富广场 = 中信金控客户端 App。数据围绕一条用户旅程：

**引流（活动/外投/渠道）→ 注册 → 激活 → 实名 → 活跃（PV/曝光/点击）→ 参与活动任务（抽奖/奖品/积分）→ 导流到金融产品（转化）**

周边两条支线：① 内容线（资讯/财富号/AI 打标）；② 企微客服线（客服任务/朋友圈/单聊）+ 中信人（员工）转介线。

## 三、数据域（10 个）与实际分布

用户 CU / 运营 OR / 经营 BS / 风控 RC / 产品 PS / 交易 TR / 账务 AC / 公共 PB / 日志 LM / 渠道 CH。
实际事实表集中在 LM(7)、OR(15+)、TR(4)、CU(3)、BS(1)、CH(1)；**RC/PS/AC 三个域目前基本无事实表**（风控仅黑名单）。

## 五、DWS 口径模式（派生规则要挂的真相源）

- **时间窗标准序列**：当日/近7日/近15日/近30日/近180日/近一年/本月/本季/半年/本年/历史累计（11 档，同一序列在多表重复出现）。
- **人数 vs 次数成对**：`d_usr_drag_nop 当日导流用户人数` / `d_all_drag_nop 当日导流人数`（去重 vs 流水）。
- **PV 双口径**：全量访问 vs 登录用户访问（`Pv_day` vs `Pv_Login_Day`）。
- **BI 工具**：核心指标表标注「观远专用」（DWS_DAY_WHOL_PV_QTY_DF 等 3 张）。
- 指标代码表：DIM_BS_OPR_ANALY_INDX_CD_NF（经营分析指标代码）。

## 六、身份识别（handoff 命门）的现状

- 四种 ID：`usr_id` 用户ID、`login_id` 登录ID、`anony_id` 匿名ID、`uid_anony_id` 用户游客id（MAU 表注明「统计 UV 使用」）。
- 归一靠两张 DIM：`DIM_CU_LOGIN_ANONY_MAPPING_DF`（login_id ↔ anony_id ↔ last_login_id 最近一次时间）、`DIM_CU_ANONY_LAST_LOGIN_MAPPING_DF`（anony_id → 最新 login_id）。
- 埋点侧 `IS_VISIT` 标记是否游客（0/1）。
- **本体化第一刀**：User 对象 + 身份链接（IdentityMapping）显式建模，问答时「游客/登录/实名」三态口径由语义层统一裁决，不许 LLM 现场拼 ID。

## 七、数据缺口 / 疑点清单（待 Jack 澄清或字段假设清单覆盖）

1. **DIM_CU_USR_DF 用户维表字段详情缺失**（字段详情 sheet 中 0 行）——用户核心属性（注册渠道/实名态/标签）只能从注册事实表+标签维表拼，缺权威用户属性清单。
2. **DWS 表重名**：`dws_or_page_chnl_pv_df` 在目录出现两次（#33/#34，描述分别为「来源渠道」「来源入口」）——疑设计笔误。
3. **财富节 5 张表**（DWD_OR_WEALTH_FEST_*）无业务过程描述、字段分类全空。
4. **8 张有字段详情的表不在目录**：DWD_CU_REAL_DF(实名)、DWD_OR_RECORDS_DF、DWD_OR_SEND_RECORD_DF、DWD_TR_POINT_DF、DWD_TR_POINT_BASE_DF、DWD_WEALTH_FEST_BLACJKLIST_DF、dwd_or_rsr_slot_df 等；另有 DWD_OR_LUCKY_DRAW_DF 与 dwd_or_lucky_draw_df 疑同表异名。
5. 字段类型不统一（STRING vs varchar(128)），大小写混用（Evt_Id vs login_id）——设计文档态 vs 落地表态的漂移。
6. **导流表反范式极重**：DRAG 单表 51 字段中渠道 id/nm 占 19 个（导流渠道 4 级 × 来源渠道 4 级），对象化后可大幅收敛。
7. Q3「高质量订单 22%」的「高质量」定义不在字典中——需 Jack 给口径（疑=导流到金融产品的有效订单占比）。
