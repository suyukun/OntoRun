# 财富广场·注册场景 middle-out 落地方案 v0.1

> 状态：草案，待 Jack 圈选问题清单后启动。前置：docs/财富广场-ChatBI展示层产品设计_v0.2.md、demo（scripts/fortune_demo/）。

## 〇 一页结论

- 数仓按「数据是什么」组织（数据域：TR/CU/CH…），业务按「想问什么」提问。语义层是两套坐标系的转换器：**场景 = 横切若干数据域的表子集 + 问题集 + 口径卡**。
- 方法 = **卡 → 原语 → 组合** 三段循环：问题钉住口径（口径卡），口径提炼成原语（对象/度量/维度/身份规则），确定性编译器组合原语生成 SQL。LLM 只选原语，永不写 SQL。
- 输入规范：**给可执行的 SQL，别给描述性文字**；按问题拉取，不按库存推送。
- 验收含「非菜单证明」：两道从未做过卡的题必须靠组合答对并通过对账。

## 一 术语修正：场景 ≠ 数据域（2026-09 Jack 挑战确立）

| | 数仓数据域（官方分类） | 语义场景（本文） |
|---|---|---|
| 组织轴 | 按数据是什么分（名词） | 按业务想问什么分（动词性） |
| 服务对象 | 存储/治理/分工 | 消费/问答 |
| 例子 | 交易域 TR、用户域 CU、渠道域 CH | 注册场景、活跃场景 |

**方法论结论（进白皮书素材）**：语义场景横切数据域，两者不可混称。场景到数据域的映射表本身是交付物。

注册场景映射：

| 数据域 | 表 | 在场景中的角色 |
|---|---|---|
| TR 交易域 | dwd_tr_rgst_df | 注册事实（业务过程） |
| CU 用户域 | dim_cu_usr_info_df | 客户属性（性别/地域/归一身份） |
| CH 渠道域 | dim_ch_chl_df | 渠道维度（层级待确认） |

本体视角：注册是用户实体的动作（事件），场景是「关于该动作的问题」的打包，不是给动作划存储地盘。

## 二 核心机制：卡 → 原语 → 组合（回应「这只是查 SQL」）

### 2.1 四层递进

| 层级 | 机制 | 判定 |
|---|---|---|
| L0 报表菜单 | 预写 SQL 一问一答 | 死路（问题空间组合爆炸，人工枚举追不上） |
| L1 规则选择 | LLM 选规则 ID（当前 demo） | 安全但不可扩展，过渡态 |
| **L2 原语+受约束组合** | **度量 × 维度 × 时间粒度，确定性编译器生成 SQL** | **目标态，本体收益所在** |
| L3 自由 NL2SQL | LLM 直接写 SQL | 幻觉面失控，拒绝 |

### 2.2 提炼规则（卡片如何变原语）

每张确认后的口径卡拆解为：

| 卡片成分 | 提炼为原语 | 注册表示例 |
|---|---|---|
| 去重键 | 身份规则（实体粒度） | 用户数一律归一到 usr_id |
| 聚合表达式 | 度量（measure） | 注册用户数 = COUNT(DISTINCT usr_id) |
| GROUP BY 列 | 维度（dimension） | 渠道 / 性别 / 时间粒度 |
| JOIN | 链接（link） | 注册事件 → 渠道 |
| 源表+过滤 | 对象绑定 + 口径声明 | 事实表 + 有效期 |

示例：REG_BY_CHANNEL 与 GENDER_RATIO 两张卡 → 一个度量（注册用户数）+ 两个维度（渠道/性别）→ 新问题「分性别分渠道注册数」「按周注册趋势」零新人工 SQL，组合生成。

### 2.3 为什么必须先有卡再抽象

- 口径真相只存在于现行 SQL 里，字典里没有（干瘪是行业常态，语义在数仓同学脑子里）。
- 从已验证口径提炼的原语**继承正确性**——实体先行（124 表全量理解）已实证失败，问题先行不抽象则停在 L0/L1。middle-out = 两者合取。
- 安全边界不变：编译器是确定性代码，LLM 自由度 = 选原语 + 给参数。**智能在模型，正确在编译器，真相在已验证口径。**

### 2.4 不变量（governance 测试锁死）

| # | 不变量 | 内容 |
|---|---|---|
| I1 | 同源一致 | Σ分渠道 = 总数（热路径 vs 明细下推，1778/1781 拦截器先例） |
| I2 | 身份粒度 | 所有「用户数」度量 dedup 到归一身份，禁止混用 anony_id |
| I3 | 时间显式 | 默认时间字段必须显式声明（rgst_dt vs data_dt），禁止隐含 |
| I4 | 组合保真 | 编译产物在卡片参数子集上必须与卡片 SQL 数字相等 |
| I5 | 拒答完整 | 未注册原语的问题必须结构化拒答并说明，禁止静默降级 |

## 三 三层输入规范（回应「我该喂你什么」）

| 层 | 内容 | 格式 | 频率 | 状态 |
|---|---|---|---|---|
| L0 目录索引 | 三份数据字典 | 降级为目录：只承诺「找得到哪张表在哪个域」，不承诺字段级理解；理解笔记未确认字段全部标 unverified | 已有 | 完成 |
| L1 口径卡 | 每场景 5-8 张：官方 SQL + 六填空 | 填空模板（Rose 起草，数仓只改） | 每场景一次 | 待办 |
| L2 全局约定速查表 | 后缀语义（_DF/_DI）、四类 ID 生成/归一/失效规则、通用枚举码表、时区与刷新时刻 | 一页速查表 | 一次性，全域复用 | 待办 |

原则：**按问题拉取，不按库存推送**——场景外字段不读。无官方口径的题：Rose 起草 SQL、数仓确认、标「新定义」、Jack 拍板，第一期限量。

## 七 验收（场景级）

1. 圈选的每题有 confirmed 口径卡（数字对账通过）；
2. 原语注册表落地，I1-I5 不变量测试全绿；
3. **非菜单证明**：两道从未做过卡的题（如「8 月按周注册趋势」「分性别分渠道注册数」）由组合生成答案且对账通过——答不出 = 只是报表菜单，不验收；
4. 跨域问题（如 Q9 深入活跃）结构化拒答且指向正确扩展路径。
