# ADR 0008：S4 聚焦金控 + Agent 唯一入口 + 处长验收

- 状态：已接受（Jack 2026-08-27 拍板"开工"）
- 日期：2026-08-27

## 背景
S3 收口（tag v0.3.0）后项目陷入方向迷茫：零售与金控双演示并列无叙事关系；33 对象/54 表全量铺开没有重点；产品面（菜单+表格浏览器+Agent 藏在菜单里）与项目论点"为 Agent 而建"自相矛盾；DES、方法论呈现、血缘、规则配置什么都想要导致没有特色。Jack 判定"缺乏整体的产品规划"。

## 备选
- A：保留现状继续堆功能——否决，这就是问题本身。
- B：换回零售供应链场景——否决，场景平庸（同类 demo 泛滥）、S3 金控资产（33 对象/54 表口径/监管锚定）全部报废。
- C：聚焦金控风险一处场景 + Agent 对话唯一一级入口 + 剧本驱动 + 处长验收倒推——采纳。

## 决定
C。要点：口径真相源 = docs/v0.4-核心链口径包-v0.3.md；演示对象 = 中信金控风险合规部风险技术管理处处长（风险系统建设者），验收 = 5 分钟感受价值/显专业/看得出智能体优势；DES 降级为后台数据生产线；33 对象不删、12 进门面；零售收起；双观众结构（处长技术线 + 处务会业务线）。

## 理由
1. 真实业务背书：表结构源自真实风险系统 211 表字典脱敏，处长就是内部客户，专业性可验证。
2. 资产复用最大化：S3 的对象/动作/规则/数据管道全部保留，只做收敛与叙事重构。
3. 双模型对抗复核（豆包/DeepSeek）支撑：口径包已达"内行挑不出刺"标准，两条 P0 级剧本漏洞已在 v0.3 修复。

## 后果
- 正面：重点、特色、验收标准三者齐了；证据链+双签+真实写回的差异化在单一场景里能演透。
- 代价：S1/S3 部分界面收起；团队需补金控风险业务口径知识（已按四部法规锚定缓解）；剧本驱动意味着数据是道具，再生与剧本强耦合（用 verify 脚本锁住）。
- 风险：口径包成为单点真相源，必须随演示迭代同步维护；处长归口岗位理解若有偏差需回调选题（已按风险技术管理处定位）。
