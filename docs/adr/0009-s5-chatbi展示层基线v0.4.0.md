# ADR 0009：S5 ChatBI 展示层基线 v0.4.0（Agent 式交互范式定版）

- 状态：已接受（Jack 2026-09-09 实测初步通过，拍板打 tag 定基线）
- 日期：2026-09-09
- 关联：tag v0.4.0（落 06277d9）；docs/财富广场-ChatBI展示层产品设计_v0.2.md；docs/ChatBI-UX审查报告_v0.1.md

## 背景
2026-09-08 方向再锚后（财富广场数据分析体系 = 方法论第一落点），09-09 一天内走完：产品设计 v0.2（双外部模型对抗评审）→ 开发计划 → T1-T8 七任务（子代理交付、Rose 复核）→ T7 联调 → UX 审查报告 → Jack 实测提九条反馈 → 第二轮重构。九条反馈的共同指向：初版三级披露（L1 摘要条/L2 步骤/L3 抽屉）是"数据系统思维"，不是"Agent 产品思维"——过程展示位置、信息重复、话术僵化、编号暴露等问题全部由此派生。

## 备选
- A：保留 L1/L2/L3 三级披露结构，仅微调文案与位置——否决：不解决"过程在右上角、展开在数据下面"的反直觉布局，三处重复展示（卡内 L2、抽屉全记录、数据全量）仍在。
- B：整体重构为 Agent 惯例交互（思考流 + 审计抽屉两态）——采纳。
- 拒答话术：固定一句专业话术 vs 动态生成（命中词 + 可问清单 + 变体池）——选动态；查询历史 tab：保留 vs 删除（与会话列表重复）——选删除；数据全量 tab：保留 vs 删除后主卡加 TSV 复制——选后者。

## 决定
B 及三个子选择，全部落地：
1. **交互范式**：流式时思考区展开直播步骤（淡入）→ 首个回答 token 或 final 到达自动折叠为「已思考 N 步 · X.Xs」（耗时来自后端 final 帧 total_ms）→ 点击可再展开；数据在回答下方。用户手动操作过则尊重用户状态。
2. **信息归位**：决策过程只在消息卡思考区（怎么算的）；详情抽屉重定位为审计视图（凭什么信：口径/命中规则/校验记录/执行 SQL/证据编号+复制/总耗时）；req id 从卡面常驻撤进抽屉。
3. **命名**：产品定名「财富ThoughtSpot」（Jack 三选一后 custom 拍板），副标题「有过程 · 有依据 · 可溯源」。
4. **会话管理**：时间分组（今天/昨天/7 天内/更早）+ hover 快捷置顶 + ⋯ 菜单（重命名/置顶/收藏/归档/删除）+ 底部归档区（恢复/彻底删除）；归档=archived 列可恢复，区别于删除=hidden 物理保留。
5. **拒答动态化**：rules.build_reject_answer 变体池（seed=request_id 稳定）+ 命中词 + 可问清单从规则 label 单一来源生成；前端配可点示例 chips。无数字，不触 D6 门。
6. **v0.4.0 基线**：展示层定版，后续增量提交不回退交互范式；语义层为下一主线（Jack 亲做）。

## 理由
1. 对齐用户已养成的 Agent 心智（Claude/ChatGPT/DSH 的 thinking 折叠交互），零学习成本；未来数据量增大、决策链变长时该形态自然容纳（直播过程 → 折叠摘要）。
2. 每条反馈映射一个结构性根因，重构后"过程、凭据、数据"三者各只出现一次，认知负担最小。
3. D6 防幻觉不变量全程未动：数字仍只来自 rows/params 模板槽，拒答话术无数字。

## 后果
- 正面：展示层从"能演示"到"敢给人用"；pytest 15 / vitest 28 全绿定基线。
- 代价：删除了查询历史 tab 与数据全量 tab（后端 /api/history、/api/trace 保留，审计能力不丢）；conversations 表加 archived 列（migrate() pragma 探测自动补列）。
- 风险：**「财富ThoughtSpot」含 ThoughtSpot 商标词，对外发布（GitHub/公众号等）前必须 Jack 再确认**；「已思考 N 步」耗时依赖后端 total_ms，旧 trace 无此字段则不显示（降级安全）。
