## 0. 结论先行

1. **重写定位（修正 v0.1 的错误理解）**：不是「所有代码原创」，也不是「只借鉴思想」——是**把 nano-ontoprompt 的功能整体重写/移植进 OntoRun**：以它的功能清单为蓝本，全部**重新实现**，产出我们自己的代码库（目录/命名/结构/风格都按 OntoRun 来，**不照抄、不翻译、不让人看出是抄的**），**不重复造轮子**（它能直接借鉴的功能点直接做）。
2. **优先级**：重写框架 = 最高优先（对外发布 A、白皮书深化都依赖这个基础框架）。
3. **技术栈与 OntoRun 现有完全同构**，前端用**我们自己风格（AntD）**，不引入重服务。
4. **一次成功 = 跑通全链路**：原始数据→管道→Curated→自动映射→本体→LLM 动作→写回源系统→审计，测试全绿。

## 1. 重写边界与反抄袭准则（执行会话必读）

- **功能对齐**：目标能力以 nano-ontoprompt 为蓝本（数据管道三路径、自动映射、LLM 提取、质量审查、图谱），但**代码全是我们自己的**。
- **禁止**：复制/改写它的任何源文件；照抄函数名/变量名/注释；目录结构与它一致。
- **允许**：借鉴功能清单、接口形态、Palantir 设计原则（公共知识）、以及我们自己的研究（白皮书/B站笔记结论）。
- **风格**：遵循 OntoRun AGENTS.md 编码规范（Pydantic 风格、数据不可变、小文件、无硬编码）。
- **可复用**：OntoRun 现有 ontology/、runtime/、api/、agent/、web/ 基础组件直接复用扩展。

## 2. 技术栈定案（无待定项）

| 层 | 定案 | 说明 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2.0 + Alembic | 与现有一致；装包用 uv |
| 存储 | SQLite（元数据库 + 源系统库双库）；Postgres 仅配置位预留 | 不引入任何外部服务 |
| 图查询 | 默认**关系表（SQLite）实现**；**GrafitoDB 作为可选增强**（SQLite 内嵌、无服务器、纯 Python，已确认轻量；实现为可插拔 adapter，不设为硬依赖） | 优雅降级原则 |
| LLM | OpenAI 兼容 SDK + 现有 provider 热插拔（MVP=DeepSeek）；key 只走环境变量 | 复用 src/agent |
| 异步 | 同步执行；预留 Celery（发布期） | MVP 不引入 |
| 向量检索 | MVP 不做（关键词搜索先行） | 发布期如需再引入 |
| 前端 | React 18 + TS + Vite + **AntD（我们的风格）** + Cytoscape.js（图谱）+ @xyflow/react（管道画布）+ zustand + @tanstack/react-query | 复用现有 web/ 基础 |

## 3. 目录结构（OntoRun 扩展）

```
src/
├── ontology/        # [复用] 对象/链接/动作定义 + 注册表（Pydantic）
├── runtime/         # [复用] 索引/查询/动作引擎/审计/写回回路
├── api/             # [复用] FastAPI 语义接口（新增构建相关端点）
├── agent/           # [复用] provider 热插拔
├── app/             # [复用] 演示入口
└── builder/         # [新建] 本体构建子系统（本次重写核心）
    ├── connectors/  #   数据接入：文件/SQL/REST（MVP: 文件+CSV/Excel/JSON/MD）
    ├── pipeline/    #   转换管道：DAG 执行 + A/B/C 三路径步骤
    ├── curated/     #   Curated 数据集：质量评分 + 审核
    ├── mapping/     #   自动映射：数据集→对象类型/列→属性/外键→关系/基数
    ├── extraction/  #   LLM 提取：文档→实体/关系/动作 + 七道校验器
    └── logic/       #   逻辑规则发现 + 状态机
web/src/             # [扩展] 新增：管道画布/图谱视图/对象类型管理/数据浏览
data/                # [复用] 模拟数据 + 双库
tests/               # [扩展] 新增 builder 测试
```

## 4. 数据模型设计（新增表，均 SQLite，Alembic 迁移）

| 表 | 字段要点 | 说明 |
|---|---|---|
| object_types | id/ontology_id/name/name_cn/description/category(domain|artifact|conceptual)/property_schema(JSON)/source | **对象类型一等公民**（修反模式#2） |
| link_types | id/ontology_id/name/semantic_name/category(semantic|fk_inferred|structural)/source_type_id/target_type_id | 链接类型一等公民 |
| datasets | id/ontology_id/name/source/status/row_count/schema(JSON) | 原始数据集 |
| pipelines | id/ontology_id/name/dag(JSON)/status | 管道定义 |
| curated_datasets | id/dataset_id/quality_score(JSON)/status(draft|reviewed|approved)/version | Curated 结果 |
| mappings | id/ontology_id/entity_class/source_table/field_mapping(JSON)/fk_mappings(JSON)/status | 自动映射结果 |
| extraction_tasks | id/ontology_id/status/progress/result_summary | LLM 提取任务 |
| logic_rules | id/ontology_id/name/logic_type/expression(JSON)/severity/status | 逻辑规则（草稿→审核→发布） |
| action_types | id/ontology_id/name/parameters/submission_criteria/effects/status | 动作类型（对接现有 runtime） |
| action_runs | id/action_type_id/before_snapshot/after_snapshot/status/error | **审计快照**（对齐 Palantir function_runs） |

> 单一数据模型：实体表统一（概念/实例用 category 字段区分），**不做 v1/v2 双表**（修反模式#3）。

## 6. 分阶段实施（每阶段 TDD；每阶段结束跑 tests+lint；阶段间独立 red-team 审查）

| 阶段 | 任务 | 交付物/验收 |
|---|---|---|
| P0 骨架 | 读本蓝图 + AGENTS.md；建 builder/ 包骨架 + Alembic 迁移；定统一异常/响应格式 | 骨架可导入，迁移可跑 |
| P1 建模 | object_types/link_types 一等公民 + CRUD + 注册表接入现有 ontology/ | 单测 80%+ |
| P2 管道 | 文件连接器 + 三路径转换步骤 + DAG 执行 + 管道 API | 管道 E2E（CSV→Curated） |
| P3 映射+提取 | 自动映射（FK/格式容错/备用键）+ LLM 提取 + 七道校验器 + Curated 审核 | 映射/提取 E2E |
| P4 逻辑+动作 | 逻辑规则发现 + 状态机 + 动作类型（对接 runtime，补 before/after 快照） | 动作执行 E2E + 审计快照 |
| P5 前端 | 管道画布 + 图谱视图 + 对象类型管理 + 数据浏览（AntD 风格） | vitest + 手动验证 |
| P6 全链路 | 构建→运行时→写回回路打通 + 三问测试 + 白皮书「本体构建」章节 | E2E 全绿 + 验收 |

## 7. 复用 vs 新建 vs 重写 清单（执行会话据此分流）

- **复用（OntoRun 现有，直接扩展）**：ontology 注册表、runtime 动作引擎/审计/写回、agent provider、web 基础组件、data seed
- **新建（参考 nano 功能清单，全新实现）**：connectors、pipeline、curated、mapping、extraction+校验器、logic 发现、前端画布/图谱
- **重写（以 nano 为蓝本，功能对齐但代码全新）**：上述「新建」项的**功能规格**参照 nano 的 README/ONTOLOGY.md/优化计划，但实现全部自写

## 8. 关键设计决策（执行会话必须遵守）

1. **Object Type / Link Type 一等公民**（独立 schema，不散落字符串）
2. **单一数据模型**（实体/概念/实例用 category 字段，无 v1/v2 双表）
3. **领域驱动建模**（先建模后映射，禁止源列 1:1 Kitchen Sink；实体三分类：业务/过程/结果）
4. **动作引擎复用现有 runtime** + 补 before/after 快照审计（对齐 Palantir function_runs）
5. **LLM 输出七道校验**（结构/必填/引用完整/去重/类型白名单/语法/语义引用）——LLM 输出视为不可信输入
6. **优雅降级**（SQLite-first；GrafitoDB 可选 adapter；无外部服务可跑）
7. **草稿→审核→发布状态机**（对象类型/逻辑/动作上线前走审）
8. **provider 热插拔**（复用现有 src/agent）

## 9. 风险与预案

| 风险 | 预案 |
|---|---|
| 网络不稳（pip/npm） | 一律 uv + 清华/npmmirror 镜像；装包失败重试不换招 |
| GrafitoDB 不稳定/过重 | 可选 adapter，回退关系表实现，主链路不受影响 |
| LLM key 缺失 | 提取/语义链接用 mock 数据走通，标注需要 key 的步骤；key 只走环境变量 |
| 范围膨胀 | 严格按 P0-P6；发布期项（权限矩阵/多行业/MCP）一律 TODO 注释，不实现 |
| 执行会话中途卡住 | 优先自测自证（跑通最小用例再继续），不要停等；确实阻塞才在最终报告标注 |

## 10. 验收标准（一次成功的定义，全部满足才算完成）

1. **全链路跑通**：`python -m pytest tests/ -v` 全绿；前端 `npm run test` 全绿；lint/build 通过
2. **端到端演示**：一条 `CSV → 管道 → Curated → 自动映射 → 本体 → LLM 动作 → 写回源系统 → 审计` 链路的自动化脚本可运行
3. **三问测试继续通过**（现有写回回路不回归）
4. **审计含 before/after 快照**
5. **白皮书「本体构建方法论」章节有实质内容**（LLM 五流派 + 自动映射四技法，引用我们自己的研究）
6. **不依赖外部服务可跑**（SQLite-only；Docker 不是必需）
