# S3 M3 Agent 对话窗口 · 技术方案 v1

> 目标：让用户用自然语言问风险问题（精准答）+ 执行真实动作（双签+审计）。替代现有 AI 查询页。
> 依据：S3 方案 v1.0 + M2 本体（独立注册表）+ DES 数据（ap_anping 308k 行）+ S2 已验证设施（Agent/ContractExecutor/双签）。

## 一、现状盘点（S2 已验证设施）
- **Agent**（src/agent/agent.py）：LLM tool calling 编排 + 双签（high_risk 动作 LLM 提议→人工确认→执行）+ 会话持久化。现注册 S1 零售 6 动作。
- **ContractExecutor**（src/des/contract/executor.py）：受限结构化查询（契约 JSON→七道校验→执行）——**读引擎直接复用**。
- **RestActionExecutor**（src/app/main.py）：动作走 engine.execute() 统一写入口。
- **ObjectQuery**（src/runtime/query.py）：对象/链接遍历。

## 二、M3 三件事（M2 挂载适配 + 读引擎 + 写引擎）

### 2.1 挂载适配（M2 子代理文档化的 3 条）
1. **RiskCustomer 改名**：Customer → RiskCustomer（与 S1 零售 Customer 冲突，对齐 DES ErpCustomer 先例）；链接 inverse 前缀 customer. → risk_customer.。
2. **链接 prefix**：customer.belongs_to_group → risk_customer.belongs_to_group 等。
3. **9 个动作写回 handler**：confirm_warning / adjust_warning_level / submit_disposal / approve_disposal / push_warning / close_warning / adjust_concentration_limit / register_risk_project / update_risk_project_progress。

### 2.2 读引擎（精准问答）
- 复用 ContractExecutor：LLM 生成契约 JSON（对象/过滤/聚合/指标）→ 七道校验 → 执行 ap_anping 数据。
- 指标查询走 ap_dim_metric（维度指标物化）。
- 域外拒答：契约校验失败/可表达集外 → 明确 DECLINE + 引导可查项。

### 2.3 写引擎（动作模板）
- 9 个动作 handler：状态机校验（SignalStatus/DisposalStatus/ApproveOrderStatus）+ 前置校验 + 写回 SQLite + 审计 + 双签。
- 双签沿用：high_risk 动作（adjust_warning_level / submit_disposal / approve_disposal / close_warning / adjust_concentration_limit / update_risk_project_progress）LLM 提议→确认→执行。

### 2.4 数据源切换
- 对话/查询默认指向 ap_anping（data/des/enterprises/ap_anping/*.db）。
- 保持 S1/S2 共享注册表不动（风险用独立注册表）。

## 三、端点（替代/扩展现有 /agent）
- POST /agent/chat：用户消息 → LLM → （读）契约查询 / （写）动作提议 → 回复/双签
- POST /agent/confirm：双签确认/驳回 → 执行/取消 → 审计
- （读查询也可走现有 /objects/* 语义接口，数据源切 ap_anping）

## 四、验收（M3）
- 30 题评测集（docs/S3-M3-评测集30题-v1.md）：可表达集内答对 + 域外拒答
- 双签：高风险动作确认后才执行 + 审计留痕
- 数据源：ap_anping 308k 行可查
- P95 exec ≤500ms
- 增量测试（不跑全量）：评测集抽查 + 双签流 + 动作状态机

## 五、边界（遵守铁律）
- 子代理禁止跑全量 pytest
- 不破坏 S1/S2 共享注册表（风险独立）
- 动作 handler 用现有 engine 管道（统一写入口 + 审计）
- 每次 commit 英文 conventional
