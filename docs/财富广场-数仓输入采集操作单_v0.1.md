# 财富广场·数仓输入采集操作单 v0.1（给 Jack，一页）

> 配套方法论见 `docs/财富广场-注册场景middle-out落地方案_v0.1.md`（不用读）。本单只回答一件事：**你给 Rose 输入什么、怎么给**。

## 你的三个动作

| 步 | 动作 | 耗时 |
|---|---|---|
| 1 | 把下面的消息发给数仓同学（可原样转发，可改成你的口气） | 2 分钟 |
| 2 | 他回什么（文字/语音/截图/SQL 文件/表导出），**原样**丢进 `materials/fortune-warehouse-input/` 文件夹，不用整理不用命名 | 随手 |
| 3 | 等我出「三色清单」：绿=口径已确认可进语义层；黄=有冲突/多版本，列出来你拍板；红=还缺什么输入 | 我收到输入后 2 个工作日内 |

**形式不限，原样即可。** 整理、归类、追问、整理成口径卡全是 Rose 的活。唯一两个硬要求：SQL 必须是系统里真实在跑的（从调度/报表后台拷的，不是凭记忆写的）；对账数据必须给（权限或导出，二选一）。

## 给数仓同学的消息（直接转发）

```text
X 你好，我们在梳理注册相关的数据口径，想请你帮几个忙，都是小活不用写文档：

1.【注册数怎么算的】「每日/每月注册用户数」现在系统里是怎么算的？
   请从调度系统或报表后台把**在用的 SQL 原样拷一份**给我（有注释更好）。
   如果好几个地方都在算，每个都给我，注明哪个是正式报表在用的。

2.【渠道关联】注册明细表（dwd_tr_rgst_df）跟渠道维表是怎么关联的？
   如果某条注册记录的渠道编码在维表里找不到，这条记录会怎样？
   （丢掉 / 计入默认渠道 / 报错？）另外渠道维表有没有一级/二级层级？

3.【身份关联】匿名访客和注册用户在数据里怎么关联？
   DIM_CU_LOGIN_ANONY_MAPPING_DF 这张表怎么用？表名结尾 _DF 是什么意思？

4.【数据坑】注册相关的表里，有没有哪些字段看着能用、其实有坑？
   （比如渠道字段一堆默认值、时间字段另有业务含义）说 2-3 个最常见的就行。

5.【对账数据】我们想拿几天数据自己核一遍数。两个方案任选：
   a) 给个只读账号；b) 导出三张表各一份（2026-07-01 ~ 2026-08-31）：
      dwd_tr_rgst_df / dim_cu_usr_info_df / dim_ch_chl_df

这些整理完也是给你们沉淀口径文档，先谢了。
```

## 兜底：最小启动包

他实在忙，只给到这两样也开工，其余我先用现有字典推、推完找他验证：
- 第 1 条的 SQL（注册数的现行算法）；
- 第 5 条的对账数据（权限或三张表导出）。

## 我拿到输入后做什么（你不用管，备查）

1. 整理成口径卡，空缺项列追问清单给你转给他；
2. 用对账数据空跑：语义层数字 vs 数仓 SQL 数字逐条比对；
3. 出三色清单（见步 3），黄的由你拍板口径裁决号；
4. 确认后的口径提炼进语义层原语（原子指标/维度/修饰词，OneData 词汇）。
