# S4 M4 彩排设计书（内部派活文件）

> 触发：M3 联调收尾后执行。目的：在真处长之前，用多模型扮演「内行处长」轮番刁难，把演示打到问不倒。

## 一、被测对象
- 演示七幕剧本（口径包 v0.3 §七）的端到端走查：真实系统操作（后端 :8000 + 前端），不是纸面评审。
- 走查方式：主会话按剧本逐幕操作，记录每幕实际输出/截图文字描述，作为彩排输入。

## 二、扮演组合（火山 Coding Plan 套餐内，已冒烟验证）
- 豆包 doubao-seed-2.1-turbo —— 扮演「风险合规部业务骨干」视角
- DeepSeek deepseek-v4-pro —— 扮演「风险技术管理处处长」视角（懂系统懂业务、时间紧、挑剔）
- 供应商/模型覆盖已验证可用；彩排 search 预算 = 0（只读本地文件与走查记录）

## 三、处长人设 prompt 要点（两路共用）
- 身份：金控风险合规部风险技术管理处负责人，管全面风险管理信息系统建设 8 年；手上有 1104 报表/大额风险暴露报送/关联交易报送三大常规活；被业务处催过、被监管问过。
- 性格：不给面子，专挑「演示 coherent 但一戳就破」的地方；对「AI 答不上剧本外问题」零容忍但欣赏诚实拒答。
- 行为：每幕看完提 1-2 个刁钻问题（如「天晟在全部集团客户里排第几？」「这条预警谁确认的？多久超期了？」「恒昌的认定依据拿给我们合规部看能过吗？」），并对以下维度打分 1-5：价值感知 / 专业度 / 智能体优势 / 玩具感（反向）。

## 四、评分与通过线
- 四维均 ≥4 且无「一戳就破」级发现 = 彩排通过；否则修复后第二轮复测（最多两轮，两轮不过 = 升级给 Jack 议）。
- 输出：per-model 彩排报告（docs/s4-rehearsal/）+ 汇聚修复清单 + 修复提交。

## 五、流程
1. 主会话七幕走查 → 生成走查记录（docs/s4-rehearsal/walkthrough.md）
2. 双模型并行彩排（workflow agent，provider 覆盖）
3. 汇聚 → 修复 → 第二轮复测（如需）
4. 通过 → 报 Jack 安排 M5
