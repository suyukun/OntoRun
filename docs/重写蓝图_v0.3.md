## 0. 结论先行（含灵魂问题的答案）

1. **重写定位**：把 nano-ontoprompt 的**精华**重写/移植进 OntoRun，**不是全量照搬**。经独立评估，它 = 「功能清单 + 踩坑记录」：功能广度堆叠、深度不足（320 测试均为浅层、7 个挂、E2E 脚本有 bug、v1/v2 双模型是自认的反模式）。
2. **范围收敛原则**：只吸收下面「精华清单」，其余全部不做——不做平台、不做功能堆叠、不引入重服务。
3. **优先级**：重写框架 = 最高（对外发布、白皮书深化都依赖它）。
4. **技术栈与 OntoRun 现有完全同构**；前端用我们自己风格（AntD）；**图查询默认关系表（SQLite），不引入任何图数据库/向量库**；外部服务一律不依赖。
5. **一次成功 = 全链路跑通**：原始数据→管道→Curated→自动映射→本体→LLM 动作→写回源系统→审计，测试全绿。

## 1. 精华清单（本次重写吸收什么）与弃疗清单（明确不做）

### 1.1 精华清单（吸收，全部重写实现）

| # | 能力 | 说明 |
|---|---|---|
| E1 | 三路径转换管道 | 结构化（CSV/Excel schema 推断+清洗）/ 半结构化（JSON 拍平/XML 解析）/ 非结构化（文档→MD→LLM 或规则结构化） |
| E2 | 自动映射四技法 | FK 检测 / 值格式容错（SUP-001↔SUP001）/ 备用键匹配（文档提及→实体）/ 基数推断 |
| E3 | LLM 提取 + 七道校验 | 文档→实体/关系/动作；校验：结构/必填/引用完整/去重/类型白名单/语法/语义引用（LLM 输出不可信） |
| E4 | 草稿→审核→发布状态机 | 对象类型/逻辑/动作上线前走审，published 才能被运行时执行 |
| E5 | 优雅降级 | SQLite-first；所有可选能力缺失时回退，本地零依赖可跑 |
| E6 | before/after 快照审计 | 动作执行记录变更前后快照（对齐 Palantir function_runs），并入现有审计 |
| E7 | 宽表拆分 + 增量更新 | 大宽表按实体拆分；增量同步/处理/索引三层配合（构建期细节） |

- ❌ 多语言 UI / RDF 导出 / 用户管理全家桶 / 导出全家桶（不做功能堆叠）
- ❌ 前端截图 demo 风格 / 华丽仪表盘（重真实可交互，不重外表）
- ❌ 多租户、权限矩阵、多行业模板、MCP 传输层（发布期项，一律 TODO 注释）

## 6. E1 三路径管道规格（P2 执行依据）

DAG 节点类型：connector → storage → transform → output。每节点：输入/输出 schema + 处理函数 + 逐节点状态。

| 路径 | 输入 | 处理步骤（自写实现） | 输出 |
|---|---|---|---|
| A 结构化 | CSV/Excel | 1) schema 推断（列名/类型/非空率） 2) 清洗（去重/类型纠正/空值策略） | 干净表 → Curated |
| B 半结构化 | JSON/XML | 1) JSON 拍平（Explode 嵌套数组→独立行） 2) XML 解析为行集 | 多张关联表 |
| C 非结构化 | MD/PDF/DOCX | 1) 转 Markdown（markitdown） 2) MD 结构化提取（表/标题/段落 → 行） 3) LLM 可选提炼 | 结构化表（每行带源引用） |

## 7. E2 自动映射规格（P3 执行依据）

1. **字段推断**：列名→属性名（snake_case→PascalCase 属性）、列类型→属性类型、is_technical 标记（纯 ID/时间戳列隐藏）
2. **FK 检测**：跨表主键/外键同名或含实体名推断链接，自动推断基数（1:1/1:N/M:N）
3. **值格式容错**：对前缀+序号（SUP-001 ↔ SUP001）归一后匹配
4. **备用键匹配**：文档提及的自然语言名称（公司名）→ 实体（可选 LLM 辅助，需要 key）
5. **宽表拆分**：一实体对应一表；大宽表按业务实体拆分（规则+LLM 辅助，需人工复核）
6. **映射审批**：自动生成映射 → 人工审核 → apply 写入本体注册表

## 8. E3 七道校验器规格（P3 执行依据）

LLM 提取输出（entities/relations/logic_rules/actions）入库前逐道校验，四级严重度（fatal/error/warning/info）：
1. 结构（合法 JSON、必含 entities 数组）
2. 必填字段（实体 name/type、关系 source/target/type、动作 name）
3. 引用完整性（关系两端必须指向存在的实体）
4. 去重（按 (name,type) 与 (source,type,target) 去重）
5. 类型白名单（实体类型在预设域集合内，>50% 自定义则告警）
6. 语法校验（动作 function_code 用 ast.parse）
7. 语义引用（linked_entities/linked_logic 指向真实存在项）

## 10. 关键设计决策（执行会话必须遵守）

1. Object Type / Link Type 一等公民（独立 schema，不散落字符串）
2. 单一数据模型（实体/概念/实例用 category 字段，无 v1/v2 双表）
3. 领域驱动建模（先建模后映射，禁止 1:1 Kitchen Sink；实体三分类：业务/过程/结果）
4. 动作引擎复用现有 runtime + before/after 快照审计（E6）
5. LLM 输出七道校验（E3），LLM 输出视为不可信输入
6. 优雅降级（SQLite-first，无外部服务依赖）
7. 草稿→审核→发布状态机（E4）
8. provider 热插拔（复用 src/agent）
9. 图查询用关系表，不做图数据库/向量库（收敛）
10. 只做精华清单 E1-E7，弃疗清单一律不做

## 11. 风险与预案

| 风险 | 预案 |
|---|---|
| 网络不稳（pip/npm） | 一律 uv + 清华/npmmirror 镜像；装包失败重试不换招 |

| markitdown 等转换依赖 | 缺则 C 路径降级为「手动/规则结构化」，不阻塞 A/B 路径 |

## 12. 验收标准（一次成功的定义，全部满足才算完成）

1. `python -m pytest tests/ -v` 全绿；前端 `npm run test` 全绿；lint/build 通过
2. **端到端演示脚本**：一条 `CSV → 管道 → Curated → 自动映射 → 本体 → LLM 动作 → 写回源系统 → 审计` 链路自动化可运行
3. **三问测试继续通过**（现有写回回路不回归）
4. 审计含 before/after 快照（E6）
5. 白皮书「本体构建方法论」章节有实质内容（LLM 五流派 + 自动映射四技法 + 三路径管道）
6. **不依赖任何外部服务可跑**（SQLite-only；无 Docker、无图库/向量库/队列）
