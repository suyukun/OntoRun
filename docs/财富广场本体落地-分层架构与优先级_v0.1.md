## 二、层间关系

一条「定义下行、事实上行」的链，每层只干一件事，且只信下一层的返回：

| 层 | 一句话职责 | 财富广场侧现状 |
|---|---|---|
| ① 展示 UX | 人看 / 人问 | 月报展示层（Slidev）+ OntoRun ChatBI 对话框，**两壳互不相通** |
| ② LLM/Agent | 人话 ↔ 语义查询的翻译，无权发明答案 | 无（OntoRun B 方案契约可搬） |
| ③ 语义接口 | 边界：只放行本体可表达的查询，**幻觉死在这层** | 无（固化期建） |
| ④ 本体运行时 | 忠实执行 ⑤ 的定义去算数，不解释业务 | OntoRun 全套资产可搬 |
| ⑤ 语义层 | **定义**：对象/链接/映射/口径规则 | 仅 metrics.md 口径库雏形（人读文档，需结构化） |
| ⑥ 数据/源系统 | 事实的存放 | 真数据散在各系统，每月人肉进月报，无来源登记 |

治幻觉机制 = 「每层只信下一层」：任何一层输出不合格，上层只能拒答，不能编。

## 三、优先级：只有 ⑤ 必做，⑥ 必喂，其余全部可缺席

| 层 | 不做会怎样 | 结论 |
|---|---|---|
| ⑤ 语义层 | 退化成传统 BI 或裸 NL2SQL，不再是本体论落地 | **唯一必做**。无需工程即可开工（纸 + metrics.md + 问题台账）；④③②全等它的定义 |
| ⑥ 数据 | 没数可算，体系空转 | **必喂但不用建**：数据已存在，「做」=纪律（登记来源 + 定期拿到），人肉起步 |
| ④ 运行时 | 永远手工跑——不可持续，但可验证 | 固化期（落地第 3 步）才建 |
| ③ 语义接口 | 上 LLM 前必须补（幻觉闸门）；手工期「接口」= Jack 与 Rose 的对话 | ChatBI 之前必须有 |
| ② LLM/Agent | 无自然语言入口，体系照跑（手工查） | 放大器，不是地基 |
| ① 展示 | 已有两壳 | 现阶段零新建 |

**最小可跑通体系 = ⑤ ＋ 人肉 ⑥ ＋ 一个看答案的人。**
= 落地三步走的第 2 步（手工跑出第一个答案）的架构学解释。

## 四、纪律（防滑坡）

1. 领域是组织方式（命名空间），不是开工范围——对象按领域标准命名（「客户」不叫「导流任务客户」），开工范围永远 = 第一问的最小切片。
2. 第一刀产出形态 = 可追问、口径一致的问答切片，不是报表、不是裸 NL2SQL。
3. 手工期先摸清「语义层该固化什么」，摸清再固化——不摸清就固化，固化的是垃圾。
4. 盘点齐全≠每层都补。开工点永远是最小切片，其他层是它的下游。
