# des-enterprise-modeling：DES 企业模拟编排器

> 定位：DES 的标准调研执行器。每次生成企业必须走完本 skill 定义的 6 步，每步有标准依据、必交产物、校验项。
> 产出 = 业务调研资产（初稿，不具约束力）；本体（M2）是执行真相源。确定性只承诺"生成段"（第 5 步）；调研段产物冻结后进入生成。

## 六步流水线（强制顺序）

### STEP 1 企业画像（TOGAF 业务架构）
- 标准：TOGAF Business Architecture（业务能力地图 Business Capability Map）
- 输入：行业关键词 + 企业类型（如"金控集团/全牌照"）
- 产出：企业档案（名称/牌照/组织/子公司/业务背景/经营故事）+ 业务能力地图
- 校验：名称虚构不撞真实企业；业务板块与"全牌照"匹配；经营故事有因果（为什么是这几块业务）
- 模板：企业档案 JSON + 业务能力清单

### STEP 2 业务域建模（DDD 限界上下文）
- 标准：DDD（Bounded Context / Ubiquitous Language）
- 输入：STEP 1 画像 + 表结构参考（如有）
- 产出：业务域清单（每个域：名称/边界/核心实体/通用语言词表）
- 校验：域边界不重叠；实体归属唯一；通用语言与表字段语义对齐
- 模板：业务域 JSON + 实体清单

### STEP 3 业务流程建模（BPMN 2.0 分级）
- 标准：BPMN 2.0（Level 1 描述性 → Level 2 分析性 → Level 3 端到端）
- 输入：STEP 2 业务域 + 核心业务链路
- 产出：核心流程（事件/活动/网关/泳道）+ 状态机（状态/迁移/触发条件）
- 校验：流程有始有终；状态迁移有确定性触发；无死循环
- 模板：流程 JSON + 状态机 JSON

### STEP 4 业务规则建模（DMN 决策表）
- 标准：DMN（Decision Model and Notation）+ pyDMNrules 规则引擎
- 输入：STEP 3 流程 + 领域规则知识
- 产出：规则集（决策表：条件/动作；如预警等级判定、五级分类、编码规则、集中度阈值）
- 校验：规则可被 pyDMNrules 执行；决策表无歧义（同一输入不命多条规则）
- 模板：规则 JSON（DMN 兼容）

### STEP 5 确定性数据生成
- 标准：DES 现有确定性基建（固定 seed + manifest 校验 + 配置驱动）
- 输入：STEP 1-4 冻结资产 + 表结构定义（YAML）
- 产出：N 系统模拟数据（SQLite 落盘）+ manifest
- 校验：行数/sha256/外键完整性（复用 S2 manifest 逻辑）
- **此步必须完全确定性**（固定 seed）；调研段产物冻结后才进入本步

### STEP 6 质量门禁（SynEval 多维评估）
- 标准：SynEval 多维框架（Fidelity 保真 / Utility 可用性 / Consistency 一致性）
- 输入：STEP 5 数据 + STEP 1-4 资产 + 领域知识
- 产出：质量报告（每表行数 / 规则命中率 / 外键完整性 / 字段语义一致性 / 分布合理性）
- 校验：rows-per-object 健康指标（核心表 ≥3-5 万行）；规则全部命中；无空对象
- 门禁：任一项不达标 → 回退到对应 STEP 修正，不进入交付

## 三、质量约束（每次强制执行）
1. **单一事实来源**：调研段产出（STEP 1-4）是"初稿"，M2 本体有权重定义；DES 不产与本体同构的执行定义（状态机/前置校验归本体）。
2. **确定性边界**：STEP 1-4 可 LLM 辅助（非确定），但冻结后（版本化文件）才进 STEP 5；STEP 5 必须固定 seed。
3. **不依赖个人经验**：业务知识来源 = 方法论标准 + 网络调研 + 表结构字典，不依赖任何个人。
4. **研究对象锚定**：每份资产要能回答"这支撑了语义接口/本体落地的什么验证"。

## 四、交付物
- 企业模拟资产包（ap_enterprise/）：profile.json（画像）、domains.json（业务域）、flows.json（流程+状态机）、rules.json（规则集）、schema.yaml（表结构）、data/（SQLite）、manifest.json、quality_report.json（质量）
- 全部可复现（seed 固定 + manifest 校验）
