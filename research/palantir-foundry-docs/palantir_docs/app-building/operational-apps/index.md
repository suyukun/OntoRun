# 什么是运营应用程序？

在Palantir，我们经常将某些工作流程和应用程序称为“运营”。这是什么意思？

一个运营应用程序用于推动特定的决策过程，并允许用户通过数据输出来捕获他们的决策。虽然传统的仪表盘和报告侧重于为用户提供只读的见解，但运营应用程序使用户能够采取操作。

通常，我们发现推动决策的工作流程更有可能获得用户的采用并影响组织结果。此页面的其余部分描述了如何使用Foundry的应用程序搭建功能在实践中创建运营应用程序。

## 操作类型

在Foundry Ontology中，操作类型提供了一种集中、管理的方式，以定义组织中的用户如何将数据写回系统。在配置操作类型时，您可以定义用户将输入的参数，并灵活地配置用户将看到的表单，包括丰富的选项以创建子部分、描述等。

通过使用提交标准来控制谁可以执行哪些操作，从而管理确保数据仅根据您组织的约束进行写入的规则，规则可以是任何复杂程度。

除了基本的表单输入工作流程外，操作类型还支持一系列高级选项：

- 上传附件允许用户在提交信息时捕获图像、PDF或其他文件。
- 副作用允许用户发送通知（包括通过电子邮件），或协调将数据从Foundry发送到其他系统，使用Webhooks。
- 函数支持的操作允许您使用代码定义任意复杂的操作类型，以定义对象应如何更改。
## 在应用程序中使用操作类型

一旦在Ontology中定义了操作类型，在Foundry的应用程序搭建工具中使用它是无缝的。Workshop和Slate都原生支持将操作表单直接嵌入面向用户的应用程序中。

- 在Workshop中，按钮组微件可以配置为让用户轻松地将数据提交回平台。
- 在Slate中，操作微件向用户展示一个操作表单。您可以将其嵌入在对话框中以模拟Workshop体验，或根据需要将其编织到您的应用程序中。
- 如果您有兴趣完全在Foundry的应用程序搭建框架之外开发自定义应用程序，您可以使用Foundry的REST API搜索和应用操作。
## 结论

在数据集成和管理上的投资使组织中的运营人员能够使用数据做出更好的决策，并将这些决策捕获到系统中以便进一步学习。您可以使用Foundry的Ontology和应用程序搭建功能在短短数小时内创建闭环工作流程。
