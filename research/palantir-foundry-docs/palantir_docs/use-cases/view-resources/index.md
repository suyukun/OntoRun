# 查看资源

一旦创建了新的应用案例，可以在应用案例概览页面查看连接的应用和Ontology资源。如果是从现有的备份项目中创建的应用案例，这些资源会自动出现在你的应用案例中。如果是通过新的应用案例创建的新项目，则需要在查看它们及其连接的Ontology组件之前添加应用资源或数据源。

应用案例概览提供了包括应用案例工作流描述、应用案例所有者名称以及应用案例状态在内的元数据。概览还包含应用、Ontology和备份数据资源的部分。Ontology资源按Object类型和操作类型分类。选择概览或左侧边栏中的部分标题以打开资源页面。

## 查看应用

在应用页面，你将找到为应用案例创建或通过现有项目引入的所有应用资源，包括Workshop模块、Slate文档和Quiver分析。在下面的例子中，我们的应用案例包括两个Workshop模块和一个Slate文档。

选择应用资源的名称以打开应用页面。

在应用页面，你可以查看此应用使用的Object类型以及其他使用该Object类型的应用。

应用案例应用列表中的操作菜单允许直接导航到用于创建该资源的Foundry应用。要修改应用资源，将鼠标悬停在表格中的任意行上并选择编辑应用。

## 查看Ontology组件

应用案例Ontology资源包括Object和操作类型。在应用案例中的应用中引用的Object类型和操作类型将自动填充为应用案例中的Ontology资源。

了解更多关于创建Ontology组件的信息。

### Object类型

在Object类型页面，你将找到应用案例中任何应用使用的所有Object类型。继续上面的例子，我们的两个Workshop模块应用中使用了几个Object类型。

Object类型列表中的操作菜单允许直接导航到Ontology Manager应用以编辑Object类型的定义。你也可以选择移除以删除任何手动添加但未被应用案例中的任何应用使用的Object类型。

表格中列出的Object类型可能包括以下指示器：

- Object类型状态：状态为实验性或已弃用的Object类型将在行上显示状态标签。没有状态标签的Object类型处于活跃状态。
- 共享/本地状态：支持应用案例项目中的数据源的Object类型将显示本地标签。没有本地标签的Object类型由不同于应用案例项目的数据源支持。
当一个Object类型标有本地标签但也被不在此应用案例中的应用使用时，将出现警告指示器，建议将应用案例的所有备份数据集移至共享的Ontology项目中。

选择一个Object类型以查看有关资源的更多详细信息，包括属性、数据源和源系统详细信息。在下面的例子中，我们可以看到有关FlightObject类型的更多详细信息。

点击在Ontology Manager中查看和编辑以在Ontology Manager应用中打开Object类型。

了解更多关于编辑Object类型和导航到Ontology Manager及返回的信息。

### 操作类型

在操作类型页面，你将找到Ontology中与应用案例中的应用资源相关的所有操作类型。

操作类型列表中的操作菜单允许直接导航到Ontology Manager应用以编辑操作类型的定义。你也可以选择移除以删除任何手动添加但未被应用案例中的任何应用使用的操作类型。

表格中列出的操作类型可能包括以下指示器：

操作类型状态：状态为实验性或已弃用的操作类型将在行上显示状态标签。没有状态标签的操作类型处于活跃状态。

了解更多关于创建Ontology的信息。

## 查看数据源

备份数据部分提供了填充应用案例中使用的Ontology Object类型的数据源列表。选择一个数据源以在数据集预览中查看。

备份数据列表中的操作菜单允许打开输入和数据输出数据源的数据沿袭图。你还可以看到为该数据源提供数据的通过更新资源。

表格中列出的备份数据源可能包括以下指示器：

Object类型状态：状态为实验性或已弃用的Object类型将在行上显示标签。请注意，没有状态标签的Object类型处于活跃状态。

数据输出指示器：当一个数据输出数据源存在但位于不同的项目中时，输入数据源和信息指示器将显示在行上。

了解更多关于在Foundry中连接到数据和在Pipeline Builder中创建管道的信息。
