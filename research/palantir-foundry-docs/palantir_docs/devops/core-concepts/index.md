# 核心概念

本页面描述了支持 Foundry DevOps 和 Foundry Marketplace 的核心概念。我们建议您在继续之前阅读此页面，因为 Foundry DevOps 和 Marketplace 使用了专业术语（例如，“产品”）。

## 产品

在 Foundry DevOps 中，“产品”是产品构建者提供安装的 Foundry 资源集合。构建者可以在Foundry DevOps中创建新产品。

示例产品类型包括：

- Ontology：Foundry Ontology 的一个实例，可以是综合标准行业ontology或者是一个 ontology 片段。
- 应用案例：应用案例可以简单到单个Workshop 应用程序，也可以涉及多个 Workshop 应用程序、Functions 函数和Carbon 工作区的组合。
- Pipeline：Pipelines 可以从单个数据变换到许多变换和数据连接的序列。
- 建模：容器化的可执行模型，封装任何功能逻辑，包括机器学习、预测、优化、物理模型和业务规则。
每个产品都有输出，或称为内容，这是在安装产品时生成的。产品可能需要安装者映射输入以生成输出内容。

产品是用户可以通过 Marketplace 商店前端浏览和安装的基本单位。

## 产品版本

产品构建者每次想要调整现有产品内容或添加新产品内容时，创建并发布新版本。在安装时，我们通常建议选择最新的产品版本。当新产品版本可用时，安装者可以手动升级或选择自动接收新版本。

## 商店

商店是产品的集合；这些产品通常具有共同的目的。产品构建者可以将新产品发布到商店。您在 Foundry 实例中看到的商店可能是本地的（例如，由在您的组织内在您的 Foundry 实例上工作的构建者生成）或远程的（例如，所有 Foundry 用户都可用并由 Palantir 维护的Foundry Store）。

## 安装

当安装者满足产品的必需输入（如果有）时，就会创建一个安装。每个产品可以多次安装。通常在以下情况下创建多个安装：

- 不同用户组需要一个产品。例如，您可能会在各种支持团队中安装票务管理产品，使用他们的票务数据作为输入。
- 您需要为不同的开发环境创建一个安装。例如，您可能会将票务管理产品安装到预生产空间和ontology，然后再安装到生产空间和 ontology，每个都有自己的输入数据和环境特定设置，例如发布渠道和升级窗口。
