# 安全和权限

Automate 应用程序受与平台其他部分相同的安全和权限模型的管理。这意味着用户只能查看和与他们有访问权限的自动化进行交互。此外，条件评估和效果执行使用自动化所有者或特定通知接收人的权限。这确保了条件评估和任何后续操作或通知效果始终反映用户在自动化评估时的数据访问。

在操作效果中定义的操作总是代表自动化的所有者执行，但通知效果使用每个特定通知接收人的权限。这意味着自动化可能会触发一个用户但不会触发另一个用户，这取决于每个定义接收人的权限。接收人可能还会收到不同的通知，因为基于函数的通知是针对每个用户确定的。同样，附件也是为每个个人呈现的。

这一点可以通过一个例子来最好地说明：想象一个由受限视图支持的销售机会Object类型。根据用户的权限，他们可能能够访问来自欧洲或美国的销售机会。您可以配置一个自动化，通过使用对象添加到集合条件来在新的销售机会对象被添加时通知用户。现在，当来自欧洲的新销售机会到达时，条件将根据接收人进行评估。无法查看来自欧洲的销售机会的用户将不会在自动化上看到任何活动；不会显示条件事件，也不会发送通知。然而，其他有权限查看这些销售机会的接收人将按预期收到通知。

当用户编辑自动化并保存时，他们将始终成为新所有者（从前一个所有者那里获得所有权）。这意味着操作效果将在未来代表他们执行。在这种情况下，会出现警告消息。
