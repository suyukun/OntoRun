# 评估延迟

Automate应用程序为对象集条件提供了两种不同的监控延迟模式：实时监控和计划监控。

## 实时监控

当对象集进行实时监控时，保证在对象更改显示在Ontology中的几分钟内进行评估。这意味着Automate应用程序在捕捉到更改之前，Ontology索引操作必须完成。

然而，并非所有对象集定义都支持实时监控。一个先决条件是对象类型要由对象存储V2支持。此外，实时监控不支持以下功能：

- 相对时间条件
- 多于一个对象类型
- 合并对象集
- 某些筛选类型如前缀、术语和短语
- 函数生成的对象集
如果您已将对象类型从对象存储V1迁移到对象存储V2，并希望使用实时监控，您必须在迁移后重新保存自动化。这将使Automate应用程序能够捕捉到更改并启用实时监控。

## 计划监控

计划监控根据用户定义的时间表评估条件。当不支持实时监控时，条件将默认为计划监控。此时，计划监控标签将解释是哪种功能阻止了实时监控的启用。

大多数支持实时监控的条件也提供切换到计划监控的选项，可以通过切换评估延迟或添加计划来实现。这使您可以在特定时间点或定期检查对象集条件。

摘要电子邮件是计划监控的一个典型应用案例。例如，假设我们希望在每周的开始收到上周创建的所有支持工单对象的列表。如果没有新的支持工单，我们不希望收到通知。

我们可以通过使用计划监控来实现这一点。在这个例子中，我们为包含所有支持工单对象的添加对象条件添加了一个周一上午8:00的计划。然后，我们只需添加一个通知效果来呈现上周创建的所有支持工单对象的列表。
