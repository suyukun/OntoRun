# 自动化

自动化是一个完全向后兼容的产品，替代了Object监测，成为平台中所有业务自动化的唯一入口。

自动化是一个用于设置业务自动化的应用程序。自动化应用程序允许用户定义条件和效果。条件会被持续检查，当指定条件满足时，效果会自动执行。

条件可以是静态时间条件（“每周一上午9点触发”）、基于Foundry Ontology的Object数据条件（“当一个新的优先级为高的警报Object被添加时触发”），或者是静态和Object数据条件的组合。

可配置的效果包括提交Foundry操作以及发送带有附件的平台和电子邮件通知给用户。

## 应用案例

自动化可以被用于在不同的自动化工作流中，包括：

- 定期报告发送和摘要:指定一个时间并将每周报告发送给预定义的收件人列表。由Notepad或Notepad模板生成的PDF可以自动附加到电子邮件中。
- 数据警报:定义并监测对象集，当特定数据条件满足时警报用户；例如，当开放问题对象的总数超过阈值时。
- 工作流自动化:自动化可以被用于在符合指定标准的Object数据上自动执行操作。可以自动化的一些任务包括：检查数据异常并自动将这些对象传递到具有逻辑以解决问题的操作中。监测建议或潜在操作，当预配置的事件和时间条件满足时自动应用它们。这类操作可以包括通过Webhooks向外部系统发出API调用，直接在外部系统中进行更改。
- 检查数据异常并自动将这些对象传递到具有逻辑以解决问题的操作中。
- 监测建议或潜在操作，当预配置的事件和时间条件满足时自动应用它们。这类操作可以包括通过Webhooks向外部系统发出API调用，直接在外部系统中进行更改。
- 监测的搜索:配置自动化以在保存的Object探索有新结果时或当聚合标准在所有搜索结果中满足时通知；例如，当所有传感器Object的最大温度超过阈值时。
## 访问自动化

要访问自动化应用程序，请点击Foundry导航侧栏中的名称或图标。按照创建您的第一个自动化部分中列出的说明开始操作。

自动化是为业务自动化而设计的。如果您在寻找数据连接和管道搭建的健康监测，请参阅数据健康文档。
