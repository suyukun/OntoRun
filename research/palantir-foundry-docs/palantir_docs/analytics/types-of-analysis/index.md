# 分析类型

Foundry 分析套件支持点选分析（无代码或低代码）和基于代码的数据分析，提供针对不同分析和数据源类型优化的工具，以及用于仪表盘和报告的工具。

以下是工具和支持的工作流摘要：

|  | 点选分析 | 基于代码的分析 |
| --- | --- | --- |
| 表格数据 | Contour | Code Workbook |
| 对象数据 | Quiver, Object Explorer |  |
| 时间序列数据 | Quiver | Code Workbook |
| 地图（地理空间）数据 | Map, Contour, Quiver |  |

## 点选分析

Foundry 提供两个主要的点选分析工具：Contour 和 Quiver。每个工具都针对特定类型的数据源进行设计。

Contour 允许用户对大规模的表格数据进行数据分析，而 Quiver 则针对处理对象和时间序列数据进行了优化。此外，Foundry 的 Object Explorer 应用程序是一个用于Ontology 层的搜索和分析工具，可以与 Quiver 结合使用以进行强大的基于对象的分析。

Contour 和 Quiver 都允许您：

- 可视化、筛选和变换数据，无需代码。
- 利用表达语言进行更高级的变换和聚合。
- 组织复杂的分析。
- 参数化分析，轻松在不同的数据视图和结果之间切换。
- 创建交互式仪表盘，让他人能够以指导性、结构化的方式探索和调查数据。
- 与同事分享分析。
了解更多关于这些工具优化的具体应用案例。

### Contour

Contour 适用于以下分析应用案例：

- 您想使用的数据有一部分或全部未在 Ontology 中映射。通常，我们建议尽可能使用Ontology 层，但在某些情况下可能不适用，例如一次性上传且不需要清理或重用的数据。
- 您需要处理非常大的数据集。Contour 被设计用于促进对非常大数据集的分析操作，而 Quiver 支持对象聚合最多达 50,000 行。
- 您希望将分析结果作为新数据集共享以供其他 Foundry 工具使用。了解更多关于将结果保存为数据集的信息。
了解如何开始使用 Contour。

### Quiver

Quiver 适用于以下分析应用案例：

- 您的数据已在 Ontology 中映射。对象之间的链接在 Ontology 中被原生表示，因此 Quiver 用户不必进行合并或担心识别主键或外键。合并作为链接表示，通过对对象或对象集执行Search Around来返回任何链接的对象。
- 您正在处理时间序列数据。Quiver 已针对处理时间序列数据进行了优化。Quiver 包含一个特定的时间序列库，具备传感器和信号处理功能，并可以由专有的时间序列数据库支持，该数据库已针对高频信号的特定操作进行了优化。有关更多信息，请参见时间序列分析。
- 您希望将发现嵌入到其他对象感知的应用程序中。Quiver 仪表盘可以嵌入到操作应用程序中，如Workshop。
- 您希望将分析结果写回到 Ontology。Quiver 可以使用操作将分析决策写回到 Ontology 中。这使您能够立即捕获分析结论供他人使用。
了解如何开始使用 Quiver。

### Object Explorer

用户可以在Object Explorer中进行简单的基于对象的分析工作流。Object Explorer 是一个用于回答 Ontology 层中任何问题的搜索和分析工具。用户可以在 Object Explorer 中可视化地组合搜索查询，从简单的筛选到 Search Arounds 以找到感兴趣的对象。在 Object Explorer 中起始后，用户可以转到 Quiver 进行更复杂的分析或保存分析逻辑。Object Explorer 适用于以下分析工作流：

- 您希望探索对象类型及其属性。Object Explorer 是查找相关对象数据或特定对象实例的良好起点。
- 您的最终目标是创建相关对象的列表（对象集）。Object Explorer 可以创建对象探索和对象列表，以便与他人分享或在其他应用程序如 Quiver 中使用以进行进一步分析。了解更多关于探索和对象列表的信息。
- 您不想创建一个仪表盘来展示您的发现。如果您希望从分析中创建更长期的内容，例如仪表盘，Quiver 更适合。了解更多关于 Quiver 中的仪表盘的信息。
- 您不需要保存您的分析或逻辑以供重用。Quiver 更适合您希望参数化分析以便其他合作者可以更改输入或保存逻辑以供重用的应用案例。
了解如何开始使用 Object Explorer。

## 基于代码的分析

### Code Workbook

Code Workbook 是一个允许用户使用直观的图形界面分析和变换数据的应用程序。

Code Workbook 的设计原则包括：

- 迭代速度。用户可以快速测试和完善变换和可视化逻辑，以产生有用的结果。
- 低入门门槛。Code Workbook 的图形界面和对使用预编写逻辑的支持旨在使不同技术水平的用户能够轻松上手。
- 协作。不同的用户群体可以在 Code Workbook 中共享逻辑并在单个分析上协同工作。
- 模型创建。用户可以在 Code Workbook 中对 Foundry 模型进行迭代，并轻松查看模型阶段和指标。模型然后可以提交给建模目标并用于操作。
- 平台互操作性。用户可以通过将可视化添加到 Notepads 和将准备好的生产管道提升到 Code Repository 来将他们的发现应用于整个平台。
Code Workbook 的关键特性包括：

- 一个互动控制台，用于快速迭代变换逻辑和临时数据探索。
- 可视化支持，使用常用软件包（Matplotlib、Plotly、Seaborn）创建详细的交互式图像。
- 模板，通过简单界面复用复杂和特定领域的逻辑。
- 支持多种语言（Python、SQL、R）用于代码和模板，允许用户选择最佳语言进行分析，并在单个分析中利用多种语言。
- 分支，通过隔离用户的更改来促进协作。
- 一个直观的用户界面，使其易于定制 Spark 环境、设置变换的输入类型以及查看节点之间的关系。
了解如何开始使用 Code Workbook。

Code Workbook 并未针对搭建生产管道进行优化。如果您正在搭建或维护生产管道，请使用 Code Repositories 应用程序，该应用程序包括版本历史、分支和拉取请求以及其他对稳健管道至关重要的功能。更多信息请参见Foundry 的工具进行基于代码变换的比较。

## 时间序列分析

Foundry 提供先进的端到端工具用于时间序列存储、监控、变换、分析和数据输出。从历史性能分析到趋势和相关性分析，再到预测，工作流都可以利用 Foundry 的时间序列能力。

Quiver和Code Workbook均支持时间序列分析，分别用于无代码和基于代码的分析。了解如何开始使用时间序列。

## 基于地图（地理空间）的分析

地理空间数据通常是 Foundry 用户寻求将分析与操作相结合的关键输入。Foundry 简化了地理空间数据的变换和分析，并能够启用基于地图的工作流。

Map 应用程序是一个用于地理空间分析的强大应用程序。此外，Contour和Quiver包含用于分析中包含地理空间数据的地图微件。

## 仪表盘

Contour 和 Quiver 都支持基于分析结果搭建交互式仪表盘。了解更多关于仪表盘的信息。

## 报告

Notepad 是 Foundry 的下一代报告工具，推荐用于大多数报告应用案例。了解更多关于报告的信息。
