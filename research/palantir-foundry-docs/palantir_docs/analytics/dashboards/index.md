# 仪表盘

有两种主要方式可以从Foundry分析中搭建交互式仪表盘：Contour仪表盘和Quiver仪表盘。在某些情况下，您可能希望使用代码工作区仪表盘、记事本或自定义应用程序代替。本页面讨论了您可以使用哪些工具以及何时使用它们。

了解更多关于Contour和Quiver之间的区别。

## Contour仪表盘

Contour仪表盘用于呈现来自Contour分析的内容，例如分析结果和发现。这些仪表盘支持图表到图表的筛选、行内参数引用、全屏展示视图和PDF格式导出。

了解更多关于Contour和Contour仪表盘的信息。

此截图使用来自纽约出租车与豪华轿车委员会 ↗的开源数据。

## Quiver仪表盘

Quiver仪表盘用于在只读的交互式仪表盘中呈现Quiver分析的内容。

Quiver仪表盘可以作为独立仪表盘使用或嵌入到Object视图、Workshop应用程序或记事本文档中。Quiver仪表盘还可以在Carbon中显示，并直接交付给操作用户。

了解更多关于Quiver和Quiver仪表盘的信息。

## 代码工作区应用程序

代码工作区目前支持用于Python应用程序的Dash ↗和Streamlit ↗，以及用于R应用程序的Shiny® ↗。用户可以在代码工作区中直接创建应用程序工作流程，内置Foundry的版本控制、分支和数据治理功能。

了解更多关于代码工作区和代码工作区应用程序的信息。

## 其他展示工具

### 记事本

Contour仪表盘和Quiver模板最适合在Foundry内直接使用，因为它们的交互式设计允许用户使用参数和图表选择来处理实时数据。相比之下，记事本设计用于专注于创建可能导出的静态内容的报告工作流程。此外，记事本文档可以包含来自多个应用程序的内容（包括Contour面板和Quiver卡片），而Contour仪表盘和Quiver模板仅支持来自其各自应用程序的内容。由于专注于静态内容，用户无法在记事本中直接进行分析或创建图表。

了解更多关于报告工作流程的信息。

### 自定义应用程序

Contour仪表盘和Quiver模板被优化为轻松呈现分析结果的交互视图，而应用程序搭建工具（如Workshop）可能更适合某些应用案例。具体来说，如果您的应用案例需要完全自定义和设计灵活性、多步骤工作流程或数据输出，您应该考虑Foundry的应用程序搭建工具。

Quiver模板可以嵌入到Workshop应用程序中，使更复杂的分析内容可供操作用户使用。
