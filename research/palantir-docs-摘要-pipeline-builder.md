## pipeline-builder 模块
- **定位**：Foundry 主要数据集成应用：原始数据源 → 干净输出 → 分析或 Ontology 基础。用户图形/表单描述管道，后端生成变换代码并做完整性/健康检查；可接不同执行引擎（Spark/Flink/Azure）。
- **管道** = 数据集 + 变换 + 数据期望 + 输出组成的图；表达式（单列→单列）与变换（整表→整表）同界面配置；分支 = Git 式版本控制（Save→Propose→审批→合并主分支）。
- **数据集产生四途径**：数据连接同步导入/从 Foundry 选数据集/本地上传/手动建表生成虚拟数据。
- **计算模式**：快照（全量重算、整体替换）或增量（仅对新数据执行变换）；增量限制多（合并须增量在左、不允许两个增量合并、窗口/聚合只作用当前事务）。
- **输出写入模式**：默认 APPEND/SNAPSHOT、始终追加、仅追加新行（按主键）、变更日志、快照差异/替换等 7 种。
- **物化/部署**：Deploy 只更新输出逻辑，Build 执行逻辑；可只部署不搭建推迟成本；Ontology 输出必须搭建。
- **输出类型**：数据集、Ontology 对象类型/链接类型、时间序列、地理时间序列。
- **与 Ontology 关系**：可从变换节点生成对象类型，可启用"编辑"；链接 1:N 与 M:N（不支持 1:1）；首次部署后对象/链接 ID 不可改。
- **数据期望（可机验）**：主键（列无空值+组合唯一）、行数（最小/最大）；失败即搭建失败。健康检查可设严重性/连续失败升级。
- **检查点**：批处理共享中间结果整段落盘一次，供同任务组多输出复用（占存储）。
- **唯一 ID 最佳实践**：字符串列连接 + SHA256 哈希（确定性、可分布式、跨搭建稳定）；单调递增 ID 跨搭建不稳定（作 Object 主键会迫使全量重索引）。
- **重大更改**：修改有状态函数（聚合/窗口聚合等）部署时自动检测并要求重放；重放可停机数天。
- **LLM 节点**：预置模板（分类/总结/翻译/情感/实体提取）；Skip recomputing rows 缓存输出。
